## 3. 总体判定

### 3.1 完整性（completeness）

- 8 个 ADDED Requirement 中：**6 项完整闭环**（AI 出题、有效学习、考试评分、统计、员工部门、技术选型），**2 项存在轻微缺口**（制度文件管理的"管理端在线预览/历史版本回看"、文档交付的"README 基准回填"）。
- 8 个 Scenario **全部可闭环**，主流程与异常分支在 06-关键流程中均有时序图/状态机支撑。
- 10 层技术选型（前端框架 / UI 组件库 / 后端 / 数据库 / 缓存 / AI 接入 / PDF 解析 / Word 转换 / 在线阅读器 / 部署）逐层给出 5 维对比表 + 最终选型理由 + 风险 + 备选方案 + 切换成本，达到"评审者无需另行调研即可决策"的深度。

### 3.2 正确性（correctness）

发现 **9 项 Critical**（不含 impact 侧的 1 项 file_path 冲突），主要集中在：

- **安全逻辑不闭环**：`auth:block` 键判定误伤改密后新令牌、首次登录强制改密可绕过、AI 提示词注入未纳入威胁模型、`content_html` 净化白名单与 CSP 互斥。
- **契约与实现漂移**：04-API 缺 4 个 P0/P1 端点（重置密码、AI 配置读写、连通性测试、人工录入题目）、AI 配置权威副本三册载体冲突（Redis vs 文件）、乱序 seed 与 JWT_SECRET 绑定却未考虑 90 天轮换。
- **业务规则自相矛盾**：05 心跳处理步骤 6 无条件 `state=active` 破坏 paused 语义、07 与 04/05/06 失焦暂停机制两套互斥实现、`exam_record` 缺 deadline 快照使限时可被管理员误改。

### 3.3 一致性（impact）

- **核心口径高度一致**：12 张表名、全部枚举值、六大模块名与路由前缀、技术栈定稿、心跳 30 秒 / 45 秒封顶 / 10 段位图 / 及格 60 / 补考 3 次 / 漏选 50% / 100 分制，在 01~07 中**逐字一致**，未发现严重表名/枚举/模块/技术栈漂移。
- **README 索引链接**与磁盘文件名 8/8 命中；04 全部响应示例遵守 `{ code, message, data }`，业务码全部落在 40xxx/50xxx 段，无 HTTP-status-like 违规。
- **发现的漂移**集中在两类：① **跨文档隐式矛盾**（file_path 生成规则 8 位 vs 16 位、登录锁定 5 分钟 vs 10 分钟、切屏阈值单级 vs 两级）；② **README 基准回填滞后**（`exam_paper.partial_credit_ratio` 已被下游 5 册引用但未回填基准清单）。

## 4. 变更总结（Summary of Changes）

- **完整度**：8 份文档对原始 spec 的 8 个 Requirement 覆盖度 ≈95%；10 层技术选型对比表齐全，可直接支撑评审决策；仅"管理端在线预览"与"历史版本内容回看"两处 API 契约缺失。
- **一致性**：README 作为一致性基准执行良好——12 张表名、全部枚举、模块名/路由、技术栈定稿在 01~07 中逐字一致，无严重漂移；`exam_paper.partial_credit_ratio` 是唯一未回填的基准字段。
- **安全逻辑**：发现 3 项会导致「用户被自己封禁 / 初始密码长期有效 / 判分错位」的闭环缺陷，以及 AI 提示词注入、`content_html` 净化白名单与 CSP 冲突两项新增攻击面未闭合。
- **契约完整性**：04-API 相对 01-需求分析缺失 4 个 P0/P1 端点（重置密码、AI 配置读写、连通性测试、人工录入题目），需补齐接口清单与错误码。
- **修复优先级**：10 项 Critical 建议在进入实现前**全部修复**（尤其 3 项跨文档硬冲突与 4 项安全逻辑闭环缺陷）；21 项 Warning 建议按模块批次修复；15 项 Suggestion 可在实现阶段随代码评审逐步采纳。

## 5. 修复路线建议

### 阶段 A（阻断级，进入实现前必修）
1. Critical #1：`file_path` 生成规则统一为 8 位或 16 位（05/07 逐字对齐）
2. Critical #2、#3：`auth:block` 键改为时间戳比较 + 首次登录 `last_login_at` 时序约定
3. Critical #4：`exam_record` 新增 `deadline_at` 字段并回填 README 基准
4. Critical #5：乱序 seed 密钥独立化（`EXAM_SHUFFLE_SECRET`）或 Redis 持久化
5. Critical #6：题目被在考记录引用时禁止编辑 `stem/options/answer/type`
6. Critical #7、#8：失焦暂停机制以 04/05 的 pause/resume 端点为唯一契约，07 修订对齐；05 心跳步骤 6 改为条件执行
7. Critical #9：04 补齐 4 个 P0/P1 端点与错误码
8. Critical #10：AI 配置载体统一为文件（Redis 仅缓存），修订 07 §4.2.2 与 §6.2.2 断言

### 阶段 B（重要，实现早期修复）
- 21 项 Warning，按模块归类：
  - **学习域**（#4/5/8/9/17/18/21）：pause/resume 限流、is_valid 语义、位图 OR 合并、TTL、dwell flush、降级路径
  - **考试域**（#6/7/10/19/20）：分数分布分桶、每人最高分口径、切屏阈值级数、正确率分母、AI 出题分值参数
  - **制度域**（#1/2/11/12）：管理端预览与历史回看、AI 批次追溯、解析抢占
  - **安全域**（#13/14/15/16）：登录锁定统一、统计缓存键维度隔离、提示词注入、`img` 白名单

### 阶段 C（增强，可与实现并行）
- 15 项 Suggestion，主要是可观测性（`parsed_at`/`retry_count`）、开发规范（REST 语义、路由顺序、排序参数）、性能细节（`delta_s` 毫秒化）与文档口径回填。
