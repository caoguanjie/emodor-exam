# 01 · 需求分析 —— 制度学习及考试系统（RuleExam）

> **本册定位**：定义 RuleExam 的业务背景、用户角色、功能需求、核心用例、非功能需求与业务约束，是全套设计方案（02–07 分册）的需求源头。全文术语、表名、字段名、枚举值、模块名与 [README.md](README.md) 第 3 章「设计约定速览」**逐字一致**；如有冲突，以 README 为准并须先修订 README 再同步本册。

## 1. 引言

### 1.1 系统背景

企业内部的规章制度（合规制度、安全规范、业务流程规范等）通常以 PDF / Word 文件形式下发，在落地执行中长期存在以下痛点：

1. **版本混乱、传达不可证**：制度文件通过邮件、群聊散发，员工手头的版本不一；谁看过、谁没看过无从核实，合规审计时拿不出证据。
2. **学习真实性无法保障**：即便要求"自学"，也无法验证员工是否真的读完——"打开文件挂机刷时长"无法识别，学习行为缺乏可度量、可校验的判定标准。
3. **出题成本高、考核难组织**：人工依据制度编写考题费时费力，题量与覆盖面受限；线下考试的组织、监考、阅卷成本高，且难以防抄袭。
4. **落实情况缺乏数据闭环**：管理者无法按制度、按部门、按个人看清学习完成率、考试通过率等落实情况，未完成人员难以跟进督办。

RuleExam（制度学习及考试系统）针对上述痛点，提供覆盖「制度上传 → 在线学习 → AI 出题 → 考试评分 → 统计跟进」完整闭环的一体化解决方案：

- 制度管理员上传制度文件（PDF / Word），系统解析为在线可阅读内容并按版本管理，可配置学习要求（规定学习时长 `required_minutes`、滚动分段数 `scroll_segments`），发布范围按部门圈定或面向全员；
- 对接第三方 AI 大模型（OpenAI 兼容协议，可配置 `base_url` / `api_key` / `model`）解读制度内容生成考试题目（单选题 / 多选题，100 分制），管理员逐题审核（通过 / 驳回 / 编辑 / 重新生成）后组卷发布；
- 员工必须完成**有效学习**才能获得考试资格：累计有效学习时长 ≥ 规定阈值，且滚动覆盖率覆盖到底部段，双条件同时满足；学习与考试全程防作弊；
- 评分全自动、规则化，及格线默认 60 分可配置，补考次数默认 3 次可配置，多次作答取最高分；
- 统计覆盖单项制度维度、部门维度与个人维度，支持 Excel 导出，未完成人员清单直达跟进闭环。

### 1.2 系统目标

1. **制度数字化**：文件「上传即可读」，版本可追溯，发布范围可按部门圈定或面向全员。
2. **出题低成本、质量可控**：AI 解读制度自动生成题目，管理员审核通过后才可入卷发布。
3. **学习真实性可保障**：以「时长 + 滚动覆盖」双条件判定有效学习，辅以心跳、失焦暂停、容差校验、分段位图四道防线防止刷时长。
4. **考试公平可量化**：资格校验、试题与选项乱序、限时超时自动交卷、切屏检测与规则化自动评分。
5. **落实情况可运营**：制度 / 部门 / 个人三维统计与 Excel 导出，未完成人员清单直达跟进闭环。

### 1.3 文档范围与读者

## 2. 用户角色与画像

系统共三类角色（对应 `sys_user.role` 枚举），画像如下：

### 2.1 super_admin（超级管理员）

| 项目 | 描述 |
|---|---|
| 典型身份 | 企业 IT / 系统管理负责人 |
| 职责 | 维护部门树（`sys_department`）与员工账号（`sys_user`）；执行 Excel 批量导入员工；分配角色；配置系统级参数（含 AI 服务连接：`base_url` / `api_key` / `model`）；不直接参与制度的日常运营 |
| 核心诉求 | 组织数据一次维护、多处复用；批量建账高效、错误可定位；敏感配置（如 `api_key`）安全存放；系统运行稳定、可审计 |
| 使用频率 | 低频（组织调整期集中使用），单次操作量大（批量导入） |

### 2.2 regulation_admin（制度管理员）

| 项目 | 描述 |
|---|---|
| 典型身份 | 制度归口部门（合规部、人事部、EHS 等）的业务专员 |
| 职责 | 创建制度并上传制度文件（PDF / Word）；配置学习要求（`required_minutes`、`scroll_segments`）与发布范围（`regulation_scope` / `is_all`）；发起 AI 出题并逐题审核（通过 / 驳回 / 编辑 / 重新生成）；组卷发布试卷；查看统计报表并导出、跟进未完成人员 |
| 核心诉求 | 制度「上传即可读」、版本可追溯；出题省力但质量可控（AI 出题 + 人工把关）；能看清每项制度的落实情况（应学人数、学习完成率、通过率），未完成人员一键导出直接督办 |
| 使用频率 | 高频（按制度发布周期集中使用），是系统最主要的运营角色 |

### 2.3 employee（普通员工）

| 项目 | 描述 |
|---|---|
| 典型身份 | 被纳入制度发布范围的企业全员 |
| 职责 | 学习发布范围内已发布的制度；达到有效学习标准后参加考试；查看本人的学习进度与考试成绩 |
| 核心诉求 | 清楚知道「要学什么、学多久、何时能考、考得怎么样」；学习与考试体验流畅（进度实时可见、断网不丢进度）；判定规则公平透明——只要真读了就能达标，刷时长必然无效 |
| 使用频率 | 高频但碎片化（利用工作间隙学习），单次会话时长以分钟计 |

## 3. 角色权限矩阵

功能项按六大模块（名称与 README 3.4 节固定一致）分组。「有 / 无」表示能否执行该功能；带限定词的（如「仅本人」「只读」「限发布范围」）表示数据或操作边界。super_admin 天然拥有 regulation_admin 的全部能力。

### 3.1 组织权限模块（`/auth`、`/users`、`/departments`）

| 功能项 | super_admin | regulation_admin | employee |
|---|---|---|---|
| 用户登录 / 登出（JWT） | 有 | 有 | 有 |
| 查看个人信息、修改本人密码 | 有 | 有 | 仅本人 |
| 部门树查看 | 有（完整） | 只读 | 无 |
| 部门新增 / 编辑 / 删除 | 有 | 无 | 无 |
| 员工新增 / 编辑 / 禁用 / 重置密码 | 有 | 无 | 无 |
| Excel 批量导入员工 | 有 | 无 | 无 |
| 角色分配（`sys_user.role`） | 有 | 无 | 无 |

### 3.2 制度文件管理模块（`/regulations`）

| 功能项 | super_admin | regulation_admin | employee |
|---|---|---|---|
| 制度创建 / 编辑（标题、分类） | 有 | 有 | 无 |
| 制度文件上传（PDF / Word） | 有 | 有 | 无 |
| 制度版本管理与生效版本切换 | 有 | 有 | 无 |
| 学习要求配置（`required_minutes`、`scroll_segments`） | 有 | 有 | 无 |
| 发布范围配置（`regulation_scope` / `is_all`） | 有 | 有 | 无 |
| 制度发布 / 归档（draft → published → archived） | 有 | 有 | 无 |
| 在线阅读已发布制度 | 有 | 有 | 限发布范围内的本人 |

### 3.3 AI 出题模块（`/ai`）

| 功能项 | super_admin | regulation_admin | employee |
|---|---|---|---|
| AI 服务配置（`base_url` / `api_key` / `model`） | 有 | 无 | 无 |
| 发起 AI 出题 | 有 | 有 | 无 |
| 题目审核（通过 approved / 驳回 rejected） | 有 | 有 | 无 |
| 题目编辑 / 重新生成 | 有 | 有 | 无 |
| 人工录入题目（source = manual） | 有 | 有 | 无 |
| 组卷与试卷发布（exam_paper / paper_question） | 有 | 有 | 无 |
| 查看题库与审核状态 | 有 | 有 | 无 |

### 3.4 学习行为管控模块（`/learning`）

| 功能项 | super_admin | regulation_admin | employee |
|---|---|---|---|
| 在线学习（学习会话 / 心跳上报 / 滚动上报） | 有 | 有 | 限发布范围内的本人 |
| 查看学习进度与有效学习状态 | 有（全员） | 有（全员） | 仅本人 |
| 查看他人学习会话明细（`learning_session`） | 有 | 有 | 无 |

### 3.5 考试评分模块（`/exams`）

| 功能项 | super_admin | regulation_admin | employee |
|---|---|---|---|
| 参加考试（须通过考试资格校验） | 有 | 有 | 限发布范围内的本人 |
| 试卷管理（组卷编辑 / 发布 / 归档） | 有 | 有 | 无 |
| 查看考试成绩与答题明细（`exam_record` / `exam_answer`） | 有（全员） | 有（全员） | 仅本人 |
| 查看切屏次数（`switch_count`）用于监考风控 | 有 | 有 | 仅本人 |

### 3.6 统计报表模块（`/statistics`）

| 功能项 | super_admin | regulation_admin | employee |
|---|---|---|---|
| 单项制度维度统计（应学人数、学习完成率、参考人数、通过率、平均分、分数分布） | 有 | 有 | 无 |
| 未完成人员清单查看 | 有 | 有 | 无 |
| 部门维度对比统计 | 有 | 有 | 无 |
| 个人维度统计（学习记录 + 考试成绩） | 有（全员） | 有（全员） | 仅本人 |
| 各维度报表 Excel 导出 | 有 | 有 | 无 |

> 说明：学习与考试面向「发布范围内的用户」开放，不按角色排除管理员账号——super_admin / regulation_admin 账号若被纳入制度发布范围，同样作为应学人员参与学习与考核；employee 的数据边界一律为「仅本人」。

## 4. 功能需求清单

按六大模块编号列出（编号前缀与模块对应：FR-ORG、FR-REG、FR-AIQ、FR-LRN、FR-EXM、FR-STT），每条含需求名称、需求描述、优先级与验收要点。

### 4.1 组织权限模块（FR-ORG）

| 编号 | 需求名称 | 需求描述 | 优先级 | 验收要点 |
|---|---|---|---|---|
| FR-ORG-01 | 用户登录认证 | 用户以用户名 + 密码登录，服务端校验通过后签发 JWT；密码以哈希形式存储于 `sys_user`，不存明文 | P0 | ① 正确凭据登录成功并返回 token；② 错误凭据返回 40xxx 错误码且不泄露「用户不存在 / 密码错误」的具体区别；③ token 过期或缺失时访问受保护接口被拒绝；④ 被禁用账号无法登录 |
| FR-ORG-02 | 部门树管理 | 维护部门树（`sys_department`，`parent_id` 自关联），支持新增、编辑、删除部门；部门是员工归属、发布范围与统计维度的组织基础 | P0 | ① 部门树查询返回完整层级结构；② 删除仍有员工归属的部门被拒绝并提示先转移员工；③ 部门重命名后，发布范围与统计中的部门信息同步更新 |
| FR-ORG-03 | 员工信息管理 | 对 `sys_user` 执行新增、编辑、禁用、重置密码；员工信息含用户名、姓名、工号、部门、角色（super_admin / regulation_admin / employee）、状态 | P0 | ① 用户名与工号全局唯一，重复创建被拒绝；② 禁用账号即刻无法登录且不参与应学人数统计；③ 重置密码后旧密码失效 |
| FR-ORG-04 | Excel 批量导入员工 | 提供 Excel 模板下载；super_admin 上传填好的 Excel 一次批量创建员工并归属部门 | P0 | ① 按模板导入成功的员工可直接登录；② 非法行（部门不存在、工号 / 用户名重复、角色枚举非法）整行失败且不影响其他行，返回行号与失败原因；③ 导入结束返回成功 / 失败计数与明细 |
| FR-ORG-05 | 角色权限控制（RBAC） | 按 `sys_user.role` 三角色控制接口访问与数据范围，边界以第 3 章权限矩阵为准 | P0 | ① employee 调用管理端接口（如创建制度、组卷、统计）返回权限错误码；② regulation_admin 调用员工管理、AI 服务配置接口返回权限错误码；③ super_admin 可执行全部功能 |
| FR-ORG-06 | 个人信息维护 | 用户查看本人基本信息并修改登录密码 | P1 | ① 修改密码须校验原密码，错误则拒绝；② 修改成功后旧密码立即失效，须用新密码重新登录 |

### 4.2 制度文件管理模块（FR-REG）

| 编号 | 需求名称 | 需求描述 | 优先级 | 验收要点 |
|---|---|---|---|---|
| FR-REG-01 | 制度创建与维护 | regulation_admin 创建制度主档（`regulation`）：填写标题、分类，初始状态为 draft | P0 | ① 创建成功后 `regulation.status = draft`；② 标题必填，分类支持自定义归类；③ 草稿态制度对员工端不可见 |
| FR-REG-02 | 制度文件上传 | 上传制度文件，系统创建不可变版本记录 `regulation_version`（含 `file_path` / `file_type` / `file_hash`）；同一制度可多次上传形成多个版本 | P0 | ① 仅接受 pdf / docx 两种 `file_type`，其他类型拒绝；② 上传成功即生成新版本记录并计算 `file_hash`；③ 重复上传同一文件（hash 相同）时提示但不阻断 |
| FR-REG-03 | 文件解析 | 系统异步解析上传文件：pdf-parse 提取 PDF 文本、mammoth 将 Word 转 HTML，产出 `content_html` 与 `text_content`，`parse_status` 由 pending 流转为 parsed 或 failed | P0 | ① 解析成功后阅读页可在线阅读完整内容；② 扫描版 PDF（无文本层）等解析失败场景记 `parse_status = failed` 并提示管理员重新上传；③ 解析状态在版本详情中实时可见；④ 管理端可预览：制度管理员可对 draft/published 状态的制度按指定版本预览解析产物（GET /regulations/{id}/preview），不受发布状态限制（仅角色校验） |
| FR-REG-04 | 版本管理 | 同一制度的多个版本并存且不可变；通过 `current_version_id` 指定当前生效版本；历史版本可查看 | P0 | ① 切换生效版本后，员工阅读页展示新版本内容；② 历史版本内容仍可回看；③ 版本记录一经创建不可篡改；④ 管理端历史版本内容可回看（GET /regulations/{id}/versions/{versionId} 返回解析产物） |
| FR-REG-05 | 学习要求配置 | 对制度配置规定有效学习时长 `required_minutes`（分钟）与滚动分段数 `scroll_segments`（按 10 段位图实现，默认 10 段） | P0 | ① 配置保存后，有效学习判定即时按新值执行；② 非法值（`required_minutes ≤ 0`、`scroll_segments` 非正整数）被校验拦截；③ 已达标的 `learning_record.is_valid` 不因调低阈值而回退；④ `scroll_segments` 本期固定为 10（配置项前向保留），接口仅接受 10 |
| FR-REG-06 | 发布范围配置 | 通过 `regulation_scope` 按部门（`department_id`）圈定发布范围，或以 `is_all` 标记面向全员；发布范围决定「应学人数」统计口径 | P0 | ① 按 / 全员两种方式互斥表达，配置后范围外员工不可见该制度；② 发布后再调整范围，应学人数与统计口径随之更新；③ 新员工入职进入已圈定部门后自动纳入应学范围 |
| FR-REG-07 | 制度发布与归档 | 制度状态流转 draft → published → archived；发布前置条件：存在 `parse_status = parsed` 的版本且已配置发布范围 | P0 | ① 无已解析版本或缺发布范围时发布被拦截并提示；② published 制度对范围内员工可见、可学习；③ archived 制度员工端不可见、不可再学习与考试，历史数据保留 |
| FR-REG-08 | 在线阅读呈现 | 员工端基于 pdfjs-dist / 解析产物（`content_html`）渲染在线阅读页，阅读页承载滚动位置追踪与心跳上报 | P0 | ① 阅读页按生效版本内容完整呈现；② 阅读过程滚动与计时行为被采集（详见 FR-LRN 组）；③ 移动端浏览器可正常阅读（详见 NFR-13） |

### 4.3 AI 出题模块（FR-AIQ）

| 编号 | 需求名称 | 需求描述 | 优先级 | 验收要点 |
|---|---|---|---|---|
| FR-AIQ-01 | AI 服务配置 | super_admin 配置 AI 大模型连接参数 `base_url` / `api_key` / `model`（OpenAI 兼容协议，兼容智谱 GLM、DeepSeek、通义千问等），全局生效 | P0 | ① 保存后可发起连通性测试并返回成功 / 失败；② `api_key` 存储加密、界面不回显明文；③ 未配置时发起出题被拦截并提示 |
| FR-AIQ-02 | 发起 AI 出题 | 优先基于制度生效版本的 `text_content`，文本层不足的 PDF 自动按页面渲染为图片，调用支持视觉输入的 AI 大模型解读制度内容并生成考试题目（题型 single 单选 / multiple 多选），每题含题干、选项、答案、解析；生成结果落库 `question`（`source = ai`、`status = pending`） | P0 | ① 生成的题目含完整题干、选项、答案与解析且题型合法；② 全部落库为 `source = ai`、`status = pending`；③ 生成失败（服务不可用 / 超时 / 返回格式异常）时给出明确提示且可重试，不产生脏数据 |
| FR-AIQ-03 | 题目审核 | 管理员对 AI 生成的题目逐题审核：通过（`status = approved`）或驳回（`status = rejected`）；仅 approved 的题目可入卷 | P0 | ① 仅 `status = approved` 的题目在组卷时可选；② rejected 题目不出现在组卷候选中；③ 审核操作留痕（操作人、时间） |
| FR-AIQ-04 | 题目编辑 | 管理员可编辑题目（题干、选项、答案、解析、分值）；判分始终以题目当前答案为准 | P0 | ① 编辑保存后题库即时生效；② 编辑后单选题答案仍唯一、多选题答案合法；③ 判分规则使用编辑后的答案 |
| FR-AIQ-05 | 题目重新生成 | 对驳回或不满意的题目，重新调用 AI 生成替换内容 | P1 | ① 重新生成后题目内容更新且 `status` 回到 pending 待复审；② 重新生成失败时原题目内容不受影响 |
| FR-AIQ-06 | 人工录入题目 | 管理员人工录入题目（`source = manual`），用于补充 AI 覆盖不到的考点；录入后可直接入卷 | P1 | ① 录入题目落库 `source = manual`；② 单选题答案唯一、多选题答案 ≥ 1 的合法性校验；③ 人工题目无需审核即可组卷（录入者即管理员） |
| FR-AIQ-07 | 组卷与试卷发布 | 管理员将 approved 题目组卷（`paper_question`：`sort` 组卷顺序、`score` 每题分值），试卷（`exam_paper`）固定 100 分制，可配置及格线 `pass_score`（默认 60）、限时 `duration_minutes`、最大补考次数 `max_attempts`（默认 3），状态 draft → published → archived | P0 | ① 发布前校验全部题目分值合计 = 100 分，不足或超出均拦截；② 发布后范围内员工可发起考试；③ 已发布试卷的 `pass_score` / `duration_minutes` / `max_attempts` 修改后对后续作答生效；④ archived 试卷不可再发起新作答 |

### 4.4 学习行为管控模块（FR-LRN）

| 编号 | 需求名称 | 需求描述 | 优先级 | 验收要点 |
|---|---|---|---|---|
| FR-LRN-01 | 学习会话记录 | 用户一次进入制度阅读页到离开的连续阅读记为一次学习会话（`learning_session`：`started_at` / `ended_at` / `duration_seconds`）；会话时长经容差校验后累加至 `learning_record.total_seconds` | P0 | ① 进入阅读页即创建会话（`started_at`）；② 正常离开时写入 `ended_at` 与 `duration_seconds`；③ 直接关闭页面时由服务端按最后一次心跳封顶截止会话 |
| FR-LRN-02 | 心跳上报与时长容差校验 | 学习页面每 30 秒向服务端上报一次心跳（携带当前滚动位置）；服务端做时长容差校验，单次心跳最大计入 45 秒，超出部分不计入有效时长 | P0 | ① 心跳间隔 30 秒/次、单次最大计入 45 秒的容差规则在服务端生效；② 篡改客户端高频上报（如每秒一次）不会虚增 `total_seconds`；③ 心跳携带的滚动位置用于更新滚动覆盖位图 |
| FR-LRN-03 | 失焦暂停计时 | 页面失焦（切换标签页 / 最小化窗口）时暂停计时，恢复聚焦后继续累计 | P0 | ① 失焦期间不产生有效时长累计；② 恢复聚焦后计时继续且不补记失焦期间时长；③ 长时间失焦后返回不一次性计入大额时长 |
| FR-LRN-04 | 滚动覆盖位图 | 阅读内容按 `scroll_segments`（10 段）划分，以 JSON 位图记录已读到位情况（`learning_record.scroll_coverage`），并同步更新最大滚动百分比 `max_scroll_percent` | P0 | ① 滚动经过某段后对应位图位置位；② 回滚不取消已置位段落；③ `max_scroll_percent` 单调不减；④ 位图段数与制度 `scroll_segments` 一致 |
| FR-LRN-05 | 有效学习判定 | 同时满足两个条件判定为有效学习：① `total_seconds ≥ required_minutes × 60`；② 滚动覆盖位图覆盖到底部段。两条件缺一不可；达标后 `learning_record.is_valid = true` 并记录 `valid_at` | P0 | ① 仅时长达标、未覆盖底部段：不置 `is_valid`；② 仅覆盖底部段、时长不足：不置 `is_valid`；③ 双条件同时满足的当次上报即置 `is_valid` 与 `valid_at`，且只置一次 |
| FR-LRN-06 | 考试资格校验 | 员工发起考试时校验该制度学习是否已达有效学习标准（`is_valid`），未达标则拒绝 | P0 | ① 未达标发起考试被拒绝，并返回差距信息（剩余有效时长、底部段未覆盖）；② 达标后任意时刻可发起考试（在试卷与补考次数限制内） |

### 4.5 考试评分模块（FR-EXM）

| 编号 | 需求名称 | 需求描述 | 优先级 | 验收要点 |
|---|---|---|---|---|
| FR-EXM-01 | 发起考试 | 资格校验通过后创建考试记录（`exam_record`：`status = in_progress`，`attempt_no` 为该用户该试卷的第 N 次作答）；Redis 用于考试计时与防重复提交 | P0 | ① 无考试资格时无法创建考试记录；② 同一用户对同一试卷不并发存在两条 in_progress 记录；③ `attempt_no` 从 1 起连续递增 |
| FR-EXM-02 | 试题与选项乱序 | 同一试卷对每位考生呈现时，题目顺序与选项顺序均随机打乱以防抄袭；判分始终以题目原始答案语义为准 | P0 | ① 同一试卷两名考生看到的题目顺序、选项顺序不同；② 乱序不影响判分正确性（不同顺序作答同一选项组合得分一致） |
| FR-EXM-03 | 限时考试与超时自动交卷 | 考试限时 `duration_minutes`，倒计时结束未交卷由系统自动交卷，`status = timeout` | P0 | ① 倒计时对考生可见；② 到时自动按当前已答内容交卷评分；③ 超时交卷记录 `status = timeout` 且未答题目不得分 |
| FR-EXM-04 | 切屏检测 | 考试过程中检测考生离开考试页面的行为，累计记入 `exam_record.switch_count`，用于监考与风控 | P0 | ① 每次切屏离开考试页 `switch_count` + 1；② 切屏次数在成绩详情中对管理员与本人可见 |
| FR-EXM-05 | 自动评分 | 交卷后系统按固定规则自动评分：单选题（single）答案唯一，答对得该题分值；多选题（multiple）全对得满分、错选得 0 分、漏选按配置得部分分（默认 50%）；逐题写入 `exam_answer`（`selected` / `is_correct` / `gained_score`） | P0 | ① 单选唯一答案判分正确；② 多选三种情形（全对 / 错选 / 漏选）得分与规则一致，漏选部分分比例可配置且默认 50%；③ 每题 `selected` / `is_correct` / `gained_score` 与规则结果一致，各题得分合计 = 总分 |
| FR-EXM-06 | 及格判定 | 总分 ≥ `pass_score`（默认 60 分、可配置）则 `status = passed`，否则 `status = failed` | P0 | ① 恰好等于及格线判定为 passed；② 调整及格线后对后续交卷的判定即时生效 |
| FR-EXM-07 | 补考 | 未通过（failed / timeout）后可再次作答，补考次数受试卷 `max_attempts`（默认 3 次、可配置）限制；同一试卷多次作答取最高分作为最终成绩 | P0 | ① 超出补考次数后再次发起被拒绝并提示；② 每次补考 `attempt_no` 递增且重新乱序；③ 最终成绩取历次作答的最高分，统计与个人成绩页均按最高分口径展示 |

## 5. 核心用例

选取 10 个覆盖核心闭环的关键用例。编号 UC-01 ~ UC-10。

### UC-01 上传并发布制度

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-01 |
| 名称 | 上传并发布制度 |
| 主角色 | regulation_admin |
| 前置条件 | 已以 regulation_admin 身份登录；目标分类已确定 |

**主流程**：
1. 创建制度：填写标题、分类，`regulation.status = draft`；
2. 上传制度文件（PDF / Word），系统创建 `regulation_version`（`file_path` / `file_type` / `file_hash`），`parse_status = pending`；
3. 系统异步解析文件，产出 `content_html` 与 `text_content`，`parse_status` 转为 parsed；
4. 配置学习要求：`required_minutes`（规定有效学习时长）、`scroll_segments`（默认 10 段）；
5. 配置发布范围：按部门圈定 `regulation_scope` 或勾选 `is_all` 面向全员；
6. 发布制度：状态 draft → published，`current_version_id` 指向已解析版本；
7. 发布范围内的员工在其制度列表中看到该制度，可开始学习。

**异常流程**：
- A1（第 2 步）：文件类型非 pdf / docx → 上传被拒绝并提示支持的格式；
- A2（第 3 步）：解析失败（`parse_status = failed`，如扫描版 PDF）→ 提示管理员重新上传可解析文件，且第 6 步发布被拦截；
- A3（第 6 步）：未配置发布范围 → 发布被拦截并提示。

**后置条件**：`regulation.status = published`；应学人数按 `regulation_scope` 生成统计口径；范围内员工可阅读。

### UC-02 配置学习要求

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-02 |
| 名称 | 配置学习要求 |
| 主角色 | regulation_admin |
| 前置条件 | 制度已创建（draft 或 published 均可） |

**主流程**：
1. 打开制度详情的「学习要求」设置；
2. 设置 `required_minutes`（如 30 分钟）与 `scroll_segments`（默认 10 段）；
3. 保存后，有效学习判定按新阈值执行。

**异常流程**：
- A1：`required_minutes ≤ 0` 或 `scroll_segments` 非正整数 → 校验失败，保存被拒绝；
- A2：调高 `required_minutes` 后，已达标员工（`is_valid = true`）保持达标不回退，未达标员工按新阈值继续判定。

**后置条件**：制度的学习要求配置持久化；员工学习页展示的目标时长同步更新。

### UC-03 发起 AI 出题并审核

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-03 |
| 名称 | 发起 AI 出题并逐题审核 |
| 主角色 | regulation_admin |
| 前置条件 | 制度存在 `parse_status = parsed` 的生效版本（文本可用，或为启用多模态的 PDF）；super_admin 已配置支持对应输入类型的 AI 服务（`base_url` / `api_key` / `model`） |

**主流程**：
1. 管理员选择制度与生效版本，设定生成要求（题型 single / multiple 分布、题目数量）；
2. 系统优先以 `text_content` 为上下文；扫描版 PDF 自动按页面转为 `image_url` 内容块，经 OpenAI 兼容协议调用支持视觉输入的 AI 大模型解读制度内容生成题目；
3. 生成结果逐题落库 `question`（`source = ai`、`status = pending`，含题干、选项、答案、解析）；
4. 管理员逐题审核：通过 → `status = approved`；驳回 → `status = rejected`；
5. 对表述或答案有误的题目直接编辑后通过，对质量不满意的题目重新生成；
6. `status = approved` 的题目进入可组卷题库。

**异常流程**：
- A1：AI 服务不可用 / 调用超时 → 提示失败且可重试，不产生半成品数据；
- A2：AI 返回格式异常 / 无法解析为合法题目 → 该批结果丢弃并提示重新生成；
- A3：`text_content` 为空 → 拒绝发起并提示需先完成解析。

**后置条件**：该制度题库中存在 `status = approved` 的可用题目；审核操作留痕。

### UC-04 员工有效学习

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-04 |
| 名称 | 员工有效学习 |
| 主角色 | employee |
| 前置条件 | 制度 `status = published` 且员工在发布范围内；员工已登录 |

**主流程**：
1. 员工打开制度阅读页，系统创建 `learning_session`（记录 `started_at`）；
2. 阅读期间页面每 30 秒心跳上报一次（携带当前滚动位置）；
3. 服务端做时长容差校验（单次心跳最大计入 45 秒），将有效时长累计至 `learning_record.total_seconds`；
4. 滚动经过的内容按段置位 `scroll_coverage` 位图（10 段），并更新 `max_scroll_percent`；
5. 阅读途中页面失焦则暂停计时，恢复聚焦后继续；
6. 员工离开阅读页，会话结束（写入 `ended_at` / `duration_seconds`）；
7. 当 `total_seconds ≥ required_minutes × 60` 且滚动覆盖位图覆盖到底部段时，`learning_record.is_valid = true` 并记录 `valid_at`，学习页向员工提示「已达有效学习标准」。

**异常流程**：
- A1：网络中断导致心跳丢失 → 恢复后从当前时刻继续累计，丢失区间不计时长（以服务端已收到心跳的累计为准）；
- A2：员工直接关闭浏览器 → 会话由服务端按最后一次心跳加 45 秒封顶截止，已累计进度不丢失。

**后置条件**：学习进度持久化于 `learning_session` 与 `learning_record`；达标员工具备该制度的考试资格。

### UC-05 获得考试资格

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-05 |
| 名称 | 获得考试资格 |
| 主角色 | employee |
| 前置条件 | 制度已发布且存在 `status = published` 的试卷；员工在发布范围内 |

**主流程**：
1. 员工在制度详情查看学习进度（累计有效时长 / 目标时长、滚动覆盖情况）；
2. 员工点击「参加考试」；
3. 系统校验该制度的 `learning_record.is_valid`；
4. 校验通过 → 允许进入考试（进入 UC-06）；
5. 校验失败 → 返回未达标原因：剩余有效时长缺口、底部段未覆盖。

**异常流程**：
- A1：`is_valid = false` → 拒绝发起考试并展示差距；
- A2：暂无已发布试卷 → 提示「暂未开考」。

**后置条件**：资格状态对员工透明可见（学习页实时展示双条件达成进度）。

### UC-06 参加考试并自动评分

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-06 |
| 名称 | 参加考试并自动评分 |
| 主角色 | employee |
| 前置条件 | 已通过考试资格校验（UC-05）；试卷 `status = published`；未超出补考次数限制 |

**主流程**：
1. 员工发起考试，系统创建 `exam_record`（`status = in_progress`、`attempt_no` 递增），Redis 启动考试计时；
2. 系统对试题与选项乱序后呈现试卷，开始 `duration_minutes` 倒计时；
3. 员工逐题作答；考试中离开考试页面（切屏）累计 `switch_count`；
4. 员工主动交卷（`status = submitted`）或倒计时结束由系统自动交卷（`status = timeout`）；
5. 系统自动评分：单选（single）答对得该题分值；多选（multiple）全对得满分、错选得 0 分、漏选按配置得部分分（默认 50%）；逐题写入 `exam_answer`（`selected` / `is_correct` / `gained_score`）；
6. 总分 ≥ `pass_score`（默认 60）→ `status = passed`，否则 `status = failed`；
7. 员工即时查看总分、逐题对错与解析。

**异常流程**：
- A1：资格校验失败（学习被判定未达标）→ 拒绝创建考试记录；
- A2：考试中断网 / 误关闭页面 → 重新登录进入后，in_progress 记录仍在限时内可继续作答；
- A3：重复点击交卷 → Redis 防重复提交拦截，仅首次交卷有效。

**后置条件**：`exam_record` 进入终态（passed / failed / timeout）并带总分；统计口径（参考人数、通过率、平均分、分数分布）随之更新。

### UC-07 补考

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-07 |
| 名称 | 补考 |
| 主角色 | employee |
| 前置条件 | 前次作答 `status = failed` 或 `timeout`；已用补考次数未超过试卷 `max_attempts`（默认 3 次） |

**主流程**：
1. 员工在成绩页查看历次成绩，选择「补考」；
2. 系统校验剩余补考次数；
3. 创建新 `exam_record`，`attempt_no = 前次 + 1`，`status = in_progress`；
4. 重新进行试题与选项乱序、限时作答、交卷评分（流程同 UC-06）；
5. 多次作答取最高分作为该员工此试卷的最终成绩。

**异常流程**：
- A1：已用补考次数达到 `max_attempts` → 拒绝发起并提示次数用尽；
- A2：重复 / 并发发起补考 → 防重复提交拦截，同一时刻仅一条 in_progress 记录。

**后置条件**：最高分生效为最终成绩；个人成绩页与统计报表均按最高分口径展示。

## 6. 非功能需求

### 6.1 性能

| 编号 | 需求 | 指标与验收要点 |
|---|---|---|
| NFR-01 | 在线学习并发 | 支持 500 名员工同时在线学习（心跳上报约 17 次/秒），系统功能正常、无请求堆积 |
| NFR-02 | 考试并发 | 支持 100 名员工同时参加考试（含倒计时、交卷与自动评分峰值），交卷评分在 3 秒内返回结果 |
| NFR-03 | 查询与导出响应 | 常规业务接口 P95 响应 ≤ 500ms；统计报表查询 P95 ≤ 3 秒（1 万员工规模）（1 万员工为统计性能校验规模，常态规模 2,000 人，见 07 册 §5.1 容量目标）；万行级 Excel 导出 ≤ 30 秒 |
| NFR-04 | 文件解析时长 | 常规制度文件（≤ 20MB）解析完成 ≤ 60 秒，解析过程异步不阻塞其他操作 |
| NFR-05 | AI 出题时长 | 单次出题请求（生成 10–30 题）在 AI 服务正常情况下 120 秒内返回；超时明确报错可重试 |

### 6.2 安全

| 编号 | 需求 | 指标与验收要点 |
|---|---|---|
| NFR-06 | 认证 | 全部业务接口须经 JWT 认证；token 过期 / 伪造请求被拒绝并返回统一错误码（40xxx） |
| NFR-07 | 授权（RBAC） | 接口与数据范围按三角色权限矩阵（第 3 章）强制校验，越权访问一律拒绝 |

## 7. 约束与假设

### 7.1 业务约束

| 编号 | 约束内容 |
|---|---|
| C-01 | **学习时长以服务端累计为准**：客户端上报的时长仅供参考，有效学习时长一律以服务端经容差校验（单次心跳最大计入 45 秒）累计的 `learning_record.total_seconds` 为准 |
| C-02 | **有效学习双条件缺一不可**：累计有效学习时长 ≥ `required_minutes` 与滚动覆盖位图覆盖到底部段必须同时满足，任一条件单独满足均不判定达标 |
| C-03 | **AI 生成题目必须审核**：`source = ai` 的题目必须经管理员审核为 `approved` 后方可入卷；人工录入（`source = manual`）题目由录入管理员自担质量，免审核直接入卷 |
| C-04 | **发布前置条件**：制度发布（draft → published）前必须存在 `parse_status = parsed` 的版本并已配置发布范围；试卷发布前题目分值合计必须等于 100 分 |
| C-05 | **成绩不可人工修改**：评分全自动、规则化，系统不提供人工改分入口；对成绩有异议只能通过补考（受 `max_attempts` 限制）解决 |
| C-06 | **取最高分口径**：同一试卷多次作答取最高分作为最终成绩，统计报表与个人成绩展示均遵循此口径 |
| C-07 | **版本切换不追溯学习进度**：学习进度与考试资格绑定制度（regulation）而非具体版本；切换生效版本（`current_version_id`）不清零已有学习进度，如需要求重新学习，由管理员调整学习要求（如提高 `required_minutes`）或另行发布新制度 |
| C-08 | **归档即止**：制度或试卷归档（archived）后，员工端不可见、不可再学习或发起新作答，但历史学习与考试数据保留并计入统计 |
| C-09 | **应学人数口径**：以发布范围（`regulation_scope` / `is_all`）内在职员工数为准；发布范围调整后统计口径随之更新 |

### 7.2 技术假设

| 编号 | 假设内容 |
|---|---|
| A-01 | 技术栈遵循 README 3.1 定稿：Vue 3 + TypeScript + Vite（Pinia / Vue Router）+ Element Plus 前端；Node.js + NestJS（TypeScript）后端；MySQL 8.0；Redis（考试计时、学习会话累计、防重复提交）；JWT + RBAC；Docker Compose 部署 |
| A-02 | 第三方 AI 大模型服务经 OpenAI 兼容协议可访问（兼容智谱 GLM、DeepSeek、通义千问等）；出题能力依赖其可用性，AI 不可用时仅影响新增出题，不影响已入库题目的审核与组卷 |
| A-03 | 制度文件格式仅支持 pdf / docx（`regulation_version.file_type`），且要求文件含可提取文本（扫描版图片 PDF 无法解析，需提示重新提供可复制文本的文件） |
| A-04 | 系统部署于企业内网或受控云环境，员工主要使用桌面浏览器完成学习与考试；系统规模按数千员工级设计（满足 NFR-01 / NFR-03 的并发与统计性能目标） |
| A-05 | 数据模型严格限定为 README 3.3 的 12 张表（sys_department、sys_user、regulation、regulation_version、regulation_scope、learning_session、learning_record、question、exam_paper、paper_question、exam_record、exam_answer），本册需求不得引入第 13 张表；如确需扩展，须先修订 README 再同步全套文档 |
