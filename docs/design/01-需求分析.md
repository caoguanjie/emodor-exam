# 01 · 需求分析 —— 制度学习及考试系统（EmodorRuleExam）

> **本册定位**：定义 EmodorRuleExam 的业务背景、用户角色、功能需求、核心用例、非功能需求与业务约束，是全套设计方案（02–07 分册）的需求源头。全文术语、表名、字段名、枚举值、模块名与 [README.md](README.md) 第 3 章「设计约定速览」**逐字一致**；如有冲突，以 README 为准并须先修订 README 再同步本册。

> **状态边界（2026-10-22）**：演示版现行范围以瘦身计划为准。管理端只保留五个根菜单和培训类别、学员、课程、题库资料、三类客观题、试卷、自动评分、考试记录、培训统计及系统设置；制度、员工、部门管理，图片作答、人工阅卷、实时监控和切屏采集已取消。旧制度阅读、旧固定卷自动评分与原统计继续由共享表和只读接口兼容，不恢复对应管理入口。

## 1. 引言

### 1.0 试卷设计器与内容版本增量（2026-10-23）

固定卷接入完整三栏 PaperDesigner：题库/试卷库、单一正文编辑器、属性/解析、试卷设置/模板设置与受控图片。题库人工新增和编辑继续使用现有表单；AI/导入队列入口沿用现有流程，不增加独立试题设计器。现有表单编辑 schema 3 时保留未改富文本、稳定选项 ID、受控图片及布局；不能无损转换的修改明确拒绝，保留草稿，不允许静默降级。

新建、修订、审核入池和新发布只接受服务端集中目录启用的难度；当前为简单 `easy` / 困难 `hard`。历史 `medium` 与未知值继续读取和展示，不自动归档、重分类、重抽或重算历史成绩。完整原稿仅供管理端续编，学员只接收校验后的 schema 2/3 内容。旧客户端遇到 schema 3 在开考写入前收到升级原因，不消耗次数。实现与验证等级见[本次验收记录](../../review/main-question-designers-acceptance-2026-10-23.md)。

### 1.1 系统背景

企业内部的规章制度（合规制度、安全规范、业务流程规范等）通常以 PDF / Word 文件形式下发，在落地执行中长期存在以下痛点：

1. **版本混乱、传达不可证**：制度文件通过邮件、群聊散发，员工手头的版本不一；谁看过、谁没看过无从核实，合规审计时拿不出证据。
2. **学习真实性无法保障**：即便要求"自学"，也无法验证员工是否真的读完——"打开文件挂机刷时长"无法识别，学习行为缺乏可度量、可校验的判定标准。
3. **出题成本高、考核难组织**：人工依据制度编写考题费时费力，题量与覆盖面受限；线下考试的组织、监考、阅卷成本高，且难以防抄袭。
4. **落实情况缺乏数据闭环**：管理者无法按制度、按部门、按个人看清学习完成率、考试通过率等落实情况，未完成人员难以跟进督办。

EmodorRuleExam 当前面向单家培训机构提供「课程与资料 → AI/人工题库 → 发布考试 → 自动评分 → 记录与统计」闭环，同时保留旧制度学习和固定卷的只读兼容链路：

- 管理员在题库内上传 PDF / Word 资料并取得资料版本，外部接口统一使用 `material_id + material_version_id`；底层复用旧 `regulation/regulation_version` 保存来源和解析结果；
- 对接第三方 AI 大模型（OpenAI 兼容协议，可配置 `base_url` / `api_key` / `model`）解读资料并生成单选、多选题；判断题由人工录入或文件导入，管理员审核后组卷发布；
- **legacy 制度固定卷**员工必须完成**有效学习**才能获得考试资格：累计有效学习时长 ≥ 规定阈值，且滚动覆盖率覆盖到底部段，双条件同时满足；新培训考试默认关闭该学习门槛，但不放宽服务端计时、空白答案、答案/解析不下发、令牌吊销与防作弊规则；
- 新旧考试都只对三类客观题自动评分；及格线默认 60 分、最多 3 次作答、多选漏选比例均由服务端规则控制，最终总分不可直接修改；
- 培训统计按场次、难度、来源与当前应考集合交集计算；旧制度/部门/个人统计后端继续兼容，但现行菜单隐藏。

### 1.2 系统目标

1. **制度数字化**：文件「上传即可读」，版本可追溯，发布范围可按部门圈定或面向全员。
2. **出题低成本、质量可控**：AI 解读制度自动生成题目，管理员审核通过后才可入卷发布。
3. **学习真实性可保障**：以「时长 + 滚动覆盖」双条件判定有效学习，辅以心跳、失焦暂停、容差校验、分段位图四道防线防止刷时长。
4. **考试公平可量化**：实名/资格、冻结题单与乱序、稳定选项ID、服务端期限和主动整卷评分；到期纯timeout不提交/不评分。
5. **落实情况可运营**：制度 / 部门 / 个人三维统计与 Excel 导出，未完成人员清单直达跟进闭环。

## 2. 用户角色与画像

系统共三类角色（对应 `sys_user.role` 枚举），画像如下：

### 2.1 super_admin（超级管理员）

| 项目 | 描述 |
|---|---|
| 典型身份 | 企业 IT / 系统管理负责人 |
| 职责 | 创建管理员并分配 `role_ids`；维护角色、菜单、字典、站点配置和 AI 服务连接；管理培训类别与学员 |
| 核心诉求 | 权限分配明确；敏感配置（如 `api_key`）安全存放；系统运行稳定、可审计 |
| 使用频率 | 按培训与系统配置需要使用 |

### 2.2 regulation_admin（制度管理员）

| 项目 | 描述 |
|---|---|
| 典型身份 | 制度归口部门（合规部、人事部、EHS 等）的业务专员 |
| 职责 | 在题库上传资料、发起 AI 出题并审核，维护三类客观题与试卷，查看考试记录和培训统计 |
| 核心诉求 | 资料版本可追溯；出题省力但质量可控；能看清考试完成与成绩情况 |
| 使用频率 | 高频（按制度发布周期集中使用），是系统最主要的运营角色 |

### 2.3 employee（普通员工）

| 项目 | 描述 |
|---|---|
| 典型身份 | 被纳入制度发布范围的企业全员 |
| 职责 | 学习可见课程或旧制度内容，参加分配的考试，查看本人的进度、历史、成绩与错题 |
| 核心诉求 | 清楚知道要学什么、何时能考、考得怎么样；草稿和服务端期限可恢复；判分规则公平透明 |
| 使用频率 | 高频但碎片化（利用工作间隙学习），单次会话时长以分钟计 |

## 3. 角色权限矩阵

功能项按六大模块（名称与 README 3.4 节固定一致）分组。「有 / 无」表示能否执行该功能；带限定词的（如「仅本人」「只读」「限发布范围」）表示数据或操作边界。super_admin 天然拥有 regulation_admin 的全部能力。

### 3.1 身份与权限模块（`/auth`、`/admin`、`/me`）

| 功能项 | super_admin | regulation_admin | employee |
|---|---|---|---|
| 用户登录 / 登出、本人资料与改密 | 有 | 有 | 仅本人 |
| 创建管理员（必须提交非空 `role_ids`） | 有 | 按细权限 | 无 |
| 培训学员增改查、启停与导入 | 有 | 按细权限 | 无 |
| 角色、菜单、字典、站点和会话治理 | 有 | 按细权限 | 无 |

学员不再选择部门：新建和导入学员写入 `department_id=NULL`；更新既有学员不接受部门字段并保留历史 `department_id`。底层 `sys_department`、`sys_user.role` 和旧会话数据继续用于共享兼容链路，但不提供部门、员工管理 CRUD。

### 3.2 题库资料与旧制度只读兼容

| 功能项 | super_admin | regulation_admin | employee |
|---|---|---|---|
| 题库资料上传、版本查询与解析重试 | 有 | 按细权限 | 无 |
| 以 `material_id + material_version_id` 发起 AI 出题 | 有 | 按细权限 | 无 |
| 旧制度内容/文件读取 | 按原范围 | 按原范围 | 仅旧发布范围内本人 |

现行产品不提供制度创建、编辑、发布、归档、范围配置或版本切换入口。资料层底层复用 `regulation/regulation_version`，不得据此恢复制度管理 UI/API。

### 3.3 AI 出题模块（`/ai`）

| 功能项 | super_admin | regulation_admin | employee |
|---|---|---|---|
| AI 服务配置（`base_url` / `api_key` / `model`） | 有 | 无 | 无 |
| 发起 AI 出题 | 有 | 有 | 无 |
| 题目审核（通过 approved / 驳回 rejected） | 有 | 有 | 无 |
| 题目编辑 / 重新生成 | 有 | 有 | 无 |
| 人工录入题目（source = manual） | 有 | 有 | 无 |
| 组卷与试卷发布（exam_paper / paper_question） | 有 | 有 | 无 |
| 查看题库与审核状态 | 有 | 有 | 无 |

### 3.4 学习行为管控模块（`/learning`）

| 功能项 | super_admin | regulation_admin | employee |
|---|---|---|---|
| 在线学习（学习会话 / 心跳上报 / 滚动上报） | 有 | 有 | 限发布范围内的本人 |
| 查看学习进度与有效学习状态 | 有（全员） | 有（全员） | 仅本人 |
| 查看他人学习会话明细（`learning_session`） | 有 | 有 | 无 |

### 3.5 考试评分模块（`/exams`）

| 功能项 | super_admin | regulation_admin | employee |
|---|---|---|---|
| 参加考试（须通过考试资格校验） | 有 | 有 | 限发布范围内的本人 |
| 试卷管理（组卷编辑 / 发布 / 归档） | 有 | 有 | 无 |
| 查看考试成绩与答题明细（`exam_record` / `exam_answer`） | 有（全员） | 有（全员） | 仅本人 |
| 查看考试记录、详情与自动评分结果 | 有 | 按 `exam_records:read` | 仅本人 |

### 3.6 统计报表模块（`/statistics`）

| 功能项 | super_admin | regulation_admin | employee |
|---|---|---|---|
| 单项制度维度统计（应学人数、学习完成率、参考人数、通过率、平均分、分数分布） | 有 | 有 | 无 |
| 未完成人员清单查看 | 有 | 有 | 无 |
| 部门维度对比统计 | 有 | 有 | 无 |
| 个人维度统计（学习记录 + 考试成绩） | 有（全员） | 有（全员） | 仅本人 |
| 各维度报表 Excel 导出 | 有 | 有 | 无 |

> 说明：学习与考试面向「发布范围内的用户」开放，不按角色排除管理员账号——super_admin / regulation_admin 账号若被纳入制度发布范围，同样作为应学人员参与学习与考核；employee 的数据边界一律为「仅本人」。

## 4. 功能需求清单

按六大模块编号列出（编号前缀与模块对应：FR-ORG、FR-REG、FR-AIQ、FR-LRN、FR-EXM、FR-STT），每条含需求名称、需求描述、优先级与验收要点。

### 4.1 身份与权限模块（FR-ORG）

| 编号 | 需求名称 | 需求描述 | 优先级 | 验收要点 |
|---|---|---|---|---|
| FR-ORG-01 | 用户登录认证 | 用户以用户名 + 密码登录，服务端校验通过后签发 JWT；密码以哈希形式存储于 `sys_user`，不存明文 | P0 | ① 正确凭据登录成功并返回 token；② 错误凭据返回 40xxx 错误码且不泄露「用户不存在 / 密码错误」的具体区别；③ token 过期或缺失时访问受保护接口被拒绝；④ 被禁用账号无法登录 |
| FR-ORG-02 | 培训学员管理 | 管理员维护 institution/external 学员、培训类别、启停状态和导入批次；学员不选择部门 | P0 | ① 创建/更新 DTO 不接受 department 字段；② 新建/导入写 `department_id=NULL`，更新保留既有历史值；③ 用户名/工号重复、非法来源或类别被拒绝 |
| FR-ORG-03 | 管理员管理 | 通过 `POST /admin/administrators` 创建管理员并分配业务角色 | P0 | ① `role_ids` 必填且非空；② 角色必须存在且可分配；③ 创建后权限按角色立即生效 |
| FR-ORG-04 | 学员批量导入 | 提供培训学员模板、预检、批次确认与错误明细，不要求部门列 | P0 | ① 合法行可登录；② 非法行有行号和原因且不污染其他行；③ 同批确认幂等 |
| FR-ORG-05 | 可配置 RBAC | 系统身份与业务角色分离，接口和按钮按权限代码控制 | P0 | ① 学员调用管理接口被拒绝；② 管理员只能访问已授权能力；③ super_admin 天然拥有已注册权限 |
| FR-ORG-06 | 个人信息维护 | 用户查看本人基本信息并修改登录密码 | P1 | ① 修改密码须校验原密码，错误则拒绝；② 修改成功后旧密码立即失效，须用新密码重新登录 |

### 4.2 题库资料与旧制度兼容（FR-MAT）

| 编号 | 需求名称 | 需求描述 | 优先级 | 验收要点 |
|---|---|---|---|---|
| FR-MAT-01 | 资料上传 | 在题库内上传 PDF / DOCX 资料，创建不可变资料版本；响应返回资料版本 `id` | P0 | ① 仅接受 pdf/docx；② 返回 `id/version_no/file_type/parse_status/duplicate_hint`；③ 重复文件提示但不伪造新来源 |
| FR-MAT-02 | 资料解析 | 异步产出 `content_html/text_content`；扫描 PDF 可按受控页图供多模态出题 | P0 | ① 状态为 pending/parsed/failed；② 可重试失败版本；③ 页面图片为内部临时输入，不是图片作答 |
| FR-MAT-03 | 资料版本选择 | AI 出题必须显式提交 `material_id + material_version_id`，服务端校验版本归属 | P0 | ① 两个字段缺一拒绝；② 不接受外部 `regulation_id/regulation_version_id`；③ 题目内部仍可记录实际底层来源列 |
| FR-MAT-04 | 旧制度只读兼容 | 已发布旧制度的内容/文件、阅读计时、固定卷资格和历史统计继续可读 | P0 | ① 旧范围校验不放宽；② 不新增制度管理写入口；③ 历史数据不迁移清空 |

### 4.3 AI 出题模块（FR-AIQ）

| 编号 | 需求名称 | 需求描述 | 优先级 | 验收要点 |
|---|---|---|---|---|
| FR-AIQ-01 | AI 服务配置 | 具备 `ai_config:write` 的管理角色配置 AI 大模型连接参数 `base_url` / `api_key` / `model`（OpenAI 兼容协议，兼容智谱 GLM、DeepSeek、通义千问等），全局生效；super_admin 天然拥有该权限 | P0 | ① 保存后可发起连通性测试并返回成功 / 失败；② `api_key` 存储加密、界面不回显明文；③ 未配置时发起出题被拦截并提示 |
| FR-AIQ-02 | 发起 AI 出题 | 基于指定资料版本的文本或受控 PDF 页图生成 single/multiple；请求必须指定 `material_id/material_version_id`、类别与难度，模型不能覆盖请求标签；judgment 由人工录入或文件导入 | P0 | ① 生成题含完整题干、选项、答案与解析且题型合法；② `source=ai`、`status=pending` 与内部来源版本来自已校验资料；③ 失败可重试且不产生半成品 |
| FR-AIQ-03 | 题目审核 | 管理员审核当前不可变题目版本：通过（approved）或驳回（rejected）；新确认记录实际管理员与时间，仅当前 approved 版本可进入新候选池 | P0 | ① 候选只取当前 approved 版本；② rejected / pending 当前版本不进入新候选池；③ `approved_by/approved_at` 与 `reviewed_by/reviewed_at` 留痕，遗留未知历史保持 null |
| FR-AIQ-04 | 题目编辑 | 管理员修订类别、难度、三类客观题内容和解析；题库无分值，核心编辑新增 revision 并回到 pending，不覆盖旧 revision | P0 | ① 旧版本内容不可变且可查；② single 答案唯一、multiple 至少两个、judgment 固定正确/错误；③ 旧题首次编辑只捕获升级当时内容，不伪造更早历史；④ 人工录题无考点/资料来源输入，也无“新建考点组”入口；⑤ 新增/修订不要求或暗填分数，组卷时按卷独立赋分 |

## 5. 核心用例

选取 8 个覆盖现行闭环与共享兼容链路的关键用例。原制度创建/发布和学习要求配置用例已随管理能力取消，不再作为现行验收项。

### UC-03 发起 AI 出题并审核

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-03 |
| 名称 | 发起 AI 出题并逐题审核 |
| 主角色 | regulation_admin |
| 前置条件 | 题库资料存在 `parse_status = parsed` 的指定版本（文本可用，或为启用多模态的 PDF）；具备 `ai_config:write` 的管理角色已配置支持对应输入类型的 AI 服务（`base_url` / `api_key` / `model`） |

**主流程**：
1. 管理员选择资料、资料版本、培训类别与难度，设定 single / multiple 数量；judgment 通过人工录入或文件导入；题库生成不配置分值；
2. 客户端提交 `material_id + material_version_id`；系统以该版本 `text_content` 为上下文，扫描版 PDF 可按页转为受控 `image_url` 内容块；
3. 合法结果在一个事务中创建题目身份与 revision 1；类别/难度取请求值，内部来源列记录实际资料版本，状态为 pending；
4. 管理员逐题审核当前版本：通过 → approved 并记录实际确认人/时间；驳回 → rejected 并记录复核人/意见；
5. 编辑或单题重新生成创建新的 pending revision，旧 revision 不覆盖；扫描 PDF 重新生成继续使用多模态链路；
6. 新候选池只读取当前 approved 且类别/题型/难度匹配的版本；已有发布/个人题单冻结由后续发布链路负责。

**异常流程**：
- A1：AI 服务不可用 / 调用超时 → 提示失败且可重试，不产生半成品数据；
- A2：AI 返回格式异常 / 无法解析为合法题目 → 该批结果丢弃并提示重新生成；
- A3：`text_content` 不足且不是可多模态处理的 PDF → 拒绝发起；扫描 PDF 则按页渲染后继续。
- A4：类别不存在/停用、难度非法、资料与版本不匹配或 AI 题缺真实来源版本 → 拒绝且不写题目。

**后置条件**：题库存在带类别、难度与不可变版本的题目；当前 approved 版本可被后续发布服务按精确条件读取，审核操作留痕。

| 用例编号 | UC-04 |
| 名称 | 员工有效学习 |
| 主角色 | employee |
| 前置条件 | 制度 `status = published` 且员工在发布范围内；员工已登录 |

**主流程**：
1. 员工打开制度阅读页，系统创建 `learning_session`（记录 `started_at`）；
2. 阅读期间页面每 30 秒心跳上报一次（携带当前滚动位置）；
3. 服务端做时长容差校验（单次心跳最大计入 45 秒），将有效时长累计至 `learning_record.total_seconds`；
4. 滚动经过的内容按段置位 `scroll_coverage` 位图（10 段），并更新 `max_scroll_percent`；
5. 阅读途中页面失焦则暂停计时，恢复聚焦后继续；
6. 员工离开阅读页，会话结束（写入 `ended_at` / `duration_seconds`）；
7. 当 `total_seconds ≥ required_minutes × 60` 且滚动覆盖位图覆盖到底部段时，`learning_record.is_valid = true` 并记录 `valid_at`，学习页向员工提示「已达有效学习标准」。

**异常流程**：
- A1：网络中断导致心跳丢失 → 恢复后从当前时刻继续累计，丢失区间不计时长（以服务端已收到心跳的累计为准）；
- A2：员工直接关闭浏览器 → 会话由服务端按最后一次心跳加 45 秒封顶截止，已累计进度不丢失。

**后置条件**：学习进度持久化于 `learning_session` 与 `learning_record`；达标员工具备该制度的考试资格。

| 主角色 | employee |

### UC-06 参加考试并自动评分

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-06 |
| 名称 | 参加考试并自动评分 |
| 主角色 | employee |
| 前置条件 | 旧制度固定卷已通过 UC-05；或新培训考试已通过发布/类别/来源/次数/身份校验（默认不要求学习完成）；试卷 `status = published` 且未超出补考次数限制 |

**主流程**：
1. 员工发起考试，系统创建 `exam_record`（`status = in_progress`、`attempt_no` 递增），Redis 启动考试计时；
2. 系统对试题与选项乱序后呈现试卷，开始 `duration_minutes` 倒计时；
3. 学员逐题改答，完整稳定ID答案保存到当前user/record本地最小草稿；题面只驻内存，不调用服务端draft/heartbeat；
4. 学员主动交卷并二次确认，冻结完整record_id + answers[{item_id,option_ids}]；服务端锁本人record后取accepted_at，严格早于deadline才受理；到期只查状态/纯timeout，不提交草稿；
5. 首次有效主动提交按冻结answer_option_ids/分值/规则评分，多选非空真子集按冻结比例部分分；每题恰一次、未答[]，跨题/重复/缺项/旧字段等严格拒绝；
6. 同事务写完整答案/逐题得分、manual/finalized、submitted_at=accepted_at、graded_at与passed/failed；重复终态返回首次结果；
7. 本人和管理员通过统一结果 reader 查看冻结题面、本人答案、标准答案、解析与得分。

**交卷后分支**：

| 路径 | 状态与结果 | 后续操作 |
|---|---|---|
| legacy固定卷 | 主动提交保持旧数字协议/评分兼容；新到期同样纯timeout，不从Redis暂存评分；历史submitted/已评分timeout只读保留 | 合法评分集合进入旧统计；新纯timeout排除，未通过且剩余次数可补考 |
| 新培训考试 | 主动受理为passed/failed + manual + finalized；到期为timeout + not_submitted + score=0，submission_method/submitted_at/graded_at=NULL，无逐题结果 | 失败或纯timeout且次数未用尽可补考；纯timeout历史可见，不进finalized成绩/排名分母 |

**异常流程**：
- A1：legacy 固定卷资格校验失败（学习被判定未达标）→ 拒绝创建考试记录；新培训改校验发布、类别/来源范围、次数、期限、身份和并发，不因未完成学习拒绝；
- A2：考试中断网 / 误关闭页面 → 重新登录进入后，in_progress 记录仍在限时内可继续作答；
- A3：重复点击/不同答案并发/submit与timeout竞争→record锁只允许一个终态，主动评分副作用仅一次；请求结果不明先查状态，active且未截止最多重试一次同payload，否则保留草稿继续查证；

**后置条件**：主动受理才形成最终评分；纯timeout无答案/评分事实。历史submitted显示待确认；历史已评分timeout保留原分数、明细及允许的冻结结果图片。统计/排名排除新纯timeout，不重写历史终态。

### UC-07 补考

| 项目 | 内容 |
|---|---|
| 用例编号 | UC-07 |
| 名称 | 补考 |
| 主角色 | employee |
| 前置条件 | **legacy 固定卷**前次作答 `status = failed` 或 `timeout`；或**新培训考试**前次已finalized且未通过或为纯timeout；两者均须未超过试卷 `max_attempts`（默认 3 次） |

## 7. 约束与假设

### 7.1 业务约束

| 编号 | 约束内容 |
|---|---|
| C-01 | **学习时长以服务端累计为准**：客户端上报的时长仅供参考，有效学习时长一律以服务端经容差校验（单次心跳最大计入 45 秒）累计的 `learning_record.total_seconds` 为准 |
| C-02 | **有效学习双条件缺一不可**：累计有效学习时长 ≥ `required_minutes` 与滚动覆盖位图覆盖到底部段必须同时满足，任一条件单独满足均不判定达标 |
| C-03 | **AI 生成题目必须审核**：`source = ai` 的题目必须经管理员审核为 `approved` 后方可入卷；人工录入（`source = manual`）题目由录入管理员自担质量，免审核直接入卷 |
| C-04 | **发布前置条件**：试卷发布前只能引用当前 approved 的三类客观题版本，题目分值合计必须等于 100 分 |
| C-05 | **最终总分不可直接修改**：single/multiple/judgment 均由服务端按冻结快照自动评分；finalizer 汇总总分、及格和正确率，最终结果只读，不提供人工改分入口 |
| C-06 | **取最高分口径**：legacy 同一试卷多次作答取最高分；新培训统计在同一考试场次、难度、评分规则内按每人 finalized 记录最高分统计，同分并列；旧制度跨试卷报表保留原口径，不能混算 |
| C-07 | **版本切换不追溯学习进度**：学习进度与考试资格绑定制度（regulation）而非具体版本；切换生效版本（`current_version_id`）不清零已有学习进度，如需要求重新学习，由管理员调整学习要求（如提高 `required_minutes`）或另行发布新制度 |
| C-08 | **归档即止**：制度或试卷归档（archived）后，员工端不可见、不可再学习或发起新作答，但历史学习与考试数据保留并计入统计 |
| C-09 | **应学人数口径**：以发布范围（`regulation_scope` / `is_all`）内在职员工数为准；发布范围调整后统计口径随之更新 |
