## 1. 业务背景与目标

### 1.1 业务背景

现有平台已经覆盖学员、培训类别、视频课程、题库、试卷发布、随机抽题、自动评分、考试记录和统计。本次需要在这些功能上增加报名收费、预约安排、现场签到和退款处理。已经确认的业务安排如下：

1. **个人和企业都可以购买两种服务**：398元包含培训和考试，必须先参加培训才能考；98元只包含考试。企业一笔订单只选一种服务，需要两种服务时分别下单。
2. **个人自行办理，企业统一代办**：个人先付款再预约。企业导入成员、统一付款后，可以把成员约到同一日期和时段，也可以分批安排；之后由员工本人查看预约、改期或凭剩余次数预约下次考试。
3. **号源由运营设置**：开放日期、时间段和每日总人数都可以配置。培训加考试可以整天接待同一批人；单独考试可以设置多个时段，不固定时段数量，也不自动均分名额。
4. **学员在海珠区固定地点到场**：本人在学员端查看预约和办理改期，预约当天通过定位和照片核验完成签到。同一天培训和考试共用一次签到，签到不能代替实际参加培训。
5. **付款、服务和退款分别记录**：系统保存付款、预约、签到、培训参加、考试及退款记录。企业从PC端、个人从H5端申请退款；后台审核通过后人工办理，再由运营登记实际退款结果。

### 1.2 建设目标

| 目标 | 可验收结果 |
| --- | --- |
| 个人闭环 | 学员使用个人手机号验证码登录，选择服务、付款、预约、改期、签到，并进入现有培训与考试流程 |
| 企业闭环 | 企业联系人使用机构开通的企业后台账号，导入成员、统一报名付款并批量安排初次预约；员工本人在学员端查看和改期 |
| 排期与容量 | 运营配置服务日期、整天或多个自定义时段和每日总号源，时段数量与粒度不限于上午／下午；满额后不可继续预约，不超卖 |
| 现场核验 | 学员在预约日期当天，于海珠培训地点配置半径内完成定位和照片人证比对，同一天只签到一次 |
| 支付可追踪 | 保存微信确认的付款、企业直接转账确认、退款申请、审核及运营登记的退款结果；每笔记录可查询，微信结算到银行不作为订单已付款的条件 |
| 考试融合 | 新开考检查预约、签到及对应服务资格；398元套餐须先经现场确认参加本轮培训，98元无套餐培训门槛；不改写既有试卷快照、作答、评分、超时和历史成绩 |

### 1.3 首期范围

- 单家培训机构，当前只有海珠区一个培训地点；
- 398元培训加考试服务与98元单独考试服务；
- 个人先付款后预约；
- 企业导入成员、统一付款、批量初次预约；
- 企业微信扫码支付和对公转账，个人移动端在线支付；
- 预约查看、个人改期、现场签到、退款审核和收支核对；
- 接入现有课程、公共随机考试、考试记录和统计。

### 1.4 明确不建设

首期不建设多地点或分校选择、付款前锁位、候补补位、当天临时预约、二维码签到、活体核身、系统短信／微信／推送通知、企业成员换人、月结授信、优惠券商城、证书平台和住建平台对接。

首期不建设机构修改或取消已有预约场次后的批量迁移、重新确认及通知流程；有预约后按第4.3节保留原日期、时段和预约，仅可停止接受新预约。

首期不建设微信商户余额提现、结算到银行卡、手续费或银行结算差额的对账功能，不接入自动退款接口。微信结算和提现由机构在微信商户平台与银行处理；企业直接向机构对公账户付款仍须人工核实到账。

## 2. 角色、账号与数据边界

### 2.1 角色划分

| 使用者 | 登录端 | 主要职责 | 数据范围 |
| --- | --- | --- | --- |
| 机构管理员 | PC管理端 | 配置服务、地点、场次、企业账号；查询预约和签到 | 按现有RBAC权限 |
| 运营／财务人员 | PC管理端 | 确认对公到账、审核退款、核对收退款 | 仅获授权的订单和财务操作 |
| 现场工作人员 | PC管理端 | 查看当天名单和签到结果，处理定位或照片核验异常 | 当天最少必要身份信息 |
| 企业联系人 | 企业PC入口 | 导入成员、报名、统一付款、批量安排初次预约、申请企业退款 | 仅本企业成员和订单 |
| 学员个人 | H5／小程序 | 个人报名付款；查看本人预约、改期、签到、培训和考试 | 仅本人 |

### 2.2 企业后台账号与学员个人账号

企业账号与学员账号完全分开：

```text
机构开通的企业账号 → 登录PC企业入口 → 管理本企业名单、订单和初次预约

个人手机号验证码   → 登录H5／小程序 → 查看本人预约、改期、签到、培训和考试
```

- H5／小程序不提供企业账号登录、企业身份切换或企业管理菜单；
- 企业导入名单后，系统为成员建立或关联个人学员记录；
- 企业完成预约后，每名员工都得到一条归属于本人的预约；
- 员工使用导入名单中的本人手机号登录，即可看到自己的预约；
- 后端保留预约来源是个人还是企业，用于付款、权限和统计，学员端无需选择来源；
- 企业后台会话不能进入学员答题，个人学员会话不能进入企业名单和缴费管理。

### 2.3 企业账号开通

首期由机构后台填写企业名称、联系人和手机号并开通企业账号，不开放企业自行注册。企业联系人仅能访问本企业数据，不获得机构管理员、题库、答案或其他企业数据权限。

## 4. 核心业务规则

### 4.1 服务与价格

| 服务 | 价格 | 包含内容 | 考试机会 |
| --- | ---: | --- | --- |
| 培训加考试 | 398元 | 300元培训费＋98元考试费；1次培训资格＋考试资格 | 取关联试卷配置，当前默认3次 |
| 单独考试 | 98元 | 不含培训，只提供考试资格 | 取关联试卷配置，当前默认3次 |

- 398元套餐必须先实际参加本轮现场培训，并由现场人员确认后才能使用本轮考试资格；98元单独考试不要求参加该套餐培训。初次预约仍一次生成当天培训及关联考试预约，培训前可以安排考试预约，但不能提前开考；
- 支付模块不得另行写死3次；
- 服务介绍和下单确认页读取当前关联已发布试卷的次数；提交订单前向购买方展示价格、成员、服务内容、承诺次数和适用退费条款。提交时如报价或权益与确认页展示不一致，须重新确认，不能静默替换；
- 服务对外出售前必须关联一份可用的已发布试卷；个人或企业提交订单时，由服务端固定价格（单价及应付总额）、购买成员及人数、服务内容、`paper_id`、承诺次数、服务版本和适用退费条款的内容及版本，保存一份下单时确认的完整内容，以下称“订单快照”；后台后来改配置，不修改这份内容；
- 订单提交后，订单详情、支付金额校验和后续权益发放均以该订单快照为准；到账确认只激活订单已经承诺的权益，不重新读取当前服务价格、成员或试卷次数来解释原订单。微信回调延迟或企业转账人工确认较晚，都不能改变原订单承诺；
- 未付款订单过期后，须按当前报价及权益重新向购买方展示并确认，再创建新订单；旧订单及其快照保留，不原地改价或自动替换条款。已付款但确认延迟，不等于未付款订单过期，不要求购买方因确认延迟重新下单。订单关闭后发现收款，按第4.6.1节核实并办理，不丢弃这笔钱；具体付款有效期另行确定，本条不设置任意过期时长；
- 第一次成功开考仍由现有考试模块冻结当时可用的发布版本、抽题规则和题单，但本轮次数上限须遵守订单快照的承诺次数，不能被后来减少的试卷配置覆盖；如果付款后关联试卷已撤回且没有可用发布版本，阻止新开考并由运营改配等价发布版本或退款，不能静默换卷；
- 成功开始考试才消耗一次，超时未交卷也计次，开始事务失败不计次；
- 次数用尽仍未通过时，只能重新购买98元，或重新购买398元获得新的培训与考试服务；
- 重新购买形成新的服务资格轮次，当前轮次的次数从第1次重新计算；每次考试记录关联具体服务资格轮次，保留旧订单、旧考试次数和历史成绩，不修改旧记录来“清零”；
- 不按398元／98元设置题目难度或通过率，难度继续按现有考试设计和服务端学员来源处理。

### 4.2 培训地点

- 首期只有海珠区一个培训地点，后台为单地点设置页，不提供分校列表和学员选校；
- 地点字段至少包含名称、详细地址、经度、纬度、签到半径和启用状态；
- PC内嵌高德地图，支持地址搜索、地图选点、拖动标记和范围圈预览；
- 经纬度由地图带出并只读展示，签到半径默认100米、允许后台调整；
- 后台地图和移动端定位统一采用GCJ-02坐标；
- 数据层保留独立地点记录，不能把海珠地址、坐标和100米写死在代码中；
- 地点修改不改变历史预约，预约保留地点名称、地址和坐标快照。

### 4.3 场次、时段与名额

- 场次分为“培训加考试场”和“单独考试场”；98元人员不能预约培训加考试场；
- 运营人员可按星期或具体日期配置每日总号源及可预约时段；时段支持整天，也支持自定义开始、结束时间和按小时划分，不固定为上午／下午，不固定为3场或4场；
- 还没有人预约的日期或时段，可以修改或删除；已有预约记录的日期或时段，不能直接修改或删除，可以停止接受新预约，已有预约继续有效；
- 停止接受新预约只关闭新的预约入口，不取消已有预约、不释放其名额；已约学员仍按原日期和时段到场，并按原资格规则签到、参加培训和考试。以上是机构排期维护规则，不限制学员按第4.7节自行改期；
- 本文的时间配置仅指预约日期和时段，不另设“服务时间”；首期使用唯一海珠地点，不建设因机构更换地点、日期或时段而迁移已有预约的流程；
- 培训加考试日按整天一批人组织。例如场地可容纳60人，就开放60个号，同一批学员上午培训、下午考试；不要求把这60个号再拆成小时配额；
- 单独考试日由运营配置每日总号源及多个时段，例如全天120个号、上午两场下午两场，也可配置3个、5个、6个或按小时划分的时段。上述人数、时段数量和星期均为示例，实际由运营设置；
- 名额仍按日期和场次类型配置每日总上限，各时段共享当日总名额，不按时段数量自动平均分配，也不把每日总号源复制给每个时段；所有时段的已约人数合计不得超过当天总名额；
- 一名398元学员初次预约产生培训、考试两条关联记录，但只占当天套餐场一个名额；当天连续考试不因考试次数增加而重复占用名额；
- 现场人员负责当天培训、考试、连续重考及不同批次的接待安排。首期不增加系统营业时间、最晚新开考时间或自动清场控制；此边界不改变预约日期校验、考试次数和每次考试已有的截止时间；
- 学员只能预约明天及以后的日期，当天不再接受新预约；
- 不建设付款前临时锁位、超时释放锁或候补补位；提交正式预约时才校验并占用名额；
- 企业批量提交时按本次实际成员数检查容量，同一批可以预约到相同时间，也可拆分到不同日期；
- 企业每次提交选中的成员必须全部预约成功，或全部失败且本次不新增预约、不占名额，并提示失败原因；不能只成功一部分。企业仍可主动分多次提交安排不同日期，完整性要求针对本次提交，不要求整张订单一次约完；398元每位成员的培训及关联考试预约必须一起建立；
- 已签到人员改期时，原日期名额不回补、不触发当天补位；目标日期仍须有名额；
- 尚未签到且预约日期在未来的普通改期，原预约失效后可以按有效预约重新计算余量。

### 4.6 支付与到账

本节中的“开通资格”，指让订单中的学员可以凭已购服务办理预约；不会替学员预约、签到或开始考试。

- **先核实付款，再开放预约**：个人和企业都必须付清对应订单。系统按提交订单时确认的人数和价格计算应付金额，付款页面不能自行改金额；后台后来改价，也不能改变原订单应付金额。
- **收到钱后按原订单办理**：确认收款后，为原订单中的成员开通已经购买的服务和考试次数。同一订单只开通一次，不因为工作人员多点一次或微信重复发送付款通知而多给一次资格。
- **付款方式**：个人在微信小程序内或微信内网页付款，企业在PC扫码支付或对公转账。对应微信接入方式分别为小程序支付、JSAPI支付和Native支付。
- **微信付款以微信确认结果为准**：系统接收并核验微信的付款成功通知，必要时主动查询原微信订单；微信确认交易成功、商户和金额正确后，本系统记为已付款并开通一次原订单资格。无需等待微信结算到机构银行卡；结算或提现异常不自动改成学员未付款，也不自动给学员退款。用户付款截图、页面显示成功，都不能单独作为已收款的依据。
- **对公转账以银行实际到账为准**：有权限的财务人员核对银行收款记录后，在系统登记对应订单、金额、银行交易凭据、确认人和时间。不得只看客户的转账截图就确认收款。
- **每笔真实收款都要留下记录**：一个订单可能因为重复付款等原因收到多笔钱，每笔都保留；订单已付清，不代表后来多收到的钱可以忽略。重复读取同一笔收款，不得再记成一笔新收入。
- **退款由人工办理，结果由运营登记**：企业从PC端、个人从H5端提交申请，后台审核通过后显示“待人工退款”。有权限的工作人员在微信商户平台办理原交易退款，或对原对公转账办理银行退款；本系统不调用退款接口出款。运营核实实际结果后登记成功、处理中或失败，不能把审核通过当成钱已退回。
- **只核对本系统的订单收退款**：缴费订单和退款页面保留付款记录、审核记录、人工退款结果及第4.6.1节的异常处理；收支汇总查询可后续完善。首期不下载交易账单做整套自动对账，也不核对微信向机构银行卡结算、提现、手续费和结算差额。财务仍须核实企业直接对公转账及人工办理的退款，这与微信结算流程分开。
- 正式上线前须具备微信商户资质、证书和接收付款通知的域名，并完成真实支付与退款验收。

#### 4.6.1 遇到异常收款时怎么办

| 遇到的情况 | 系统和工作人员怎么处理 | 怎样才算处理完 |
| --- | --- | --- |
| 用户已经付款，系统还显示未付款 | 页面显示“正在核实付款，请勿重复付款”。系统主动向微信查询原订单；微信确认付款成功且金额正确后，记下这笔收款并开通一次原订单资格。没有查清前不自动另建付款订单；暂时查不到结果的，列入财务待处理，由财务在微信商户平台核实 | 确认付款成功则订单显示已付款且资格可用；微信确认未付款才按未付款处理。查询失败不能当成未付款，也不能只靠截图放行 |
| 本地订单已经关闭，之后才发现实际收到钱 | 先保存这笔收款，由财务核对原订单、金额、是否重复付款及退款情况。原订单仅因未付款关闭、金额足够、原服务仍能提供且购买方没有申请取消或退款的，按原订单开通一次资格；重复付款、已取消／已申请退款或无法提供原服务的，进入退款处理。少付、无法确定付款方的按下方对应规则处理 | 每笔钱有明确结果：用于原订单服务，或退回原付款方；不能因为订单关闭而忽略收款，不能套用新价格或自动给已退款订单重新开通资格 |
| 企业已经转账，又扫微信付了一次 | 两笔收款分别登记在同一订单下，订单只开通一次资格；财务核对实际多收金额，按每笔原付款来源办理退回，不再增加学员、培训资格或考试次数 | 保留订单应收的金额，多收部分实际退回；正常购买的资格继续有效 |
| 同一笔银行转账被重复登记，或被登记到两个订单 | 根据银行交易凭据和收款账户识别同一笔钱；系统提示该笔收款已经登记在哪个订单，拒绝再次用于另一订单，即使两名工作人员同时操作也一样。原登记有误的，走下面的纠错流程 | 一笔实际银行收款只登记一次、只用于一个订单；不因重复点击或多人操作重复开通资格 |
| 对公转账少于订单应付金额 | 财务确认确实少付后，页面显示已收金额和还差多少，提示企业补足；补款仍登记到原订单。确认仍用于本订单、未退回且未进入退款处理的钱已足额，才为原订单全部成员开通资格，不按部分款项擅自给部分成员开通。企业不再购买的，由财务核实后按退款流程退回已收款 | 已补足并开通一次资格，或已收款实际退回；少付期间不能把订单标成已付清 |
| 实际付款多于订单应付金额 | 原付款方和订单已核实、正常应付部分足额时，开通一次原订单资格；多出来的金额列为“多收待退”，由财务核对后退回，不擅自转为下一单余额或增加考试次数 | 多收部分实际退回，原订单服务继续有效 |
| 收到钱，但不知道是谁付的或对应哪个订单 | 先登记为“收款待核对”，保留金额、银行交易凭据等信息；财务核实付款方和对应订单前，不给任何人开通资格，也不能随意找一张同金额订单挂上。查明后登记到正确订单；查明为误转款的，核实原付款方后办理退回 | 款项已用于确定的正确订单，或已退回核实过的原付款方；不能退给未核实身份的申请人 |
| 工作人员误点了已收款，或把钱登记到了错误订单 | 有权限的财务人员新增一条更正记录，写明原登记、错误原因、改正结果和处理人，不能删除原记录。没有实际收款的，不得凭错误记录办理退款；钱记错订单的，更正到核实后的正确订单，并保留原关联历史。错误开通的资格按下方规则处理 | 收款归属、应付实付和资格恢复一致；已提供的培训、考试及成绩保持真实，不通过删记录或改成绩掩盖错误 |

处理异常还须遵守以下规则：

- **退过的钱不能再算作付款**：核算还差多少或多收多少时，只计算仍用于本订单、未退回且未进入退款处理的钱。例如98元订单先收到50元并已退回，后来收到48元，目前只收到可用的48元，不能按98元开通。已退回或正在退回的部分也不能再退一次。
- **正常购买的资格不能被误伤**：退回多收、重复收到或误转的钱，不等于取消原订单服务。只退多收的钱时，不暂停正常资格、不减少考试次数；这类退回不按“已参加培训不退服务费”拦截。
- **误开通的剩余机会先核实再恢复**：没有真实足额收款却误开通的，暂停由该错误产生、尚未使用的培训和考试机会，阻止新的预约、培训参加确认和新开考；即使已经考过一次，剩余次数也要暂停。保留已有预约及名额等待核对，不自动取消或释放。查明有正确足额收款后，只解除这次误登记造成的暂停；确认没有收款时保持暂停，补足后再核对恢复。若原订单已有另一笔正确足额收款，正常资格不因本次纠错而暂停。已经开始的考试继续按原规则恢复、交卷或超时，已参加培训和历史成绩不得删除。
- **核实付款不能取消正在办理的服务退款**：补记付款或改正登记，只处理这次收款问题；学员已经申请取消服务、退款处理中或已经退款的，仍按第4.8节处理，不能因为查到了付款记录就重新开通或恢复资格。
- **同一笔退款不能退两次**：人工办理后暂时查不到结果，办理人员先在微信商户平台或银行核实原退款；未确认前不再退一次，运营也不能把它登记成成功。退回金额不能超过实际应退的余额。
- **有人负责，结果有凭据**：每笔异常记录处理人、异常原因、下一步处理动作及处理经过；未解决的持续留在待处理列表。只有收款归属和资格均已核对正确，或退款已确认实际完成，才可标记处理完毕。

### 4.7 预约查看与改期

- 无论个人自行预约还是企业批量预约，最终都形成归属于具体学员的个人预约；
- 学员端“我的预约”统一展示本人预约，不要求学员识别预约来源；
- 企业安排成功后，员工无需重复报名、付款或初次选日期；
- 员工只能修改自己的预约，不能修改同批其他成员；
- 已签到但培训和考试都尚未开始时仍可改期；
- 398元学员本次培训和绑定考试均未开始时，可以把培训及绑定考试一起改到其他可约日期；
- 已参加培训但未参加考试时，培训事实保留，不退款，只允许修改考试预约；
- 已经开始的考试不能通过改期取消或逃避本次尝试；
- 改期不自动退款，也不额外收费；跨天改期后在新日期重新签到。

改期必须整体完成：目标名额检查、新预约安排、原预约变更及相应名额处理共同成功，才算改期成功。目标日期满额或保存失败时，保留原预约、原名额及原签到适用关系，目标日期不遗留本次占位。398元尚未参加的培训及绑定考试必须一起改期，不能只成功一条；已参加培训后仅改尚未参加的考试预约，保留培训事实。成功后的原日期名额仍按第4.3节处理，已签到改期不回补原日期名额。

“改期”与“预约下次考试”分开处理：尚未参加的预约换日期，按改期处理；已经参加过考试、凭剩余次数另一天再来，按第4.10.1节新增考试预约，不能把已使用的历史预约改到新日期。过去日期未到场、未签到的预约仍可由本人改到未来可约日期，不因缺席消耗考试次数。

### 4.8 退款与成员变更

本节处理的是取消已购服务后的退款。第4.6.1节中退回多收、重复收取或误转的款项，只纠正收款错误，不适用本节取消正常服务资格的处理；不得因此冻结或终止正常已付款成员的资格。

- 个人从H5“我的订单”申请退款，企业联系人从PC企业订单申请；小程序沿用个人申请规则，员工不能把企业款退给自己；
- 后台运营审核申请；审核通过后交工作人员人工退款，再由运营录入退款结果。首期不自动审批、不通过本系统退款接口出款；
- 398元服务在培训和考试均未使用时，审核通过后全额退款；
- 98元服务在考试未使用时，审核通过后全额退款；
- 企业可在同一订单中选择部分未使用成员申请退款，不影响其他成员；
- 已参加培训但未考试的398元服务不退款，只能改考试预约；
- 企业成员资格不能换人、转让或修改身份证后沿用原付款；
- 企业若需增加新员工，必须新增报名、付款和预约；
- 退款记录必须关联原订单、原成员、申请人、审核人、金额和实际处理结果，不能通过删除成员伪造退款。

#### 4.8.1 申请退款后暂停服务，防止重复退钱

- **申请退款后，先暂停对应成员的服务**：系统接收有效退款申请时，一并暂停该成员本轮服务资格。待审核、已同意待退款、退款中和退款结果待核实时，都不能新预约、改期、确认参加培训或开始新考试。现场名单须显示“退款处理中，暂停服务”；不能只禁止学员操作，却仍允许工作人员确认培训。
- **退款和使用服务不能同时成功**：接收退款申请、确认参加培训和新开考时，都由服务端检查最新记录。如果培训已确认参加或考试已开始，按本节未使用服务的退款规则拒绝申请；如果退款申请先被接收，后续培训确认和新开考必须被拒绝。审核及人工办理退款前还要重新核对，不能只凭申请时的旧页面判断。已经发生的培训、进行中考试和历史成绩不删除；进行中考试仍按原规则恢复、交卷或超时。
- **同一成员的同一份服务，只能有一笔未处理完的服务退款申请**：已有申请待审核、待退款、退款中或结果待核实时，再提交不能另建一笔，也不能把该成员重复放进另一批退款。页面返回现有申请及处理进度；不同成员仍可分别申请。
- **先算清还能退多少**：受理、审核、交人工办理和录入结果时，都核对该成员、订单及原付款分别已经退了多少、还有多少正在办理。本次申请金额，加上其他申请中已退回、待审核、审核通过待办理、退款处理中和结果不明的金额，不得超过按退款规则可退的实际收款；同一申请在不同处理阶段只计算一次，合并办理时也不能再把汇总金额重复加一遍。每笔原付款的全部退款合计不得超过该笔实际收款，多收款退回和服务退款一起计算，不能各算一遍。
- **看不清结果时，先核实原退款**：人工操作后，办理人员在微信商户平台或银行查询原退款记录。页面没反应或结果不明时，不能再退一次，也不能同时换一个渠道再退。只有整笔申请被驳回或终止，且确认不会再出款，才释放尚未退回的金额额度；仍在人工办理的继续保留金额占用。
- **审核拒绝与退款完成分别处理**：审核拒绝时，只解除这次退款造成的服务暂停；若还存在收款纠错等其他暂停，继续按其原因处理。审核通过后取消尚未开始的未来预约，未签到者释放未来名额，已签到者不回补原日期名额；审核前不删除预约或提前回补名额。人工退款失败或结果待核实期间仍暂停服务，不因失败自动恢复。运营核实凭据并登记实际退款成功后，终止对应成员的本轮服务资格，不影响同订单其他正常成员。
- 首期不提供“只取消预约但继续保留待预约资格”的独立取消操作，学员选择改期或申请退款即可。第4.6.1节退回多收、重复收到或误转的钱不取消正常服务，但同样遵守不得超额退款、结果不明先查询的要求。

#### 4.8.2 人工退款与结果登记

- **审核通过后交人办理**：每笔申请指定办理人并显示办理进度。同一申请不能同时交给两人各退一次；更换办理人时，先核实前一人是否已经退钱。微信退款由工作人员登录微信商户平台操作，原对公收款由财务通过银行办理。
- **运营按凭据录入结果**：登记原订单、退款成员、实际金额、办理渠道、办理时间、退款单号或银行凭据及录入人。录入成功须有可核对的实际退款成功凭据，不能只勾选“成功”。处理中、失败或结果不明也要如实登记原因，不得提前结束资格或释放退款金额占用。
- **多人合并办理仍逐人记账**：同一笔付款中的多个已批准成员可由工作人员合并退款。每人保留应退金额和申请记录，合计等于实际退款金额；运营确认成功后只更新这些成员，不把整张企业订单当成全部已退。
- **遇到微信限制由办理人核实**：工作人员办理前在商户平台核对原交易、已退和待退金额，以及可办理的退款方式。平台提示次数、期限或账户限制时，记录原因并交财务处理，保留原申请，不能假报成功或让客户再申请一次。
- **不能原路退回时仍要防重复**：财务先确认原退款不会继续出款，再核实原付款方和其他可用方式；采用线下转账时，记录原付款方确认、收款账户及实际退款凭据，不能随意退给其他员工。
- **登记错了保留更正记录**：不能删除原结果再重填；须写明原因、凭据和改正结果，重新核对对应成员资格及可退金额，不改培训、考试和成绩历史。

微信官方支持在商户平台人工退款；本系统首期不接入退款申请、退款查询或退款通知接口。官方普通商户退款规则仍列明付款后365天及最多50次部分退款，人工办理时由工作人员结合商户平台实际记录核实，不能把系统内登记的次数当作微信全部实际退款次数。依据：[微信退款产品说明](https://pay.wechatpay.cn/doc/v3/merchant/4013071001)、[微信接入指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791870)。

渠道限制不自动取消已购资格，也不直接否决原本符合规则的退款申请；无法办理时保留待处理并由财务继续核实。首期不实现自动计算微信退款剩余次数、自动占用渠道次数或自动出款的流程。

### 4.9 现场签到与本人核验

```text
预约日期当天打开小程序，进入本人预约详情
  → 本人点击“签到”（未签到尝试开考时，先引导“去签到”）
  → 检查本人付款、有效预约及服务资格
  → 获取本次最新定位和定位精度
  → 服务端按预约地点坐标和配置半径计算距离
  → 当天首次到场拍摄一张正脸
  → 后端读取既有加密实名姓名和身份证号做人证照片比对
  → 服务端成功保存当天签到，显示“今日已签到”
  → 培训与当天全部考试复用，尚未自动开考
```

#### 主动签到与页面入口

1. 考试二维码进入考试Tab，培训二维码进入课程Tab；也可以自行打开小程序。二维码仅作页面入口，不证明本人到场。
2. 本人在预约详情点击“签到”后开始核验；打开小程序、扫码、进入Tab或仅定位成功，都不自动签到。
3. 没点签到就保持未签到，预约当天到场后可以随时再点；付款、本人有效预约和服务资格仍须正常。
4. 定位在配置范围内、正脸照片比对通过，且服务端成功保存记录后，才显示“今日已签到”；点击按钮本身不算成功。
5. 当天尚未签到时，点击“开始考试”须提示“请先完成签到”，提供“去签到”按钮；不办理就不能新开考，不抽题、不启动倒计时、不扣次数。
6. 签到成功后，98元可进入考试须知；398元还须本轮现场培训参加确认，否则提示“请先参加培训并由工作人员确认”。签到不自动开考。
7. 同一天、同一地点不重复签到；换一天参加须有新日期有效预约并重新签到，不跨天补记过去签到。

#### 核验与复用规则

- 只校验预约日期当天，不设置提前多少分钟、迟到多少分钟或时段结束窗口；
- 定位是否在范围内只能由后端计算，客户端不能提交权威布尔值；
- 身份证只在首次实名认证时上传，签到不重复上传身份证；
- 首期使用静态正脸照片人证比对，不宣称活体检测；
- 同一学员、同一预约日期、同一地点只保留一次有效签到；
- 培训和当天连续考试不重复定位、不重复拍照；
- 398元现场培训是否已经参加，由有权限的现场人员核实本人实际参加本轮培训后，在签到页面单人或批量执行“确认参加培训”；服务端须先检查该成员是否正在退款或因收款错误暂停服务，有暂停则不能确认。该确认关联本轮服务资格，与签到分开记录，是培训资格已使用、退款判断及本轮考试培训门槛的权威事件。视频学习进度继续由现有课程模块记录，不替代现场参加确认；
- 跨天改期或凭剩余次数新增考试预约后，均须在新日期重新签到；
- 设备、定位或供应商异常时，允许有权限的现场人员人工核验并记录原因；
- 不使用短时码、固定码或试卷二维码作为签到或开考凭证；
- 已付款但当天未到场不触发客服催办、电话短信、自动退款或黑名单。

签到数据遵循最小化保存：照片提交供应商完成比对后立即删除临时原图；不落库保存学员本次精确经纬度，只保存地点ID、签到时间、服务端计算距离、定位精度、核验方式和通过／失败结果。距离与精度摘要默认保留180天，之后仅保留签到结果、时间和人工操作审计；生产部署可按机构批准的隐私政策缩短该期限，不得延长后默认无限保存。

### 4.10 培训与考试衔接

- 398元初次预约培训时，系统自动建立当天关联的培训预约和考试预约；两条记录分别保留，一人只占当天套餐场一个名额；
- 398元套餐先培训后考试：必须已有现场人员对本人本轮现场培训的参加确认，才能使用本轮考试资格；上午未参加培训、下午直接来考试的，不能开考，即使已经付款、预约或签到也不能放行。98元单独考试不要求该培训确认；
- 签到不等于培训完成，不自动抽题、不启动考试倒计时、不消耗次数；
- 学员从考试Tab或预约详情准备新开考时，先检查当天有效签到；未签到提示“请先完成签到”并提供“去签到”。签到成功后，98元进入考试须知；398元还须有本轮培训参加确认，缺少时提示“请先参加培训并由工作人员确认”。本人在须知页明确点击“开始考试”后，后端再次检查付款、服务资格、预约、签到、实名、次数及398元培训确认，不能只靠页面提示放行；
- 398元未参加培训者可按第4.7节把本人尚未参加的培训及绑定考试改到未来培训加考试场，不能凭未培训的398元资格转约单独考试场绕过培训。因缺少培训确认被拒绝开考，不生成考试记录、不消耗考试次数；
- 新开考成功后才按现有随机考试规则抽题、保存题单并计次；进行中恢复不换题、不额外计次；
- 当天连续考试与跨天使用剩余次数按第4.10.1节处理；
- 考试次数最初从关联试卷配置读取，提交订单后以本轮订单承诺次数为准。进行中的最后一次即使页面显示剩余0次，也必须允许继续答题；只有该次结束后才显示“考试次数已用完”；
- 考试卡片展示“第N次／共M次”或剩余次数；失败记录和本次新开考入口归于同一考试，历史记录可查看；
- 学员改期、退款或场次停止接受新预约不得删除已开始或已完成的考试记录，不重算历史成绩。

#### 4.10.1 当天连续考试与剩余机会跨天预约

1. **当天继续考**：次数未用尽且本次考试已经结束时，可沿用当天预约和签到继续考试，不重复预约、签到或占名额；每次成功开始新考试才消耗一次机会，超时未交卷也按既有规则计次。
2. **另一天再考**：当天未使用完的次数保留。学员凭原订单、原服务资格轮次，在学员端选择未来可约的单独考试日期和时段，新增一条考试预约，占用目标场次一个名额；不重复收费、不重置次数，跨天重新签到。预约本身不消耗考试次数，已使用的原预约、签到和考试记录保持历史。
3. **已经参加的培训不重复安排**：398元学员培训已参加后，后续只约单独考试场；98元学员跨天使用剩余次数也走同一流程。已有企业代付资格的员工同样由本人办理后续考试预约，无需企业重新报名或付款。
4. **正在进行的考试不能靠另约取消**：本次考试须按原规则交卷或超时结束，再办理剩余机会的跨天预约；不得用改期或新预约取消本次考试、延长截止时间、返还已用次数或重新抽题。

办理跨天预约仍须确认原服务资格有效、未被冻结或退款终止、有剩余次数且目标日期有名额；398元须有本轮培训参加确认，98元不要求。次数用尽时按第4.1节重新购买。已经使用过一次考试机会，不构成阻止剩余机会预约的理由；398元已确认的本轮培训事实可供当天重考和跨天剩余考试复用，不要求每考一次重新培训。

示例：398元学员周一已参加培训、完成第1次考试，尚余2次；本人可新增周二单独考试预约，不再收费或安排培训。周二签到后开始的是本轮第2次考试；若仍有机会，当天可继续第3次，不再另占一个号。日期与3次上限仅为示例，上限取本轮承诺次数。

## 6. 核心用例

### UC-AP-01 个人购买并预约

1. 学员通过手机号验证码登录；
2. 选择398元或98元服务，确认价格、服务内容、考试次数和退费条款；提交时系统固定本人及这些购买承诺，创建订单；
3. 按订单快照付款，确认到账后激活原承诺的服务资格，订单进入“已付款待预约”；
4. 学员选择明天及以后符合服务类型的日期和时段；
5. 服务端检查每日总名额并创建本人预约；
6. 学员在“我的预约”查看详情，按预约日到场。

异常：提交时展示报价或权益已变化，须重新确认；未付款订单过期后重新确认当前报价并创建新订单，不覆盖旧订单。付款未确认不能预约；确认延迟不改变原购买承诺。目标日期满额不创建预约，已付款资格继续保留并可改选或申请退款。

### UC-AP-02 企业批量报名、付款和初次预约

1. 机构开通企业账号；
2. 企业联系人登录PC，下载模板并上传成员名单；
3. 系统逐行预检，企业修正错误或确认有效成员；
4. 企业为本单选择一种服务，确认成员、价格、服务内容、考试次数和退费条款后提交订单；系统固定本单成员及购买承诺，企业按该订单统一付款；
5. 微信或对公到账确认按原订单快照核对并激活对应成员资格；企业选择已付款成员和一个日期／时段批量提交；
6. 系统检查本次选中成员资格和总容量，整体生成所有成员的独立预约及必要的培训／考试关联记录，并占用对应人数的名额；
7. 企业自行通知员工；员工用个人手机号登录即可查看。

异常：成员不能换人；任一成员资格不符、容量不足或保存失败，本次提交全部失败并提示原因，不新增任何成员预约或占位，不静默拆分。此前其他提交已成功的预约不受影响；同一成员、订单或预约重复提交不得产生重复记录或重复占名额。

### UC-AP-03 学员个人改期

1. 学员在“我的预约”打开本人记录；
2. 系统确认所修改的预约对应服务尚未参加；已参加培训者只修改尚未参加的考试预约；
3. 学员选择新的未来可约日期；
4. 服务端检查目标容量，整体完成目标预约安排、原预约变更和相应名额处理；398元尚未参加的培训与绑定考试一起改期；
5. 改期成功后，旧签到不能用于新日期，新日期到场后重新签到；失败时原预约、名额及签到适用关系保持不变，目标日期不留本次占位。

已签到人员改期时，旧日期名额不回补；已参加培训后只允许修改尚未开始的考试预约。

已经参加过考试、使用剩余次数另一天再来的，走UC-AP-06，不修改已使用的历史预约。

### UC-AP-04 到场签到并考试

1. 学员在预约日期当天扫码或自行打开小程序；考试二维码进入考试Tab，培训二维码进入课程Tab，进入页面本身不签到。
2. 本人打开预约详情并点击“签到”；若从考试入口直接点击“开始考试”但尚未签到，先提示“请先完成签到”，提供“去签到”。
3. 本人暂不点击时保持未签到，当天到场后可随时再点；不自动到场、不新开考、不扣次数。
4. 点击后，系统检查本人付款、有效预约和服务资格；获取最新定位，由服务端计算与预约地点的距离。
5. 定位在范围内后拍摄正脸，服务端读取既有实名资料做人证比对；通过并成功保存后显示“今日已签到”。
6. 同一天、同一地点的培训及全部考试复用本次签到。
7. 98元学员可进入考试须知；398元须先实际参加本轮现场培训并由工作人员确认，缺少时提示“请先参加培训并由工作人员确认”。
8. 本人在须知页明确点击“开始考试”，服务端再次检查全部开考条件；新开考成功才生成本次题单并计次，签到不自动开考。

异常：定位、相机或供应商异常可由有权限的现场人员人工核验并留痕；未签到不能新开考，但不影响查看历史。398元上午缺席培训、下午签到不代表补上培训，仍须按规则参加培训或改期。已有进行中的考试优先按原题单和截止时间恢复，不重签、不重扣次数；跨天参加新考试须有新日期有效预约并重新签到。

### UC-AP-05 企业部分退款

1. 企业联系人在订单中选择不再参加且服务未使用的成员；
2. 提交退款原因；
3. 系统核对所选成员的服务使用情况、已有退款申请及可退金额，接收有效申请时同时暂停对应服务；不能新预约、改期、确认参加培训或新开考；
4. 运营审核时重新核对培训、开考、原订单及可退金额；
5. 审核拒绝则仅解除本次退款造成的暂停；审核通过则按规则取消未开始预约，显示“待人工退款”并指定办理人；
6. 工作人员在微信商户平台或银行核实并办理，同一笔原付款下多人退款可以合并，保留每名成员金额；结果不明时人工核实原退款，不重复退钱；
7. 运营核实实际成功凭据，录入金额、成员、渠道、时间和单号，系统更新对应成员退款结果并终止其本轮资格；失败或处理中如实登记，原申请继续跟踪，不自动调用退款接口；
8. 其他成员订单、预约和资格不受影响。

禁止将退款成员替换成其他员工；新增员工必须重新报名和付款。

### UC-AP-06 凭剩余次数预约下次考试

1. 398元已参加培训或98元学员结束当天本次考试，决定另一天使用剩余次数；
2. 本人在学员端点击“预约下次考试”，选择未来单独考试日期和时段；
3. 服务端确认当前没有进行中的考试，原服务资格有效且有剩余次数、目标日期有名额；398元还须已有本轮培训参加确认，98元无需该确认；
4. 新增关联原服务资格轮次的考试预约，占目标场次一个名额，不创建新的收费订单、不扣考试次数；
5. 原预约、签到、培训参加及考试记录保留；新日期到场后重新签到；
6. 明确点击开始考试并成功开考时，才继续消耗本轮下一次机会；当天继续考试仍复用本次预约和签到。

异常：资格冻结／已退款、次数用尽或目标日期满额时不创建预约；存在进行中考试时先按原规则完成或超时结束，不能用另约取消当前考试。重复提交不得重复占号，预约失败不改变剩余次数和历史记录。

### UC-AP-07 核实异常收款并完成处理

1. 系统发现付款结果未确认、重复收款或金额不符，或财务发现银行收款无法对应订单、原登记有误；
2. 保存已知收款和原处理记录；微信订单先由系统查询，暂时无法确认或需要人工处理的显示在财务待处理列表；
3. 财务核对微信／银行记录、原订单及已有资格，按第4.6.1节决定补记付款并开通资格、等待补足／查明归属、退回款项或更正错误登记；
4. 处理过程中记录负责人、原因和下一步动作，不重复记收入、开通资格或退款；
5. 收款归属、订单金额与资格均核对正确，或应退款已实际退回后，才把异常标为处理完毕。

异常：查不到付款结果不能直接视为没付款；申请退款不等于已经退回；误登记不能靠删记录消除；退多收款不能取消正常订单资格。

## 7. 业务事实与状态边界

### 7.1 分别记录的业务事实

| 事实 | 说明 |
| --- | --- |
| 订单与付款 | 提交时固定购买方、成员、价格、服务内容、试卷、承诺次数和退费条款；另记实付、付款渠道及到账状态，到账只激活原订单承诺 |
| 服务资格 | 某名学员因本人或单位付款获得的培训／考试权益及轮次 |
| 预约 | 学员在哪一天、哪个展示时段、参加哪类服务 |
| 签到 | 学员在预约日是否通过现场位置和本人核验 |
| 培训 | 是否实际参加或完成培训；签到本身不等于完成 |
| 考试 | 每次开考、题单、次数、答案、成绩和超时事实 |
| 退款 | 申请、审核、实际退款和失败原因 |

### 7.2 关键状态原则

- “已付款”不等于“已预约”；
- “提交订单固定承诺”不等于“已付款或已激活资格”；后台改价、改次数或延迟确认到账不改写已提交订单的购买承诺；
- “已预约”不等于“已签到”；
- “已签到”不等于“已培训”或“已开考”；
- 398元“已付款＋已预约＋已签到”仍不能代替本轮培训参加确认；98元单独考试不增加该套餐培训条件；
- “申请退款”不等于“已退款”；
- “改期”不等于“退款”；
- “预约下次考试”不等于改写已参加的预约，也不等于重新购买或重置考试次数；
- “考试失败”不自动生成新考试，学员明确再次开始才抽题和计次；
- 学员改期、退款或场次停止接受新预约不删除历史预约、签到或考试记录；停止接约不等于取消已有预约。

### 7.3 预约状态建议

```text
已预约
  ├─ 未签到 → 改期／申请退款
  ├─ 已签到但服务未开始 → 改期（旧日期名额不回补）
  ├─ 培训已参加、考试未开始 → 仅考试改期，不退款
  ├─ 考试进行中 → 按考试恢复、提交或超时规则处理
  └─ 本次已参加并结束 → 保留历史；有剩余考试次数可新增未来考试预约
```

状态名称在后续数据库与API设计中统一，本文不预先固定枚举字面量。

## 8. 权限、安全与隐私要求

1. 机构、企业和学员三类数据范围由服务端强制校验，不能只依赖前端菜单隐藏；
2. 企业账号只能读取本企业成员、订单和预约，不得读取题目答案、其他企业或学员私有数据；
3. 学员个人接口只按当前登录本人返回预约、资格、订单和考试记录；
4. 企业名单、手机号、身份证号、付款凭据、正脸照片和精确位置按敏感数据处理；
5. 身份证号沿用AES-256-GCM加密与HMAC查重，不在预约表重复保存明文；
6. 签到正脸只用于本次人证比对，保存范围和期限遵循最小化原则；
7. 高德Web安全密钥、支付密钥、数据库和JWT密钥只经运行环境注入，不写入仓库；
8. 系统必须核验微信付款通知的签名，确认通知确实来自微信，再核对收款商户、订单、金额和付款结果；同一通知收到多次只处理一次，不能多记一笔钱或多开通资格；
9. 订单、到账确认、退款审批、批量预约、人工签到和地点修改必须留审计；
10. 企业Excel／TXT导入限制类型、大小、行数和公式风险，错误导出不得泄露其他批次数据。

## 10. 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 个人未付款直接预约 | 服务端拒绝，不占名额 |
| 企业未确认到账批量预约 | 服务端拒绝，不生成成员预约 |
| 个人提交398元、3次考试的订单后，后台改为其他价格或1次考试，支付回调稍后到达 | 按原订单金额核对并激活原3次承诺；订单详情、资格和首次开考均不采用变更后的价格或次数 |
| 企业提交订单后，服务内容、成员资料或退费条款配置变化，财务隔天确认转账 | 以原订单固定的购买成员、人数、价格、服务内容、承诺次数和退费条款为准，到账只激活原成员资格，不重算或替换购买承诺 |
| 下单确认页展示后、正式提交前报价或权益发生变化 | 提示购买方重新确认，不静默生成与其确认内容不同的订单 |
| 未付款订单过期后继续购买 | 展示并确认当前报价及权益，创建新订单；旧订单和快照保留，不自动改价或沿用失效报价 |
| 已付款但微信回调或人工确认延迟 | 延迟确认不改变原订单承诺，不仅凭确认时间较晚认定订单未付款过期或要求再次购买 |
| 微信确认用户付款成功，但钱尚未结算到机构银行卡 | 本系统按已付款开通原订单资格，不等待银行结算；提现或结算异常不自动改成用户未付款或已退款 |
| 企业PC或个人H5提交退款，后台审核通过 | 显示待人工退款并指定办理人，本系统不调用微信退款接口、不自动标记成功 |
| 工作人员已人工退款，运营准备登记成功 | 核对原付款、成员、金额及成功凭据后录入；只结束对应成员的本轮资格，保留办理人与记录 |
| 微信已扣款，系统未收到付款通知或保存时出错 | 系统查询原微信订单，确认后补记收款并开通一次资格；重复通知或再次查询不多记收入、不多给次数 |
| 暂时无法查清微信付款结果 | 显示“正在核实付款，请勿重复付款”，保留待核对记录供财务处理，不自动另建付款订单或断定未付款 |
| 本地未付款订单已关闭，后来发现足额付款且原服务仍可提供 | 财务核对没有取消／退款申请、重复付款等冲突后，按原订单开通一次资格，不使用新价格或新次数 |
| 已关闭订单收款，但购买方已取消／申请退款或原服务无法提供 | 保存收款并进入退款处理，不自动重新开通已取消或已退款的资格；实际退回前保持待处理 |
| 企业对同一订单既转账又扫码付款 | 两笔真实收款分别保留，资格只开通一次；多收款实际退回后才结束处理，正常资格不受影响 |
| 两名财务人员同时把同一银行收款登记到不同订单 | 只允许登记到一个订单，另一操作提示该款已被使用；不会给两个订单都开通资格 |
| 企业转账少于应付金额 | 显示已收与差额，补足前不标记已付清、不开通部分成员；补款核对后一次开通整单资格，放弃购买则办理退回已收款 |
| 收到超出应付金额的款项或无法确认付款方的款项 | 多收部分列为待退，正常足额订单只开通一次；不明款项保留待核对，查明前不用于任意同金额订单 |
| 误确认没有到账的订单，学员已经考过一次 | 保留更正记录，暂停尚未使用的培训和剩余考试机会，不凭虚假收款记录退款；已开始考试正常结束，历史记录不删除 |
| 98元订单先收50元并退款，之后收到48元 | 当前仅按48元计算可用收款，不能因历史共收过98元而开通资格；正在退回的金额也不计入可用付款 |
| 核实或更正收款时，学员已经申请服务退款 | 保留服务退款造成的暂停；查到付款成功不自动恢复预约或开考，仍按服务退款规则处理 |
| 原订单已有正确足额付款，财务只纠正额外登记或退回多收款 | 原订单资格继续有效，不暂停预约、培训和考试，不减少次数 |
| 退款请求暂时没有结果或重复提交异常处理 | 核对原收退款记录，不另退一次、不重复记账；未核实完成的异常留在待处理列表 |
| 企业同批60人预约同一天 | 容量足够时生成60条个人预约；员工登录个人学员端可分别查看 |
| 企业本次提交60人，但仅余59个名额或其中一人资格不符 | 本次60人全部失败并提示原因，不产生部分预约或占位；此前已成功的其他批次不受影响 |
| 企业批量预约保存过程中失败 | 本次所有成员预约、398元关联培训／考试记录及名额变更整体撤销，不遗留部分成功 |
| 企业主动把同一订单成员分两次预约不同日期 | 每次提交分别保证全部成功或全部失败；第二次失败不影响第一次已成功的预约 |
| 企业一单混合398元和98元 | 拒绝，提示分别下单 |
| 企业尝试把甲换成乙 | 拒绝；甲只能由企业申请退款，乙重新报名付款 |
| 企业导入新成员 | 按企业默认来源创建；关联既有学员时保留其来源，不因购买398元或98元改难度 |
| 同一日期并发预约最后名额 | 最终有效预约数不超过当天总名额 |
| 培训加考试日配置整天60个号 | 最多接收60人；同一人的培训、考试两条关联预约只占一个套餐名额，由现场人员安排当天培训与考试 |
| 单独考试日配置120个号及自定义时段 | 可配置3个、4个、5个、6个或按小时划分的时段；所有时段共享120个号，不自动均分或按时段复制总额；人数与时段数量均可由运营调整 |
| 运营修改或删除尚无人预约的日期／时段 | 允许操作；其他日期／时段及其预约不受影响 |
| 运营修改或删除已有预约的日期／时段 | 服务端拒绝，原日期、时段及预约保持不变；不能绕过界面限制直接修改或删除 |
| 运营对已有预约的日期／时段停止接约 | 新预约被拒绝；已有预约仍有效且名额不回补，学员可按原安排签到、培训和考试，不自动退款或迁移预约 |
| 当天有人签到后离开并改期 | 允许选择未来日期；原日期名额不回补，目标日期正常占用 |
| 学员改期时目标日期已满或保存失败 | 原预约、原名额及原签到适用关系不变，目标日期不留本次占位，不要求学员重新抢原名额 |
| 398元未参加服务的关联预约改期时一条记录保存失败 | 培训和绑定考试均保留原安排，整体失败；不得出现培训在新日期、考试仍在旧日期 |
| 学员使用企业后台账号登录H5 | 不支持；H5只接受个人手机号验证码登录 |
| 学员查看企业代约记录 | 使用本人手机号登录后在“我的预约”看到本人记录，不显示同批其他成员 |
| 本人扫码或打开小程序，只进入课程／考试Tab或只定位成功 | 保持未签到；不凭二维码、页面进入或定位单项结果认定到场 |
| 预约当天忘记点击签到，稍后到场再点 | 当天仍可办理，无提前／迟到窗口；核对有效预约、付款、资格、定位及照片，保存成功才记签到，不跨天补记 |
| 未签到时点击开始考试 | 提示“请先完成签到”，提供“去签到”；暂不办理则不能新开考，不抽题、不计时、不扣次数 |
| 98元学员完成签到 | 可进入考试须知，但仍须本人明确开始并通过全部开考检查；签到本身不自动开考 |
| 398元学员完成签到但尚无本轮培训参加确认 | 提示“请先参加培训并由工作人员确认”，暂不能新开考，不扣次数；进入课程Tab或视频进度不能替代确认 |
| 已有进行中考试，再次从考试入口进入 | 优先恢复原考试，沿原截止时间继续，不重新签到、不重复扣次或换题 |
| 非预约日或超出地点范围签到 | 拒绝签到；不生成开考资格，不消耗考试次数 |
| 398元学员上午缺席培训、下午到场并签到后尝试开考 | 服务端因缺少本轮培训参加确认拒绝，不抽题、不计次；下午签到不等于补上培训，学员可按规则改约未来培训考试 |
| 398元学员已有本轮现场培训参加确认 | 其余开考条件满足时允许考试；当天重考或跨天用剩余次数复用该培训事实，不重复培训 |
| 398元未培训学员尝试直接预约单独考试场 | 拒绝以本轮资格绕过培训；只可按未参加服务规则改约培训加考试场 |
| 98元学员没有398元套餐培训记录 | 其余条件满足时可开考；今日考一次后可凭剩余资格预约未来单独考试场，不要求补培训 |
| 当天培训后第一次考试失败 | 次数未用尽时可立即再次考试，不需重签或重约、不重复占号；每次成功新开考才计次 |
| 398元已培训、当天只用一次考试机会 | 剩余次数保留，本人可新增未来单独考试预约；不收费、不重置次数、不重复培训，原记录保留 |
| 98元学员跨天使用剩余次数 | 凭原资格新增未来单独考试预约，占目标场次一个名额；新日期重新签到，开考后继续本轮计次 |
| 跨天预约下次考试时目标日期已满或重复提交 | 满额不创建预约；重复提交不重复占号；不消耗次数、不修改原预约或成绩 |
| 考试进行中尝试另约未来日期 | 不允许用另约取消本次考试；须先交卷或按原截止时间超时结束，已用次数不返还 |
| 过去预约日未到场、未签到 | 本人可改到未来可约日期，缺席本身不消耗考试次数；不新增催办或黑名单 |
| 最后一次考试进行中 | 即使剩余新开考次数为0，仍可继续当前考试；结束后才显示用尽 |
| 培训已参加但考试未参加 | 不退款；允许把考试改到单独考试场 |
| 仅签到但尚未确认参加培训 | 签到不自动消耗培训资格；可按未开始服务规则改期或申请退款审核 |
| 企业部分未使用成员退款 | 只处理选定成员，其他订单成员和预约不受影响 |
| 退款申请先被接收，工作人员随后确认参加培训或学员尝试预约／改期／新开考 | 全部拒绝新的服务操作；前端和服务端都不能绕过暂停，退款处理期间不提供新的培训或考试 |
| 退款申请与培训参加确认／新开考同时提交 | 只能有一个结果成立：服务先确认使用则不受理普通未使用退款；退款申请先接收则拒绝新服务，不得既提供服务又退费 |
| 同一企业成员被重复选入两笔未结束的服务退款申请 | 后一请求返回已有申请或提示该成员正在退款，不新增重复申请或重复退钱 |
| 同一订单或原付款同时提交多笔退款 | 成员可退金额、已退金额和所有未处理完金额一起检查；总额不足时拒绝新增退款，不因不同工作人员或不同页面重复占用同一笔钱 |
| 人工退款后结果暂时未知 | 保留原办理记录和金额占用，由办理人查询微信商户平台或银行；不重复退钱、不登记成功，不提前释放可退金额 |
| 同一原付款下3名成员一并获准退费 | 可合并为一笔微信退款；每名成员的应退金额和结果可追溯，只有这3名成员结束资格，其他成员不受影响 |
| 人工办理时微信商户平台提示退款次数、期限或账户限制 | 运营登记原因并交财务继续处理；原申请和暂停保留，不冒充退款成功，不直接取消符合规则的申请或强制重新下单 |
| 微信原退款未确认停止出款时，工作人员尝试线下再退一次 | 拒绝重复出款；核实原渠道不会继续退钱后，才可按例外流程登记线下退回及凭据 |
| 两名工作人员尝试同时办理同一退款申请 | 该申请只指定一个当前办理人；另一人不得再退一次，交接须核实原办理记录和实际出款情况 |
| 审核拒绝退款，但资格仍因收款错误暂停 | 仅解除退款造成的暂停，收款问题未核实前不能恢复新服务 |
| 微信退款或对公退款失败 | 不伪造退款成功；保持处理中／失败状态并允许运营重试或确认 |
| 重新购买同一考试服务 | 建立新服务轮次并从本轮第1次计算，旧订单、次数和成绩保持不变 |
| 重复支付／签到／退款请求 | 返回已有结果，不重复收款、签到或退款 |
| 定位或照片供应商异常 | 现场人员按权限人工核验并记录原因，不能直接篡改考试结果 |
| 签到隐私数据到期 | 原始正脸不留存；精确坐标不入库；距离／精度摘要到期清理，签到结论和审计保留 |
