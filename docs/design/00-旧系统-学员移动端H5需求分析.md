## 1. 引言

### 1.1 移动端建设背景

当前 H5 是一个以手机浏览器为主要载体的在线学习平台，采用登录后四底部导航的结构：

- 首页：轮播图、推荐课程和课程入口；
- 课程：课程列表、课程目录、视频课时和学习进度；
- 考试：试卷列表、倒计时答题、答题卡、提交和考试结果；
- 我的：考试记录、错题本、个人资料、修改密码、关于我们、服务条款和退出登录。

页面观察与静态资源共同确认的信息架构如下；标为“静态/待验证”的环节尚未完成运行验收：

    登录
      └─ 首页
          ├─ 推荐课程 → 课程详情 / 课时目录
          ├─ 更多 / 底部课程 → 课程列表 → 课程详情 / 课时目录
          │    └─ 视频学习 / 进度上报 / 完成（静态，播放闭环待验证）
          ├─ 考试中心
          │    └─ 试卷 → 答题 / 答题卡 / 草稿恢复 / 提交前确认
          │         └─ 新交卷或超时处理 → 新结果（静态，闭环待验证）
          │              └─ 查看答案解析
          └─ 我的
               ├─ 考试记录 → 答案解析；已有结果也已单独读取
               ├─ 我的错题本（列表内阅读，不跳入解析页）
               ├─ 个人资料
               ├─ 修改密码
               └─ 关于我们 → 服务条款

平台当前以“课程视频 + 在线试卷”为实际产品形态。它与 01 册中“制度文件 + 在线阅读 + 学习有效性判定”的模型有相似的学习/考试闭环，但课件类型、学习计时方式、考试资格和数据实体并不完全相同，重构时不能直接把两者当成同一实现。

### 1.2 移动端建设目标

1. 在手机宽度下稳定呈现登录页及首页、课程、考试、个人中心四个主导航页面。
2. 课程内容可按章节和课时浏览；有视频的课时支持播放、断点续播、进度上报和完成提示。
3. 若后续另立移动端项目，考试只复用单选、多选、判断三类客观题契约；题干和选项可显示普通图文，答题卡、服务端倒计时和提交结果需可追溯。图片答案与人工批改不纳入该候选范围。
4. 结果、考试记录和错题本形成复习闭环。
5. 弱网、刷新、误关闭页面时，已保存的学习进度和答题草稿不被无提示地丢弃。
6. 重构时把当前样例中的动态数据、空态、无视频课时、接口异常和会话失效都纳入验收。
7. 学员通过手机验证码登录或自动注册；兼容后台导入内部学员与注册后由管理员将外部改为内部，实名认证和来源标识分别维护，PC 登录不受影响。

### 1.3 文档范围与读者

**本册包含**：

- 学员端页面信息架构、路由、底部导航和页面状态；

- 首页和课程入口；

- 考试列表、答题、答题卡、倒计时、提交、结果和答案解析；
- 考试记录、错题本；
- 个人资料、内部/外部身份展示、关于我们、服务条款和退出登录；旧站密码能力保留为观察证据，不作为新 H5 的必要入口；

### 1.4 优先级定义

| 优先级 | 含义 |
|---|---|
| P0 | 学员端主链路必须具备：登录 → 课程/学习 → 考试 → 结果/复习 |
| P1 | 对完整使用体验和运营闭环重要，首个可用版本应交付 |
| P2 | 当前页面未确认或可后续扩展，不能冒充当前站点已有功能 |

2026-10-22 的登录与身份增量属于 P0：验码成功后可以建立账号，实名未通过或培训类别未配置时不能发起正式考试；这不新增课程学习完成门槛。

## 2. 学员角色与移动端画像

### 2.1 employee / student（普通学员）

| 项目 | 描述 |
|---|---|
| 身份 | 观察：当前演示账号为平台分配账号。目标：后台导入的内部学员，或手机验码后自动注册的外部学员；管理员可将外部调整为内部 |
| 目标 | 查看推荐课程，完成视频学习，参加可用试卷，查看考试结果和错题 |
| 数据范围 | 只能查看自己的课程进度、考试记录、答案、错题和个人资料 |
| 可变更数据 | 可修改普通个人资料和头像、提交实名认证；认证通过的实名信息及登录手机号不允许通过普通资料接口直接修改；考试提交、视频学习进度会产生业务记录 |
| 来源与实名 | 来源是内部 institution / 外部 external，由后台维护；实名认证独立维护，导入内部名单不等于实名认证通过，自助注册也不取得后台权限 |
| 不可执行 | 不能进入管理端，不能创建/发布课程或试卷，不能修改题库和他人成绩 |
| 使用场景 | 手机浏览器碎片化学习、移动端答题、弱网或切后台后继续使用 |

### 2.2 典型使用场景

1. 学员首次手机验码登录，已有手机号关联原账号，没有账号则自动注册为外部学员；未实名时引导认证，首页可展示当前身份及待办。
2. 学员从推荐课程直接进入详情，或从首页“更多”及底部“课程”进入列表，查看“未学习 / 已完成 X/Y / 已完成”和进度条。
3. 学员打开课程详情，查看默认展开的章节及自动选中的可播放课时；可手动切换课时，再次进入时从服务端断点继续。课时目录播放百分比与列表完成课时数分别展示。
4. 学员实名认证通过且培训类别齐备后进入考试；服务端按后台确认的内部/外部来源选择难度，逐题作答并通过答题卡跳题。
5. 学员退出答题页或发生刷新后，恢复属于本人当前作答的草稿；选择重新开始只清空本次答题内容，不延长原考试期限。
6. 学员提交试卷或时间到，查看分数、正确率、答对/错题数和答案解析。
7. 学员从“考试记录”或“我的错题本”复习。
8. 学员在个人资料中更新头像、工种、性别和生日，查看实名、登录手机号、培训类别及内部/外部来源；来源调整由管理员完成，实名及手机号不通过普通资料保存修改。

### 2.3 设备、网络与浏览器环境

- 本次观察使用约 390×844 的手机视口模拟；四个主导航页包含约 50px 的固定底栏，课程详情、答题、结果等子页面没有四底栏。
- 目标应覆盖 320–430 CSS px 宽度的主流手机，不能出现横向滚动或按钮被底部导航遮挡。
- 当前资源声明了移动视口、可内联播放的视频和中文 H5 页面；重构应验证 iOS Safari、Android Chrome 以及常见微信内置浏览器。
- 课程视频依赖网络；考试倒计时、答题草稿和服务端保存状态不能依赖客户端时钟单独成立。
- 当前演示账号存在并发登录后令牌失效现象：两个浏览会话交替登录时，前一次会话出现接口 200 后续请求 401“会话已过期”。这证明必须处理会话失效，但不能据此断言产品要求只能单点登录。

### 4.9 手机验证码、实名认证与内部/外部学员（2026-10-22 增量）

本节是用户确认的新目标，不是旧站已有功能或本仓库已交付的证明。仅改变学员 H5 的认证入口；PC 管理端账号密码登录保持不变。

**已确认的两条来源规则**：

1. 后台按学员管理模板导入本机构在培名单，标记为内部学员（`source=institution`）。不要求学员再次申请内部身份。
2. 未建号者通过 H5 手机验码后自动注册，默认外部学员（`source=external`）；管理员可以在后台将其改为内部。不增加身份申请、待审批或学员自选内部身份的流程。

来源只在创建、导入确认或管理员调整时变化。再次登录、资料保存、实名认证、会话刷新均不得把已有内部学员重置为外部。

#### 4.9.1 账号、来源、实名与类别分别维护

| 维度 | 含义与维护方 | 对考试的影响 |
|---|---|---|
| 学员 ID / 登录手机号 | ID 是历史记录归属；同一规范化登录手机号唯一关联同一学员，手机号所有权经短信验证 | 导入、短信登录、注册复用同一 ID，保留学习与考试历史 |
| 学员来源 `source` | 内部 `institution` / 外部 `external`；由后台名单导入及有权限的管理员维护 | 新培训随机考试内部为初级 `easy`，外部为高级 `hard`；不等于管理权限 |
| 实名状态 | 未认证、处理中、已通过、未通过；由后端可信核验结果维护 | 未通过可登录、查看认证状态，但不能新开正式考试；导入不等于认证通过 |
| 培训类别 `category_id` | 由后台现有学员管理业务配置；与来源分开，不按手机号猜工种 | 类别决定可用题库范围；缺失时引导联系管理员，不自动填默认类别 |

```text
后台导入在培名单 ── 按手机号预检 ── 新建或复用原学员 ── 内部
                                                       │
H5 手机验码 ── 已有学员 ── 登录原账号，保留当前来源 ────┤
            └─ 没有学员 ── 自动注册为外部 ──────────────┤
                              └─ 管理员可调整为内部 ───┘
                                                       ↓
                                  实名通过 + 类别齐备 + 考试资格通过
                                                       ↓
                                 首次开考冻结来源、类别、难度与规则
                                  （同场补考沿用，不追改历史题单）
```

“实名通过”和“内部身份”没有先后依赖：外部学员可先完成实名，内部学员也可能尚未实名。手机号只是登录与账号关联依据，不凭手机号或导入姓名认定实名。

#### 4.9.3 复用 gooodwork 短信能力的边界

复用 `/Users/caogj/Documents/emodor/gooodwork/server` 已有网易云信短信发送/验码能力，不照搬该项目的自动注册角色和会话模型。来源项目的 `/api/auth/sms-code`、`/api/auth/sms-verify` 是参考链路，不直接作为 RuleExam 已存在的接口。

短信配置沿用含义：`SMS_PROVIDER`、`YUNXIN_SMS_APP_KEY`、`YUNXIN_SMS_APP_SECRET`、`YUNXIN_SMS_LOGIN_CODE_TEMPLATE_ID`、`YUNXIN_SMS_BASE_URL`、`YUNXIN_SMS_TIMEOUT_SECONDS`，重发、有效期、验码次数与日限额由后端配置控制。业务所称的短信“key”必须区分供应商AppKey/AppSecret、模板ID和一次性challengeId；前两类只在后端通过环境变量注入，challengeId可以发给客户端但不是登录令牌。RuleExam使用独立Redis前缀（建议`ruleexam:sms_auth:`），不得与gooodwork共享挑战或限流键。

不在仓库、本文或H5包中写入真实密钥，不复制来源项目整份`.env`。本节只确认可复用的能力与配置名称，尚不代表短信已迁移、真实收码或实名认证已经通过。
