## 2 本轮已确认的决定

### D01 培训与考试分开预约 已经 D10 和 D19 澄清

- 状态：历史决定，当前以 D19 的“培训预约自动绑定考试预约、考试可单独改期”为准。
- 确认日期：2026-10-28。
- 用户原话：“培训和考试分别选择时间、分别预约”。
- 适用范围：398 元培训加考试套餐。
- 原需求含义：培训和考试各自选择时间、分别预约。后续 D08 明确要求398元套餐在同一天完成，不能再按任意两天设计。
- 变化原因：用户补充现场运营安排，培训加考试集中在指定工作日，当天完成两项。
- 当前处理：按 D19，初次预约培训时自动绑定考试预约；培训和考试分别记录、关联展示，培训后可单独改考试时间。

### D02 培训与考试独立 不以完成培训为考试条件 已被D49替代

- 状态：历史决定；398元不以培训为开考前提的口径已于2026-10-29被D49替代，以下原话及含义仅保留决策过程。
- 确认日期：2026-10-28。
- 用户原话：“两者独立，不以培训完成作为考试条件”。
- 需求含义：考试预约不需要等待培训完成；考试也不因为尚未参加或完成套餐内培训而被阻止。不规定先培训后考试的顺序。
- 取代的设想：必须完成培训后才能预约或参加套餐内考试。
- 边界：这不是取消实名、缴费、预约时间、现场签到等其他条件的授权；这些条件分别讨论。也不据此直接修改现有其他试卷的考前学习配置。
- 后续约束：D08、D10初次按当天安排；D19明确培训后考试可单独改期。D49明确398元先实际参加本轮培训、经现场人员确认后才能开考；98元无套餐培训门槛，不再把先后顺序列为待定。
- 重考衔接：D46与D49已明确398元本轮培训确认供当天重考及跨天剩余机会复用，不要求每次重新培训；原会议中“不通过后重新学习再考”的片段不作为当前规则。

### D04 企业联系人自行办理团队报名和初次预约 经D40确认继续有效

- 状态：已确认；D39的相反理解已经D40纠正。
- 确认日期：2026-10-28。
- 用户原话：“企业联系人自己登录上传名单、安排预约”。
- 当前含义：需要面向企业联系人的登录与操作入口，支持上传成员名单、办理报名、统一付款，并为同批员工批量安排初次培训和考试预约；员工只负责预约成功后的个别改期。
- 取代的设想：首期只由机构工作人员接收名单并代办，企业自助后置。
- 设计边界：企业联系人仅能处理获授权企业的成员、报名、付款和初次预约，不获得机构后台的全量学员、财务或题库权限。团队付款已由后续D05确认为企业统一付款。

### D05 团队报名由企业统一付款

- 状态：已确认。
- 确认日期：2026-10-28。
- 用户原话：“肯定是也需要支持企业统一付款，不考虑员工各自付款。”

- 一名成员同一份服务只保留一个未结束申请：重复提交或重复选入其他退款批次，返回已有申请进度；不同成员可以分别申请，不影响正常成员。
- 金额不能多退：本次金额与其他已退、待审核、待退款、处理中、结果不明金额合计，不能超过该成员、订单按规则可退的实际收款，每笔原付款的退款总额也不能超过实收。合并退款与成员明细只算一次；多收款退回和服务退款共同计算，不能两边重复退。
- 结果不明先核实：按后续D54，由办理人在微信商户平台或银行核实原退款，不能重复退钱；本系统保留金额占用，不自动查询退款或占用微信渠道次数。整笔申请被驳回或终止且确认不会再出款后，才释放尚未退回的金额额度；仍在人工办理的申请继续保留金额占用。
- 暂停与恢复：审核拒绝只解除本次退款造成的暂停，不解除收款错误等其他暂停；审核通过后的预约与名额继续按原规则处理。失败不自动恢复服务，实际退款完成后只终止对应成员的本轮资格。
- 微信限制依据：2026-10-29核对[微信普通商户退款规则](https://pay.wechatpay.cn/doc/v3/merchant/4012791903)，一笔微信付款最多50次部分退款，接口申请期限为支付成功后365天，多笔部分退款申请间隔至少1分钟；次数按原付款计算，不按企业人数计算。
- 首期办理方式（按D54）：全部退款由工作人员在微信商户平台或银行办理，运营登记实际结果。同一原付款的多个已批准成员可以人工合并退款，逐成员保存金额；不同付款分开办理，不把受理成功当成钱已退回。
- 渠道检查（按D54）：办理人在商户平台核实实际已退、待退、期限和可办理方式；不以系统本地登记次数冒充微信全部记录，不建设自动占用最后一次退款机会的流程。渠道受限时记录原因并交财务继续处理，保留原申请及成员暂停，不假报成功。
- 人工核实：财务核实原付款方、尚未退回的钱，并确认没有仍会出款的原退款后，再采用经核实的其他方式办理，保存收款方确认、账户、凭据和办理人。结果未知不得改走另一渠道再退一次，企业退款不得随意转给员工。
- 权利与渠道分开：50次、365天不作为学员服务或退款权利的自动到期条件；符合退款规则的申请继续受理，渠道不能执行时改由财务办理，不要求重新付费。退回多收款仍按D52保留正常服务资格。
- 文档落点：正式需求第4.8.1／4.8.2节、第4.9节、FR-PAY-05／07／13／14、UC-AP-05及验收场景。完整微信结算对账已由D54排除出首期，不再列为必须补充的上线条件；退款法律例外仍另行讨论。

### D54 微信确认付款即记已付款 退款人工办理并由运营登记结果

- 确认日期：2026-10-29。

- 人工结果登记：记录成员、金额、渠道、时间、退款单号或银行凭据、办理人和录入人；审核通过不等于退完，运营不得无凭据勾选成功。处理中或失败保持待处理；结果录错保存更正记录，不删除历史。
- 系统保留的保护：退款期间暂停新预约、改期、培训参加确认和新开考；同一成员不重复申请，金额不超退，合并退款逐成员留明细。每笔申请只指定一个当前办理人，交接先核实是否已出款；人工结果不明时先查原平台或银行，不能再退一次。
- 首期不接自动退款：不调用退款申请、退款查询、退款通知接口，不自动出款或自动占用微信剩余退款次数。微信官方明确可选择在商户平台人工退款，见[接入指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791870)。
- 微信渠道规则仍需遵守：官方[退款产品说明](https://pay.wechatpay.cn/doc/v3/merchant/4013071001)同时列明人工退款方式、365天及最多50次部分退款；人工办理不能被解释为不受微信规则限制。办理人结合商户平台实际信息核实，受限时记录并交财务处理，不自动否决本来符合服务退款规则的申请。
- 收支查询范围：FR-PAY-06维持P1，仅汇总本系统收款、人工退款及未处理事项；付款记录、退款申请／审核／结果登记属于P0基本流程。撤回把完整银行结算核对列为首期上线必备条件的审查建议。
- 对用户追问的核验：没有依据声称微信向银行结算失败会自动退给付款用户。官方[提现退票说明](https://pay.wechatpay.cn/doc/v3/partner/4012476674)描述的是退回发起提现的商户账户，该说明属于收付通提现场景，不能拿它冒充本项目具体商户故障的核验结果；本项目按付款结果办理，具体结算异常由商户向微信／银行核实。
- 文档落点：正式需求第1.2／1.4节、管理端菜单、第4.6／4.8节、FR-PAY-04／06／14、UC-AP-05及验收场景。沿用用户认可的简短规则口吻，不引入完整财务系统。

企业联系人自己登录PC，完成成员导入、报名、统一付款和批量初次预约；可以把同批员工统一约到相同日期和时段，也可以分批安排。D39中“企业不做初次预约”的理解已经作废。

企业入口只处理获授权企业的成员、报名、订单、付款和初次预约，不能把机构管理员账号直接发给企业。首期使用PC、机构后台开通账号继续按D12、D13；是否共用站点尚待设计，新增企业使用角色不自动等于新增一套独立应用。

团队付款按 D05，由企业统一办理，不提供员工各自付款。企业自助不意味着建设完整企业人事或多租户平台。机构工作人员是否保留协助代办功能，另行讨论。

### S04 预约 支付 到场和考试分别记录

缴费、预约、到场和考试结果分别记录。398元按D19初次预约培训时自动绑定当天考试，培训和考试分别保留；开考顺序按最新D49，必须先实际参加本轮培训并经现场确认。398元包含1次培训，98元不含培训；两者考试次数按D22读取关联试卷配置，当前默认3次。

```text
398 元套餐 → 付款 → 培训预约 → 自动绑定当天考试预约（有名额上限）
    └── 实际参加本轮培训并由现场人员确认
          └── 使用关联考试预约 → 当天考试，或培训后单独改考试时间
                └── 配置次数用尽且未通过 → 重新购买98元或398元套餐

    └── 现场考试 → 现有考试记录

缴费订单负责记录钱；预约记录负责安排时间；考试系统负责答题和成绩。
```

取消或改期不等于退款。D21已确认398元由300元培训费和98元考试费组成，但 D19仍规定参加培训后不退款、可改考试预约；费用可以分项展示，不等于允许分项退费。

### S05 失败记录与下一次考试同屏展示 旧备选 当前推荐见 S06

核对依据：[正在实施的随机考试设计](../../superpowers/specs/2026-10-28-shared-random-exam-design.md)第1、6、7、9节。仅阅读该设计及当前工作区状态，没有把文档状态等同于代码或运行验收完成。

已有设计约定：最多次数由试卷配置；成功开始考试才计次，超时未交卷也计次；进行中恢复不换题、不计新次数；学员明确再次开始才生成新记录并重新抽题；跨次允许重题；同一学员同一试卷首次开考冻结来源、发布版本与规则，撤回重发不重置次数；已及格也可在剩余次数内重考。

此前助手建议供比较；其中双记录展示已不作为当前推荐，其他考试与支付衔接问题仍保留：

1. **一项考试下显示多次记录**：PC仍只配置和发布一项随机考试，不因每次失败新增一张后台试卷。H5在同一考试下同时展示“第1次未通过—查看详情”和“第2次待考试—开始考试／去预约”。更多历史可进入全部考试记录。
2. **先出现入口 点击才抽题**：失败且仍有剩余次数时显示下一次待考入口，不在交卷后自动开始下一场，不提前计次或启动倒计时。点击开始并通过付款、预约、实名等检查后才抽题并保存。此方式与正在实施设计更一致；若坚持失败即预生成题目，需要另设计待开考状态，不能借用已开始考试记录。
3. **重新抽题不等于每道题都不重复**：原设计允许跨次重题。若需要增强差异，可优先抽此前未考过的题，不够时补抽旧题；这是新增建议，尚未确认。若要求跨次完全不重复，需要按题型、难度准备足够题量并明确缺题时怎么办，不能直接承诺一定全新。
4. **查看失败详情保持历史**：展示该次成绩、作答等历史信息，不允许重新提交或覆盖；是否显示完整答案解析继续沿用考试结果查看权限，不在本轮扩大。
5. **下一次入口与预约衔接**：按后续D24，当天未通过且有次数可以立即再考，不要求每次重考重新预约；跨天衔接已由D46明确为凭原资格新增考试预约，不改写历史预约。只保留一个当前待考／进行中入口，刷新和重复点击不生成多个考试。

支付融合还需裁决：

- 原建议为保存购买时承诺次数，避免后台改配置削减已购机会；冻结时点已由后续D51明确为提交订单时，到账只激活原承诺。首次开考仍冻结发布规则和题单，但本轮次数不得覆盖订单承诺。
- 建议重新购买产生新一轮付费考试机会并保留旧记录。但现行设计是同一学员同一试卷累计次数，仅新增支付订单不会解除原上限；必须补充购买与考试轮次的关联，不能通过修改旧次数或复制后台试卷绕过。
- 用户说按套餐区分本机构／外来，正在实施的考试设计按服务端学员来源冻结难度；重新购买98元后的来源、难度和历史归属需明确，不能在付款后直接覆盖旧记录。
- 原设计允许已通过仍继续考试；本轮只讨论失败后的入口，不自动推导为“通过后禁止重考”。

### S06 现有考试卡片显示次数 经考试须知后开考

- 状态：保留单卡片为当前推荐；进行中和次数用尽的具体文案已按 D23 确认；不代表界面已实现。
- 用户提供现有考试Tab截图，建议在时长、题数、满分这一行增加考试机会；每次使用后减少，进入考试须知后，点击开始考试才抽题。
- 展示：一项已发布考试继续对应一张卡片；待开考时显示“剩余N次”，答题中按 D23 显示“第N次考试，共M次”。次数来自试卷配置和本人记录，不写死3次，必要时换行。
- 流程：考试卡片 → 考试须知 → 明确点击开始考试 → 服务端检查条件、抽题并成功建立本次考试 → 使用次数加1、剩余次数减1。进入列表／须知、预约、刷新、开考失败不扣次数。
- 进行中：显示“第N次考试，共M次”和“继续答题”，恢复同一份题目和截止时间，不重抽、不再扣次数。最后一次也可继续当前考试，不以“剩余0次”替代当前考试信息。
- 考试结束：本次失败且仍有次数时，同一张卡片提供“再次考试”及“查看记录”；下一次仍先进入考试须知。次数用尽且无进行中考试时按 D23 显示“考试次数已用完”，保留记录查询。
- 当天重考：按 D24 允许马上再次考试，不额外插入重新预约步骤；通过须知主动开考，仍检查剩余次数并生成新的题单。
- 历史：每次考试各自保留题单、答案和成绩，从“查看记录”进入历史详情，不新增一张待考试卷卡，也不复制PC后台试卷。
- 筛选：不能把一次失败等同于整项考试彻底结束，导致有剩余机会却没有重考入口。已通过后是否继续重考暂沿用正在实施设计，不在此变更。
- 示例：上限3次，未开考显示剩余3次；首次开考显示第1次／共3次，后台剩余新开考机会为2；首次失败后显示剩余2次；第三次进行中显示第3次／共3次并可继续，第三次结束才显示考试次数已用完。
- 与 S05 的关系：用本方案替代双记录卡展示建议；不改变当前设计中“每次新开考随机抽题、进行中恢复不换题”的机制。是否减少跨次重题，以及重新购买如何恢复新一轮机会，继续单独讨论。

### S08 现场签到与本人核验方案 待选择

目标拆成三个问题，避免一个功能承担所有责任：账号表示谁登录；现场二维码表示此时拿到了现场凭证；本人核验表示当前操作人是否为实名本人。单独定位只能说明手机位置，不能解决代登录。

**方案A 简单人工版 当前首期推荐**

```text
工作人员开启本场签到并展示短时二维码
  → 学员扫码登录
  → 系统核对付款、预约、试卷、签到时间
  → 工作人员核对本人证件／实名信息并确认
  → 签到成功
  → 考试须知 → 学员点击开始 → 抽题
```

- 二维码对应已发布试卷和当前考试安排，但使用短时可验证参数，建议在现场屏幕刷新，避免永久静态码被长期转发；具体刷新时间待设计。
- 复用现有已实名事实，不要求每次重新上传身份证和完成整套实名认证。工作人员只看最少必要的脱敏信息，人工确认需记录操作人和时间。
- 不要求定位，避免室内漂移、授权失败和模拟定位导致正常学员被误拒；可以给少量无法刷脸的人员提供相同人工流程。
- 优点是链路短、成本低、身份确认清楚；代价是现场需要工作人员逐人确认。

**方案B 自动核验版 动态二维码加一次活体核身**

- 扫码后在当日第一次签到时做活体人脸核身，确认当前真人与已实名身份一致；通过后保存当日本场签到，连续考试不重复刷脸。
- 这比现有照片式实名认证更强。当前项目的腾讯 `ImageRecognitionV2` 使用现场正脸照片做身份比对，现有设计没有把它写成活体核验；若选本方案，需要新增腾讯H5／小程序活体流程和真实供应商验收。
- 人脸失败、设备不支持或本人不同意人脸时，必须提供工作人员人工核验的合理替代，不能让人脸成为唯一方式。
- 优点是减少人工、能较好防止借账号；代价是接入、费用、资质、隐私告知和异常处理明显增加。

**方案C 多因子版 动态二维码加活体加定位**

- 在方案B基础上增加机构坐标和50／100米范围判断，定位只作为现场风险信号；需要校验定位精度，不能只比较经纬度。
- 优点是能同时检查本人和手机位置；缺点是定位可被模拟、室内漂移明显，且位置和人脸都是敏感个人信息，会增加权限失败、误判和合规成本。
- 只有实际出现二维码实时转发、远程代签等风险后再考虑，不建议首期直接上。

**助手建议**：首期选A。如果现场人工核验压力确实过大，再升级为B；暂不做C。无论选哪套，扫码／核身／人工确认只完成签到，不扣考试次数、不抽题；学员仍在须知页点击开始后才生成题单。

**视频学习的边界**：已有视频有效学习时长可以证明线上学习进度，不能证明人在培训现场。若业务只要求完成线上培训，则无需额外培训签到；若必须证明参加现场培训，可复用本场一次人工／活体到场确认，不再建设独立复杂的培训签到系统。

**合规提醒**：人脸和精确位置属于敏感个人信息。采用人脸前需要明确必要性、显著告知、单独同意、最短保存、影响评估及替代方式；本讨论记录不替代正式合规评估。

### S09 定位加本人照片比对的首期链路 已按 D31 收敛

**当前项目核查结论**：现有实名认证已经实现“仅相机拍正脸＋身份证正反面OCR＋腾讯 `ImageRecognitionV2` 人证比对”。移动端正脸限定从相机获取；后端向腾讯发送OCR姓名、证件号和正脸图片，相似度低于70拒绝。当前分支定向构建和 `identity-verification.spec.ts` 30项测试通过。

但它是**单张照片人脸核身，不是活体检测**：接口只传 `IdCard/Name/ImageBase64`，没有动作、视频、数字口令或静默活体步骤。相机限定能阻止直接从相册选图，不能证明镜头前一定是真人。既有验收也明确真实腾讯OCR／FaceID、真实材料、微信和手机真机尚未执行，不能把测试Fake Provider通过当成现场核身已验收。

此前建议活体核身，用户因资质和复杂度选择 D31 的照片比对。当前首期链路调整为：

```text
已付款且已预约
  → 预约日期当天打开小程序考试入口
  → 获取本次最新定位
  → 服务端校验机构坐标、配置半径和定位精度
  → 当天首次到场签到时现场拍正脸
  → 后端读取既有实名资料做人证照片比对
  → 服务端记录本人＋预约日期＋培训地点的当天签到
  → 培训和当天全部考试复用该签到
  → 考试须知
  → 点击开始考试后才抽题、计次、下发题目
```

- 培训和当天连续考试沿用同一次有效签到，不重复定位和拍照；跨天改期后重新签到。
- 不需要二维码。试卷由预约和考试Tab确定，定位及照片人证比对承担现场与本人核验。
- 首期按 D31 接受照片比对不是活体检测的风险，产品文案只写“人证比对／身份核验”，不写“活体认证”或“确认真人”。异常时由工作人员人工核对。
- 复用已实名的加密姓名和证件号，不让学员每次重新上传身份证；现场签到只上传本次正脸照片。
- 定位建议只保存签到是否通过、机构、距离／精度的必要审计摘要；是否保存原始经纬度及期限需另作最小化设计。
- 照片核验不能作为唯一不可替代方式。设备不支持、供应商失败或用户不同意人脸时，提供工作人员核对证件的人工签到入口，并记录操作人和原因。

后续确认：D32已确定二维码完全退出签到链，D33已确定默认100米并由培训地点配置维护，D35已确定预约日期当天任意时间可签到，D36已确定培训和当天全部考试复用一次签到。当前签到主链已经收敛。

### S12 正式需求定稿采用的技术收口

以下是独立开发可实施性检查提出的缺口。它们不改变用户已确认的业务模块，由助手按最小实现原则在正式需求文档中作出技术收口：

- 原技术收口是在付款确认时冻结本轮服务的试卷、承诺次数和服务版本，已由D51替代：提交订单时固定价格、成员、服务内容、试卷、承诺次数及退费条款，到账只激活原订单权益。首次开考仍冻结发布版本和题单，次数遵守订单承诺；重新购买形成新轮次，从本轮第1次计算，不修改旧记录。
- 签到不等于参加培训。398元线下培训由现场人员在签到页执行“确认参加培训”，该事实决定培训资格是否已经使用；后续D49确认还须作为本轮398元开考门槛。视频学习进度仍独立记录，不替代现场培训确认。
- 退款申请先暂停资格；D53补充必须同时禁止新预约、改期、确认参加培训和新开考，防止重复申请、重复或超额退款。拒绝只解除本次退款暂停；审核通过后按原规则取消未开始预约，实际退款结果单独记录。首期不另做“只取消但保留待预约资格”的操作。
- 首期个人微信小程序／微信内H5分别使用微信小程序支付／JSAPI支付，企业PC使用微信Native二维码；按D54，全部退款人工办理并由运营录入结果，对公收款仍人工确认。银行流水自动导入、微信结算对账和自动退款接口不纳入首期。
- 企业开通时由机构配置新学员默认来源；导入新成员继承，已有学员保留原来源。398元／98元服务不自动改来源或决定难度。
- 签到正脸比对后删除临时原图，精确经纬度不落库；只保存地点、距离、精度、时间、方式和结果，距离／精度摘要默认180天后清理。

| 事项 | 参考文件或旧讨论 | 当前处理 |
| --- | --- | --- |
| 支付顺序 | 参考和会议存在先付款、先预约、先锁位等不同方案 | 企业按 D06、个人按 D09，均先付款后预约，不采用付款前锁位 |
| 名额控制 | D07一度提出不限名额，后询问分时段限额 | 按 D08、D26、D44，培训考试支持整天一批，单独考试由运营配置每日总号源和任意数量时段；共享当日总额，不自动均分、不另增固定分时配额 |
| 团队操作人 | 一份建议机构代办，另一份建议企业全程自助 | 按D40，企业联系人导入、报名、付款并批量安排初次预约；员工查看预约，个别改期及到场后的流程由本人完成 |
| 团队付款 | 参考文件建议企业统一支付，会议曾提出员工现场缴费 | 按 D05，团队统一由企业付款，不考虑员工各自付款 |
| 培训与考试安排 | D01分别预约，D10曾被理解为合并一条预约 | 按 D19，初次培训自动绑定当天考试，分别留存；培训后可单独改考试日期 |
| 培训参加门槛 | D02曾允许不以培训作为考试条件，已被替代 | 按D49，398元须先有本轮现场培训参加确认才能考试，98元无此门槛；初次预约仍可联动生成培训和考试记录 |
| 套餐考试机会 | 早期398元含一次考试 | 按 D20，1次培训及总共3次考试；3次未通过须重新购买98元或398元 |
| 98元次数与费用拆分 | 曾待确认且不自行拆分398元 | 按 D21，98元也含总共3次考试；398元＝300元培训＋98元考试，不改变已参加培训后不退款 |
| 次数配置来源 | D20、D21曾按套餐固定3次表述；S12曾在付款确认时冻结 | 按D22从关联试卷读取，D51明确提交订单时固定承诺次数、到账仅激活；首次开考及后续配置不得削减该承诺，新购买轮次保留旧记录 |
| 二维码及开考条件 | 原随机考试设计采用通用固定H5入口；D27、D28一度计划每卷签到码 | 按最新 D32，二维码不参与签到；预约时间＋定位＋照片人证比对成功后才能新开考 |
| 退改及签到时间 | 补充文档给出提前24小时、48小时、提前30分钟等建议 | 按D35、D37、D38，当天任意时间可签到，未开始服务可改期；已签到改期不回补当天名额，当天不接受新预约 |
