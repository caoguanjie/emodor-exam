## 2 本轮已确认的决定

### D01 培训与考试分开预约

- 状态：已确认。
- 确认日期：2026-10-28。
- 用户原话：“培训和考试分别选择时间、分别预约”。
- 适用范围：398 元培训加考试套餐。
- 需求含义：购买一份套餐后，培训和考试分别选择自己的时间，分别形成预约记录，并计入各自场次的名额。
- 不采用：一次预约同时代表培训和考试都已安排。
- 待继续明确：一份套餐允许多少次培训预约、改期和补约；取消其中一项后如何处理另一项及退款。

### D02 培训与考试独立 不以完成培训为考试条件

- 状态：已确认。
- 确认日期：2026-10-28。
- 用户原话：“两者独立，不以培训完成作为考试条件”。
- 需求含义：考试预约不需要等待培训完成；考试也不因为尚未参加或完成套餐内培训而被阻止。不规定先培训后考试的顺序。
- 取代的设想：必须完成培训后才能预约或参加套餐内考试。
- 边界：这不是取消实名、缴费、预约时间、现场签到等其他条件的授权；这些条件分别讨论。也不据此直接修改现有其他试卷的考前学习配置。
- 待继续明确：此前会议提到“不通过后重新学习再考”，补考是否存在单独要求；不得用这一尚未澄清的片段重新推导首次考试的培训门槛。

## 3 会议带入的业务基础

来源：[2026-10-28 会议纪要](../../meeting/2026-10-28-培训考试预约与收费需求会议纪要.md)。以下是会议记录带入的信息，不应与本轮新增确认混淆。

| 事项 | 当前记录 |
| --- | --- |
| 收费 | 398 元包含培训和一次考试，不另收 98 元；98 元为单独考试费用 |
| 服务对象 | 个人学员，以及企业或班组代报名的成员 |
| 批量名单 | 需要模板上传，前期提出 Excel 或 TXT |

| 排期 | 后台配置时间段及名额，根据人数增加场次 |
| 付款 | 最新完整纪要为先预约后缴费，线上或现场缴费；与较早片段和参考设计存在冲突，需最终确认 |
| 团队缴费 | 最新纪要允许企业只代报名、成员现场自行缴费；早期曾提出企业统一付款，不能默认只有一种方式 |
| 模拟考与赠送 | 是否单独收费、期限、次数、赠送会员、赠送考试是否额外提供，均未确定 |

| 外部对接 | 住建平台对接另行沟通，不纳入本次开业演示节点 |

## 4 已讨论的设计建议 还没有批准

### S01 PC 新增两个一级业务菜单

助手建议：新增“预约管理”和“收费管理”。用户尚未确认页面数量和具体命名。

可供下一轮讨论的细分为 **2 个一级菜单、8 个主要管理页面**：

| 一级菜单 | 主要页面 | 工作内容 |
| --- | --- | --- |
| 预约管理 | 培训服务 | 配置 398 元套餐、98 元考试服务及包含内容，关联现有课程和试卷；不与“培训类别”混为一谈 |
| 预约管理 | 场次安排 | 分别配置培训场和考试场的日期、时间、地点、容量；可在同一页面切换查看 |
| 预约管理 | 预约记录 | 逐人查看培训与考试预约，处理改期、取消及异常 |
| 预约管理 | 团队报名 | 企业／班组联系人、模板上传、名单检查、批量分配场次，跟踪每位成员的缴费情况 |
| 预约管理 | 现场签到 | 查看当天名单、确认到场情况，具体扫码及相机用途待定 |
| 收费管理 | 缴费订单 | 个人及可能的团队付款、线上支付结果、现场收款登记 |
| 收费管理 | 退款处理 | 申请、审核、退款结果及对应服务的处理 |
| 收费管理 | 收支核对 | 收款、退款汇总，检查本地记录和实际收退款是否一致 |

说明：8 个是讨论中的主要管理页面，不是 8 个顶级菜单，也不代表只需开发 8 个界面。详情、导入预览、弹窗及企业自助入口另计。

可精简的地方：场地资料先放在场次安排中维护；企业资料先放在团队报名中；统计先用现有业务首页或相关列表汇总。签到是否单列页面，可按现场工作人员的实际操作决定。

### S02 移动端新增三个功能区

助手建议：保留现有“首页、课程、考试、我的”底部导航，在其中增加以下功能，不另建三套底部导航。

| 功能区 | 入口建议 | 内容 |
| --- | --- | --- |
| 报名预约 | 首页 | 查看服务内容和价格，实名及报名资料，分别预约培训／考试，按最终规则缴费 |
| 我的预约 | 首页近期安排及“我的” | 分别显示培训和考试预约、时间地址、状态、到场凭证以及退改入口 |
| 我的订单 | “我的” | 待付款、付款结果、套餐包含内容、退款申请及进度 |

已有课程和考试入口继续使用。支付页、选时间页、预约详情属于上述流程内页面，不能把“三个功能区”当成“三个页面”的工期估算。

### S03 企业自助入口待决定

需要区分“机构工作人员替企业导入名单”和“企业联系人自己登录并上传名单”。

如果要求企业自助，应有仅能查看本企业报名信息的入口；不能把机构管理员账号直接发给企业。企业先只负责代报名，不意味着必须购买企业统一付款功能，也不意味着要建设完整企业人事或多租户平台。

### S04 预约 支付 到场和考试分别记录

同一套餐包含培训和考试，不代表它们共用一条预约或一份名额。

```text
398 元培训加考试套餐
    ├── 培训安排 → 培训预约 → 培训场次名额 → 培训到场记录
    └── 考试安排 → 考试预约 → 考试场次名额 → 现有考试记录

98 元单独考试
    └── 考试安排 → 考试预约 → 考试场次名额 → 现有考试记录

缴费订单负责记录钱；预约记录负责安排时间；考试系统负责答题和成绩。
```

取消某次预约不直接等于整份套餐退款。培训已使用、考试未使用时如何退款属于待定业务政策，不自行将 398 元拆成 300 元培训加 98 元考试的退款价格。

## 5 两份参考文档的采用边界

参考：

- [医疗系统预约系统模块设计](../00-医疗系统-预约系统模块设计.md)
- [医疗系统预约系统设计补充](../00-医疗系统-预约系统设计补充.md)

两份文件包含“医疗源码核查”及“培训增量建议”两种内容，不是两套都已实现、可以直接合并的系统。

适合借鉴：可约日期和时段、容量与余量、个人预约查询、取消及名额释放、操作记录。

需要重新设计：培训与考试的独立预约、套餐收费、个人与团队报名、现场缴费、退款、签到和现有考试的衔接。参考文件里的医疗患者、治疗师、就诊卡等不直接迁入。

已发现的政策差异：

| 事项 | 参考文件或旧讨论 | 当前处理 |
| --- | --- | --- |
| 支付顺序 | 多处采用先付款后预约；团队还存在先锁位后付款的设计 | 最新纪要为先预约后缴费，最终规则待确认 |
| 团队操作人 | 一份建议机构代办，另一份建议企业账号自助 | 待用户选择，不静默决定 |
| 团队付款 | 默认企业统一支付 | 最新会议允许个人现场缴费，不能套用团队统一付款的唯一流程 |
| 培训与考试安排 | 多处使用一次到场资格和单个场次来表达套餐 | 按 D01 分开预约 |
| 培训完成门槛 | 旧讨论存在先学后考设想 | 按 D02 独立，不以完成培训作为考试条件 |
| 退改及签到时间 | 补充文档给出提前24小时、48小时、提前30分钟等建议 | 全部是建议，不是已批准运营规则 |
| 题目难度 | 会议碎片涉及按收费方案区分难度 | 尚未批准，不作为本次预约和支付需求的默认规则 |

现有能力复核：PC 已有学员、培训类别、课程、试题、试卷、考试记录、角色权限等路由；移动端底部为首页／课程／考试／我的。现有学员导入和实名流程可复用，但团队报名仍需新增报名批次、场次和收费关系，不能把导入学员等同于完成预约。

## 6 待讨论问题与建议顺序

1. **谁为团队操作**：企业联系人自行上传与预约，还是机构人员代办？这决定是否需要企业专用入口。
2. **先预约后付款的最终规则**：线上待付保留多久，现场缴费如何保留名额，何时必须付清；398 元套餐两个预约如何关联同一笔付款。
3. **团队付款**：只允许成员分别缴费，还是也支持企业统一付？付款人与参训人分别记录，不能据“平台不区分谁缴”丢失退款去向。
4. **退改与部分使用**：培训与考试独立取消、改期、缺席；只使用一部分服务后的退款和剩余使用规则。
5. **现场考试条件**：是否必须签到、扫码由谁操作、相机用途、开考时间窗口；防作弊另列考试增量，不混入支付验收。
6. **次数和期限**：培训包含几次、考试含一次之外的补考收费、模拟考次数、赠送会员期限。
7. **场地与资源**：首期是否只做海珠；培训和考试能否同时举行、是否共用教室、各自容量如何设置。
8. **板块定稿和首期范围**：确认 PC 两个菜单及页面数量、移动端三个功能区、企业入口和开业演示范围。
