# 网站关于我们配置 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement task-by-task.

**Goal:** 按用户最新确认方案，PC网站配置使用“品牌展示 / 关于我们”两个页签，各自独立保存/撤销，并接通H5关于我们/服务条款。

**Architecture:** 复用 site_setting JSON 存储与现有 GET/PUT 网站配置接口，新增 about 配置键，无新表。Logo 复用既有字段，条款采用 Tiptap JSON 富文档，H5 使用已有只读富文本渲染器。旧客户端省略 about 时保留现有内容。

**Tech Stack:** NestJS、TypeORM/MySQL、Vue/Element Plus/Tiptap、uni-app/Wot UI。

**Spec:** 本对话已批准的七项表单、Tiptap与用户最新“做两个页签，现在太长”的明确指令；早先无页签方案已被覆盖。

## 契约与边界

- `about`: `{ institution_name, platform_subtitle, version, contact_email, wechat_account, contact_phone, service_terms }`。
- 前六项是字符串，最大长度依次 128/200/32/254/128/32；机构名称、平台简介、版本非空；联系方式可空，邮箱校验，联系电话支持手机、座机及常见分隔符（空表示不展示）。
- `service_terms` 为现有 schema 3 富文档或 null，复用现有结构验证/渲染，不接受 HTML、任意 URL、图片或其它媒体节点，避免引入新公开媒体授权。空条款隐藏入口。
- GET /admin/site-settings 和 GET /site-config 返回 about；PUT 可选 about，省略保留，非法输入整次拒绝。公开返回只保留上述白名单。
- 默认机构/简介/版本沿用已有 H5 展示；联系方式为空，条款沿用仓库现有静态文本，不编造联系信息或新增法律条款。迁移 039 幂等新增配置，初始化 SQL 同步。Logo/轮播稳定锁和媒体引用契约保持。
- 保留当前未提交改动。当前 mobile 登录页、首页等正在被其他任务修改，不覆盖；先交付关于我们和条款的完整配置消费，品牌名称统一到其他页面仅在不冲突情况下做最小接入。
