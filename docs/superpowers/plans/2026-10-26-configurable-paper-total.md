# 可配置试卷总分 Implementation Plan

> **For agentic workers:** 使用 subagent-driven-development 按职责实施，保留工作区并行未提交改动，不提交或部署。

**Goal:** 新增试卷和试卷设计器支持可编辑总分，默认 100，可设 120；草稿允许未配齐，发布必须配齐。

**Architecture:** 复用 exam_paper.total_score（DECIMAL(5,2)），API 以分表示总分，快照和逐题运算以整数分币 totalCents/score_cents 表示。总分与及格线写入发布快照，开考继续沿用冻结快照，不改历史数据。

**Tech Stack:** Vue 3、Element Plus、Tiptap、NestJS、TypeORM、MySQL、Vitest。

**Spec:** 本轮用户确认的方案：两处新增“试卷总分”，设计器展示已分配与差额，草稿可暂存、发布时校验。

## 约束

- total_score 默认 100，范围 0.01～999.99，最多两位小数，沿用现有列容量。
- 及格线大于 0 且不超过目标总分；修改总分不得静默改写及格线或已有题目分值。
- 新建/题库加入题目的默认分值 0；草稿允许未分配分值，已保存题目不覆盖。
- 发布要求每题正分、合计等于目标总分；题目完整性、权限、引用、发布冻结规则不放宽。
- 旧发布快照继续原值；旧制度管理创建规则不因新前端入口而恢复或扩大。
- 本次不新增数据库列，不改既有迁移 checksum，不自动提交、不部署。

## 任务

- [x] 后端：DTO、草稿写入、发布规则、随机/固定抽样、开考快照支持动态总分；回归 120 分、零分草稿、及格线越界、历史 100 分。
- [x] 前端：新增表单、设计器设置、API host/type 总分往返；显示已分配/差额；保存校验与发布职责分开。
- [x] 消费者：核对移动端、统计、成绩、评分及只读预览未硬编码 100 分。
- [x] 文档：01/03/04/05/06/README 与实体/init 保持一致。
- [x] 集成：后端编译、单测、前端测试及必要类型检查；独立审查并修复发现。

## 验收路径

新建目标 120、及格 72 的试卷 → 加入两道题 → 0 分草稿保存成功 → 配分 50+60 后保存成功但发布失败 → 配分 60+60 后发布成功 → 冻结规则 totalCents=12000/passCents=7200 → 满分答卷为 120 分。总分改为低于及格线时应拒绝，历史 100 分卷仍按原快照处理。
