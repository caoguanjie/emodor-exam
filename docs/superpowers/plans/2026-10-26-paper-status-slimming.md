# 试卷状态与查询入口瘦身 Implementation Plan

> **For agentic workers:** 通过 subagent-driven-development 并行实施前端与服务端，根智能体整合文档并验证。

**Goal:** 试卷日常管理只保留草稿、已发布，补齐查询/重置，撤回和归档写入链路退场。

**Architecture:** 保留创建、编辑、复制、发布、冻结快照及考试记录链路。移除 PC 撤回/归档动作及服务端公开路由和对应写服务；历史 withdrawn/archived 仍按原事实只读兼容，绝不转成 published 或删除考试记录。

**Tech Stack:** Vue 3、Element Plus、NestJS、Vitest、现有隔离 API 回归。

**Spec:** 用户当前明确要求状态只有草稿/已发布，其他状态链路不需要，并补充查询按钮；沿用上一轮固定题单入口瘦身，不加入自动选题。

## 边界

- 新流程为 draft → published；发布后题面与规则锁定，修改沿用复制为新草稿。
- PC 两页签的筛选只提供草稿/已发布，新增查询/重置；详情撤回、归档动作移除，包括历史卷归档写入入口。
- 删除 `/admin/papers/:id/withdraw`、`/admin/papers/:id/archive`、`/ai/papers/:id/archive` 路由及无其他用途的服务写方法。旧 URL 不得继续改状态。
- 历史状态字符串、读取、防重复发布/开考约束保留；状态列为 VARCHAR，不改物理结构、不加迁移、不改已有迁移 checksum。
- 不改题库、自动选题、学员考试、评分、学习门槛业务，不清理用户数据，不提交或部署。
- 保留所有并发修改；各智能体只写自己负责路径。

- [x] 后端：控制器及服务删除撤回/归档写入；调整相关单元/API 回归，以路由不可达断言替换旧动作调用，历史状态行为用测试预置保留覆盖。
