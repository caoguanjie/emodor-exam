# 培训机构 Demo 瘦身实施计划

状态：待用户审阅确认，尚未实施。2026-10-22。

执行方式：使用 astra-workflow 分工与集成，不使用 SDD，不要求固定轮次审查。计划获批前不修改产品代码、现行需求或数据库；不自动提交、合并、推送或部署。

## 1. 目标与依据

以培训机构业务为主，保留「资料上传解析 → AI 出题 → 题目审核 → 统一题库 → 组卷发布 → 自动评分 → 考试记录 → 成绩分析与排名」，删除已明确取消的独立功能，整理菜单。保留当前 NestJS、Vue 3、MySQL、Redis 架构，不开发独立 H5。

本轮用户指令优先于旧设计。`2026-10-21-training-admin-integration-design.md` 中“保留制度管理”、四题型、人工阅卷、实时监控等要求已被本轮范围取代。旧系统静态页面、未验证字段不能作为新增功能依据。

## 2. 删除、隐藏与保留的精确边界

| 对象 | 本轮处理 | 不能误删的部分 |
|---|---|---|
| 图片作答题 | 删除录入、导入、组卷、答题附件、评分分支及相关契约 | 题干、选项和解析中的普通图片，课程封面、视频和头像 |
| 人工阅卷 | 删除页面、接口、权限、评分服务和待人工评分分支 | AI 题目入库前的人工审核，自动评分服务 |
| 实时监控 | 删除页面、专用查询、轮询、连接状态及切屏监考采集展示 | 考试记录、正常开始/交卷时间、服务端计时、草稿保存、超时交卷 |
| 制度管理 | 删除管理页面及其创建、编辑、发布、范围、学习要求、版本切换等管理接口 | 出题资料的文件上传、解析、不可变版本和题目来源追溯，收进题库 |
| 员工管理 | 删除 `/admin/users` 入口、旧员工 CRUD 和部门式员工导入 | 学员、管理员、本人资料、登录认证与账号存储 |
| 部门管理 | 删除管理页面、CRUD 和新学员维护中的部门字段 | 既有旧考试/旧学习仍实际读取的共享历史数据；不直接删库 |
| 原统计报表 | 按此前讨论隐藏前端入口，旧 URL 回业务首页 | 当前培训统计、排名、导出；本轮不擅自扩大为删除整套旧统计后端 |

“删除干净”的验收定义：被取消的业务没有可操作页面、可调用管理接口、权限入口、普通业务中的状态分支和现行功能承诺，不通过菜单隐藏冒充删除。

共享存储不按名字机械删除：`sys_user` 是所有账号的基础；`regulation/regulation_version` 仍可承载出题资料。旧学习、旧固定卷及旧统计目前仍读取部分组织/范围实体。本计划不会把取消三个管理模块扩大成取消全部旧学习、旧卷或抹掉已有考试记录；保留依赖必须逐项列明，不能借“兼容”保留已取消的 CRUD。

## 3. 菜单结果

```text
业务首页
培训管理
  ├─ 培训类别
  ├─ 学员管理
  └─ 课程管理
考试管理
  ├─ 题库管理（录入、导入、AI 出题、题目审核）
  ├─ 试卷管理
  └─ 考试记录
统计分析（复用培训统计页面）
系统设置（默认收起）
  ├─ AI 服务配置
  ├─ 管理员
  ├─ 角色权限
  ├─ 网站配置
  ├─ 字典配置
  ├─ 菜单配置
  ├─ 在线会话
  └─ 审计日志
```

- 复用 `sys_menu.parent_id/sort/status` 和既有权限；不新增第二套菜单配置或 Demo 开关平台。
- 业务首页和统计分析是直接页面；培训、考试、系统设置是可折叠目录。
- 管理员不显示“我的学习”；不因此删除学员现有学习、考试、成绩功能。
- 删除路径从侧栏、首页快捷入口、路由及缓存标签页中清除；过期地址回业务首页。原统计页面仅隐藏。
- 出题资料没有独立侧栏菜单，放在题库的 AI 出题流程内。

## 4. 共享契约先固定

### 4.1 出题资料

新增 `server/src/modules/question-materials/question-materials.controller.ts`、`question-materials.service.ts`，复用已有上传/解析实现。

| 接口 | 输入与输出约定 |
|---|---|
| `GET /admin/question-materials` | `page/page_size/keyword`；返回 `{items,total,page,page_size}`，项目含字符串 `id`、`title`、`description` |
| `POST /admin/question-materials` | `{title,description?}`；返回上述资料对象 |
| `GET /admin/question-materials/:id` | 资料及倒序 `versions`；版本包含字符串 `id`、`version_no`、`file_type`、`parse_status`、安全的失败说明 |
| `POST /admin/question-materials/:id/versions` | multipart 字段 `file`，沿用现有 PDF/DOCX 类型、大小、内容检查；返回新版本 ID 与解析状态 |
| `GET /admin/question-materials/:id/versions/:versionId/status` | 返回版本归属、`pending/parsed/failed` 状态及安全失败说明 |
| `POST /admin/question-materials/:id/versions/:versionId/retry` | 复用已有解析重试能力，不新建任务机制 |

读接口使用 `ai:read`、写接口使用 `ai:write`，不新加一套资料角色。所有接口保持 `{code,message,data}` 信封，所有 ID 字符串化。

AI 请求明确传 `material_id + material_version_id`，服务端验证归属且版本已解析；不依赖制度发布或“切换当前生效版本”。其余类别、难度、题量、分值配置沿用当前契约。内部来源列可继续使用旧列名，避免无价值的全库改名；外部表单不再要求理解制度管理。

### 4.2 账号与记录

- `Users.vue` 当前同时服务员工和学员路由，不能整文件删除；收敛为学员页面并更新引用。
- 学员 API 不再接受/输出部门字段；账号认证、安全改密、停用吊销和管理员保护不变。
- 管理员管理目前主要是给已有账号分配角色。删除旧员工创建后，补 `POST /admin/administrators`，原子创建账号与角色关系，不要求先创建学员再提升；复用现有密码校验、权限边界和审计。
- `ExamMonitorService` 当前还承担记录查询，改为 `ExamRecordsService` 的列表/详情职责，保留考试记录接口；不整份删除造成记录页面失效。

## 6. 五个重点回归风险

1. 删员工页面误删共享学员页面：P1/P3 验证学员完整增改查、导入、停用和改密。
2. 删制度管理导致 AI 无资料：P1/P3 验证新资料与新版本的上传解析生成，不依赖预置旧制度。
3. 隐藏阅卷但残留待评分状态：P2/P4 验证只接受三题型、交卷终结及旧数据阻断策略。
4. 删监控误删计时与考试记录：P2 验证超时、重复提交、恢复和记录详情。
5. 旧缓存/角色/数据库菜单使入口复活：P1/P3/P4 验证普通管理员、超级管理员、重新登录和升级后的菜单与路由。
