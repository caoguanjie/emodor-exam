# 共用题库的独立随机模拟考设计

状态：设计已确认，并按 Astra 工作流完成源码、隔离自动化、PC/H5及独立审查。实际证据与未验边界见[验收记录](../../../review/2026-10-28-practice-random-exam-acceptance.md)；未合入原main，未升级开发/生产库或发布真实业务卷。

基线：[公共随机考试设计](2026-10-28-shared-random-exam-design.md)及其[验收记录](../../../review/2026-10-28-shared-random-exam-acceptance.md)。基线记录了当前分支的源码、隔离自动化和桌面浏览器验收；不扩大为开发库已升级、真实手机、真实供应商或生产部署已通过。本增量只覆盖模拟考，正式考试和旧制度考试继续遵守各自原规则。

## 1. 目标与已确认规则

正式考试之前，学员可以在 H5 参加模拟考，正常获得分数并复习错题。共用一套公共题库，正式卷与模拟卷各有独立的随机抽题规则、发布版本和考试记录。

- 新增独立模拟试卷，不把现有正式试卷改成模拟卷，也不在同一个 paper_id 上混用两种考试用途。
- 模拟考不限次数，及格后仍可以再次参加；不消耗正式考试次数。
- 运营可以配置模拟卷题量、题型数量、每题分值、总分、及格分和时限，例如 50 道或 100 道。两份卷的规则可以相同，也可以不同。
- 创建模拟卷时默认带入选定正式卷的配置，减少日常配置工作；创建后独立维护，不自动跟随正式卷变化。
- 每次新模拟随机抽题，一次题单内不重复；不同次模拟之间、模拟与正式之间允许重题，不保证题单一定不同。
- 模拟考主动交卷后正常评分、保留记录，答错的题进入现有错题集。
- 模拟卷修改并重新发布后，所有学员下一次新模拟使用最新配置；已开始的本次模拟和全部历史记录保持原版本。
- 刷新、退出再进入仍恢复原次考试，不重新抽题、不延长截止时间。

```text
公共题库
  ├─ 正式卷规则 / 正式发布版本 → 正式考试 → 正式成绩与次数
  └─ 模拟卷规则 / 模拟发布版本 → 模拟考试 → 模拟成绩，不限次数
                                               └─ 现有错题集
```

## 2. 范围和设计默认

复用现有 Vue / Element Plus 管理端、uni-app 学员端、NestJS 服务端及 MySQL / Redis；复用发布冻结、随机抽题、答题、服务端截止、整卷提交、自动评分、结果与错题能力。

以下是实现方基于最小改动给出的默认，未另行要求用户作新选择：

1. 本期模拟卷只支持培训公共随机卷，即 training + random + public。不增加固定模拟卷、模拟专属题库、逐题立即判分、错题专项练习或模拟排行榜。
2. 模拟卷仍要求登录、账号有效、必要资料和实名。工种可选；来源由服务端认定，institution 对应 easy、external 对应 hard，不让学员自行选难度。
3. 来源与难度沿用现有首次归属冻结规则：首次参加该模拟卷时冻结来源，后续模拟不因管理员修改来源而改变难度。本次新增的是“每次新模拟采用最新发布规则”，不额外改变来源冻结语义。
4. 有正式公共随机卷时，运营从选定卷发起“创建模拟卷”；不自动猜选多份卷中的某一份，也不自动生成或发布生产数据。无合适正式卷时仍可新建模拟随机卷，沿用现有随机卷默认值。
5. 通过发布和撤回控制可否新开考，不新增定时开放配置；模拟卷可以先于正式卷发布。
6. PC 与 H5 都沿用现有考试记录页查看模拟成绩，默认可看两种记录并标明用途；正式统计页不建立模拟专题。

学员端共享代码需保持小程序编译和原有行为兼容；本增量的产品验收以 PC / H5 为主，小程序真机不由 H5 结果代替。

## 3. PC 配置与发布

### 3.1 试卷用途与创建

新增用途 formal / practice，分别显示“正式考试”和“模拟考”。用途与现有组卷方式 mode=fixed|random 分开；不得占用 mode 或 pool_scope 表达模拟考。既有试卷、发布和记录保持 formal 语义。

在现有试卷管理中支持创建模拟随机卷，并显示用途及用途筛选。用途创建后不互转，避免已存在的历史成绩、统计和次数改变归属。需要另一种用途时创建新卷。

“创建模拟卷”复用现有新建/编辑表单：草稿源读取已保存配置，已发布源读取最新发布快照；复制题型规则、总分、及格分、时限、评分设置及已配置的考前学习条件。标题默认在原题名前加“模拟考 · ”，仍可修改。模拟次数固定为不限次，不复制正式次数限制。

该操作只准备配置并保存独立草稿，不复制任何学员归属、题单、答案、成绩或已用次数，不自动发布。新模拟卷发布时自行从当前公共题库收集候选并冻结；不继承正式卷发布 ID，也不长期绑定其候选池。正式卷后来撤回、改规则或重新发布，不影响已建模拟卷。

### 3.2 配置校验

题型仍为单选、多选、判断，题数和每题分值组成整卷。总分必须等于各题型分数之和，沿用现有整数分币计算、数量/分数/时限限制和多选评分方式。运营无需配置“模拟次数”，界面明确显示“不限次数”。

发布仍分别检查 easy / hard 各题型题数足够，排除未启用、已删除或不合法题目，冻结当时的精确题目版本、规则和媒体引用。缺题或校验失败不产生有效新发布版本，不影响已有版本记录。后续题库变化只有重新发布后才进入模拟候选池。

PC 发布/撤回说明明确区分：模拟卷再次发布影响所有人的下一次模拟；正式卷已有学员继续原冻结归属规则。

## 4. H5 体验

沿用现有考试 Tab 和通用二维码，在同一考试列表中区分“正式考试”“模拟考”，不新增底部导航或专属二维码。列表和须知显示模拟用途、题量、总分、及格分、时限及“不限次数”，不显示有限剩余次数。

```text
考试列表 → 模拟卷须知 → 明确点击开始
                      ├─ 有进行中记录：恢复原题单和截止时间
                      └─ 无进行中记录：按最新模拟发布规则抽题
                                           ↓
                                     答题 → 主动交卷
                                           ↓
                                  分数 / 解析 / 错题
                                           ↓
                                    明确点击再考一次
```

继续复用答题卡、计时、本机最小草稿、交卷确认及结果页。成功交卷后可以“再考一次”；点击后重新进入最新须知，再明确开考，不能因打开结果页自动产生记录。

须知与实际开考规则要一致：在查看须知后发生重新发布，且请求携带的预期版本已过期时，提示考试配置已更新并刷新须知，不创建新记录；用户再次确认后开始。不得在用户不知情时换成不同题量、时限或分值的考试。

模拟卷撤回后禁止新开考，已有进行中记录仍可按原协议恢复和交卷，历史成绩、解析和错题仍可查看。超时沿用纯 timeout：不自动提交、不评分、不生成答案；可以在后续明确操作时重新开始，不能在超时收口请求里悄悄新开一次。

登录、实名回跳及账号切换沿用新公共考试流程；前一个账号的列表、题单、草稿或结果不得被下一个账号复用。

## 5. 后端归属、次数与历史保护

### 5.1 复用边界

当前 exam_assignment 按 paper_id + user_id 唯一，exam_record 按该学员、试卷和 attempt_no 区分每次考试；现有 start 优先恢复进行中记录，随后才检查发布与新开考条件。独立模拟卷继续利用这一边界，不为模拟考重建一整套评分或存储模块。

新增用途需要在试卷、发布与记录读取链路中可可靠识别。既有数据默认 formal，正式接口省略新字段保持旧行为；模拟用途由服务端持久化事实确定，不能相信学员请求中的用途参数来放宽次数。

### 5.2 真正不限次数

不使用 100、9999 等有限数字冒充不限次，也不把达到阈值后的记录清零。新模拟次数持续累积供历史展示，任何已用次数都不触发业务额度耗尽；并发锁、单活跃、权限与发布校验仍保留。

契约显式区分“有限”“不限”“历史未知”三种状态。模拟上限及剩余次数可用 null 表示无有限值，但必须有明确的不限次标识，不能把既有未知 null 自动解释成不限次。正式上限继续按冻结规则执行。字段名称、DDL 列和类型细节留给实施计划，前后端必须统一语义。

### 5.3 每次模拟采用最新发布

在新开考事务中先恢复/收口已有活动记录；只有确实新开一次模拟时，才锁定并读取该模拟卷最新已发布版本，冻结该次的 release、规则、来源、难度、题单、顺序、实际分值和截止时间。发布并发必须确保这些信息来自同一有效版本，不能拼接新规则与旧题池。

最小实现方向：保留唯一 assignment 作为该学员与模拟卷的关联和单活跃锁，不改写其首次冻结字段；新模拟 record 使用本次解析出的发布与规则，而不是继续复制 assignment 中第一次的发布与规则。来源/难度继续取首次归属冻结值。正式 record 创建路径保持原样。

模拟摘要在有活动记录时读取活动 record 的冻结事实，无活动记录时读取当前最新发布配置；结果、交卷评分、历史、错题和题图授权一律以对应 record 的发布与题单为准。不得因 assignment 仍保留首次信息而把后续模拟题单与旧规则混用。实现前须核对所有这些读取点，不能只修改 start 的取题语句。

任意一次新模拟失败必须整体回滚，不遗留活动记录或题单；并发/重复开考只产生同一次记录。题单在出卷阶段不包含答案、解析或未抽中的候选题；媒体签发仍核对精确引用和本人授权。

## 6. 评分、错题与统计

模拟交卷与正式考试使用同一自动评分规则和提交幂等逻辑。保留本次总分、及格线、得分、答案和逐题解析，后台不直接修改最终总分。

错题继续由本人的已评分考试题目及答案派生；模拟和正式都进入现有错题集，并显示用途/来源试卷。沿用当前“未得满分”口径，包括部分得分及未作答题；超时未交卷不生成错题。同一题多次答错按现有各次记录展示，不新增去重、掌握状态或后来答对自动删除旧错题的机制。历史题面和媒体始终读取该次快照。

PC 考试记录提供用途筛选并可查看两种考试的成绩详情；H5 历史记录标明用途。模拟有记录不等于正式考试已参加或已通过。

正式统计、排名、导出、首页考试指标和最近正式考试等汇总入口必须在服务端排除 practice，查询总数与分页使用同一条件；不能只在前端隐藏行。仅按 paper_id 的正式统计入口也要核对用途，直接传入模拟 paper_id 不得形成正式报表。本期不增加模拟分析报表；管理端通过考试记录查看练习结果。错题集的条数与记录列表仍按各自含模拟的范围计算，不随正式统计过滤被误删。

## 7. 实施边界与一致性

预计涉及 PC Papers / PaperEditDialog / 随机规则组件，移动端考试列表、须知、结果、历史、错题及相关 store / 类型，后端 paper / release / attempt / summary / result / history / media / statistics / dashboard 读取链路。

这是在现有公共随机流程上的增量，不重新实施公共题库、工种可选、二维码和实名回跳。设计阶段核对时发现图索引中的部分 PC 符号仍为旧版本，已用当前源文件确认随机表单与公共池配置存在；实施阶段以当时实际源码与最新索引为准。

需要表结构变更时追加迁移，编号在实施时核对最新目录后确定；同步 database/init.sql、entities、docs/design/ 对应分册与接口契约。不改写已有迁移 checksum，不重写历史正式用途或成绩；新增用途的默认与回填必须保持旧数据结果不变。

本设计形成时只交付文档；后续已按用户授权实施代码与隔离验收。实际试卷创建、开发/生产数据库升级、服务切换和部署仍另行授权，不由隔离验收代替。

## 8. 验收要求

1. PC 从正式公共随机卷带入配置创建独立模拟草稿，可直接保存或改成 50 / 100 道；修改任一份卷不自动修改另一份，发布分别冻结候选。
2. 两类难度分别校验题数，非法数量/分值/总分/时限及不支持的模拟用途组合被拒绝；失败发布不产生有效新版本。
3. H5 可以进入模拟、答题、交卷、出分、看解析与再考；入口、登录或浏览须知不自动开始。
4. 模拟在已用 3 次、100 次及更高已有次数时均可新开，不使用有限哨兵；正式次数限制仍有效，两者互不消耗。
5. 每次新开执行抽样，一次题单不重题；允许不同次随机抽到相同题目，不使用“题单必须不同”的错误测试条件。
6. 恢复不换题、不延时、不新计次；并发开考只产生一次记录，重复交卷不二次评分；超时不评分且后续可明确再次模拟。
7. 同一学员完成 v1 后开始 v2，下一次采用 v2 规则；v1 尚在进行时发布 v2，继续本次仍是 v1，之后新开才是 v2。须知过期提示刷新，无新记录副作用。
8. v1 / v2 的历史分数、题目、解析和题图都可准确读取；正式卷重新发布后的既有归属语义不变。来源后来改变仍按该模拟卷首次冻结难度，不影响旧记录。
9. 正常模拟分数正确；未得满分题进入错题集并标明模拟，部分得分/未作答口径与现有一致；正式错题继续可读。
10. 模拟不进入正式统计、排名、导出和首页考试汇总；PC/H5 考试记录仍可查看模拟，分页总数和筛选一致。
11. 撤回只禁止新开，旧活动记录可恢复；登录、实名、账号禁用、换账号、本人归属与答案/媒体权限无旁路。
12. 自动化使用隔离数据库，并验证迁移默认 formal、旧数据兼容和文档/entity/schema 一致。PC/H5 实际页面验收与构建、API 自动化分别记录；真实手机、真实供应商及生产部署不冒充已验。
