## 1. 目标与本期边界

以当前 EmodorRuleExam 为主工程，保留技术架构、制度管理、AI 出题审核、考试核心规则与统计报表，融合旧安全教育平台的培训机构业务。本期交付 **PC 管理端与完整后端链路**，包括随机开考、答题保存、交卷、人工批改、考试监控、统计分析和排名。

独立学员 H5 在下一期规划。本期通过 PC 管理操作、后端集成测试及现有固定卷员工端回归验收；不把新 H5 页面、视频真机播放、相机上传或移动适配写成本期已完成能力。

### 1.2 设计默认值（用户已于 2026-10-21 确认）

以下是设计者为控制改造范围作出的选择，不冒充用户逐项指定：

- 一个学员先归属一个培训类别；来源标识由管理员维护，学员不能自行修改。来源与权限角色分开。
- 同一考点的变体归属同一培训类别、同一题型，每次组卷同考点最多出现一道；未关联考点的题目各自独立。
- 一条试卷配置代表一场可发布考试，不额外引入考试项目、报名审批、班级或多租户平台。
- 同场新考试使用相同题型数量、每题分值、总分、时限与及格线。随机模式固定执行本机构抽初级、外来抽高级，不提供修改映射的表单；中级题可录入、审核及用于固定组卷，随机使用中级和难度比例混抽留到后续明确需求。
- 新考试沿用 100 分制、默认及格线 60、时长 30 分钟、最多作答 3 次和多选漏选比例 0.5；均遵循现有允许的配置范围。次数是含首次的总次数。
- 同一学员同一场考试首次成功开考时固定来源、难度及规则，补考沿用；学员资料后续变化只影响新考试。
- 默认按同场、同难度排名，取已完成批改的个人最高分，同分并列。总览可合并人数与结果分布，但展示难度构成。
- 监控首期采用 5 秒轮询，超过 90 秒无心跳显示“连接待确认”；提供手动刷新。真正的管理员强制交卷列为后续增强，不把旧站占位按钮当作本期必交功能。

## 3. 总体业务链路

```text
制度上传与解析 → AI 按难度生成 → 管理员审核 ─┐
人工录题 / Excel、TXT 导入 ─────────────────┴→ 统一题库
                                                   ↓
学员管理（类别、来源） ─────────────────────→ 固定 / 随机组卷配置
                                                   ↓
课程 → 章节 → 视频课时 → 学习记录                发布考试
                                                   ↓
                                      按本人身份开考并固定本次题单
                                                   ↓
                                      答题保存 → 主动 / 超时交卷
                                                   ↓
                                   客观题自动判分 / 图片题人工批改
                                                   ↓
                                 答题记录、监控、统计、成绩分析、排名
```

制度是内容依据和 AI 来源，课程是学习内容组织方式，培训类别是学员、课程、题目与考试的业务归类。部门仍保留为已有组织与统计维度，不用部门字段冒充培训类别。

继续使用 Vue 3 + TypeScript + Vite + Element Plus、NestJS 模块化单体、MySQL 与 Redis。扩展现有模块和必要的新模块，共享认证、审计、文件处理和响应约定；不更换框架，不引入微服务。

## 5. 学员、类别与学习内容

### 5.1 学员范围

新学员需要明确培训类别与来源 `institution/external`。批量导入允许逐行填写，也允许为整批选择默认值；缺失或非法值返回行号与原因，不静默按初级处理。已有 EmodorRuleExam 用户保留原身份与记录，来源未确认者仍可使用原固定卷，新培训考试发布前由管理员补齐。

默认本类别已发布考试对该类别的正常学员开放；不额外增加报名或资格审批。来源只决定抽题策略。本人信息、草稿、答卷、学习记录均按身份隔离。

本机构学员默认纳入本类别已上架课程的应学范围。外来学员默认只参与考试，不进入应学分母；已有学习记录仍保留可查。管理端改类别或来源后更新后续学习范围，历史考试使用开考时冻结的归属。学员本人资料接口不得修改类别、来源和角色。

### 5.2 课程、课时与视频

课程采用草稿、已上架、已下架；章节和课时有顺序。视频课时保存名称、媒体资源、服务端核验的总时长与状态。无视频课时允许留作草稿，不产生学习时长；上架时必须保证必学课时均有可用资源。

下架阻止新的学习会话，已确认进度与考试记录保留。已有学习记录引用的课程、课时、视频不能硬删除。发布后的课时替换视频形成内容新版本；历史记录保留，新的完成要求按新版本统计，不把旧视频时长套到新视频。

新增课时类型字段，本期实现 `video`，后续可增加资料或练习类型。当前制度阅读能力保留；不要求将制度强制包装成课程或视频课时。

媒体文件复用存储抽象和鉴权访问，增加视频元数据、引用与回收检查。本期使用当前可部署的本地存储，不强制对象存储或转码平台。首期视频格式定为浏览器可播放的 MP4（H.264/AAC），后台上传后实际解析格式、时长；不支持或解析失败明确提示，不假装上传完成即可播放。具体文件大小上限作为部署配置，PC 页面、API 与 nginx 一致。

### 5.3 学习后端契约

本期实现课程/目录读取、开启视频学习会话、心跳、暂停/结束、断点查询和汇总接口，用集成测试验收。已有制度阅读继续使用原阅读判据。

视频会话默认每 30 秒上报，服务端按真实间隔计入且单次最多 45 秒；暂停、缓冲和后台状态不累计。上报包含递增序号、播放位置与播放状态，重复或乱序请求不重复计时；新会话关闭同一用户旧活动会话。位置前进超出服务端可接受的播放间隔与 2 秒容差时，不确认跳过区间，返回已确认断点。

完成条件默认是已确认观看覆盖达到视频总时长的 95%；累计有效时长与不重复观看覆盖分开保存，反复播放片段不能充当完整观看。课程进度为已完成必学课时数/必学课时总数。页面仅打开不累计；零必学课时不自动判完成。服务器只能校验协议与时间一致性，不能据此证明用户实际注意力。

以上参数属于设计默认值，后续 H5 真机联调可在保持服务端可信边界的前提下调整。移动端观看、全屏、锁屏和弱网体验在下一期验收。

## 6. 制度、AI 与统一题库

保留现有 PDF/DOCX 上传解析、版本记录和 PDF 多模态出题能力。AI 配置、异步任务、输出校验、去重、失败重试与审核继续复用。首期 AI 生成仍支持现有单选/多选，新增目标难度与培训类别；判断和图片题由人工录入或文件导入进入题库。AI 自动生成图片作答题不在本期要求内。

新题目必有类别、题型和难度；制度及制度版本是可选来源关系。AI 题必须记录实际来源版本，人工题与导入题允许没有制度来源，不创建虚假制度。题型与难度为两个字段；图片题是明确枚举，不能把未知题型都当图片题。

考点组只提供关联相同知识点变体的轻量标识，不建设知识图谱。无需强制一个考点配齐三个等级，允许先积累任意等级的独立题目。

AI 题进入待审核，人工录入与合法导入由管理员确认后可用；生成来源和审核人可追溯。编辑已审核题的核心内容形成待复核版本，不影响已发布考试冻结的内容。

导入支持 Excel、TXT，提供与实际解析器一致的模板、预检查、行级错误和重复题提示。先预览确认再提交合法行，失败行可单独修正重导；提交使用导入批次标识避免重复入库。图片作答题导入的是题干、分值建议和评分参考，不是考生答案图片。富文本图片资源使用受控上传及内容清洗。

保留 AI 当前“按题量与分值配置生成一批题”的交互以减少改造；题库生成的建议分值与考试最终分值分开，随机组卷从已审核题库中抽取并按试卷配置定分。

## 7. 试卷与按学员来源随机组卷

### 7.1 两种模式

| 模式 | 管理操作 | 开考行为 |
|---|---|---|
| 固定组卷 | 手选题目、调整顺序/分数、合计 100 分 | 使用已发布题单，按现有规则打乱题目与选项。 |
| 随机组卷 | 选择培训类别、可选制度筛选和课程关联，配置题型题数/分值；展示固定的来源到难度规则 | 后端按本机构→初级、外来→高级，从对应范围随机抽取个人题单。 |

候选题的硬筛选只有培训类别、可选制度集合、题型、难度和审核状态。未选择制度筛选时，该类别内无制度来源的人工/导入题也可入池；选择制度集合时，仅匹配集合中的来源题。类别内可跨多个制度选题。

课程关联只解释考试覆盖范围，不参与题池交并计算，也不强制学习完成。课程与制度的引用是关联关系，不要求一门课程只能对应一份制度。

发布检查：总分等于 100、每类题型分值合法、所有候选题审核通过、两类来源各自所需的难度/题型数量足够。同考点最多抽一题，数量校验按这个限制计算；不足时明确指出缺口，不自动换难度、换类别或重复凑题。

发布时冻结抽题规则与候选题版本。候选题之后编辑、撤销审核或删除，不改变已发布考试的内容；发现内容问题由管理员撤回考试。新规则和新题池通过复制为新考试重新发布，已有考试记录不被重写。固定卷新增发布也冻结题目内容。

冻结保证适用于升级后的新增发布/新开考。现有 EmodorRuleExam 已结束记录缺少历史快照，保留原数据并明确标记遗留口径，不用当前题库内容伪造当时的快照。升级前已发布固定卷的新作答，在开考时形成个人快照并记录形成时间；不宣称还原了该卷旧发布时的内容。旧记录展示若仍依赖现行题目须明确注明，编辑引用题时保留旧版本，避免继续覆盖。升级切换预检发现进行中答卷时，应等待无在考窗口，不能靠清空记录或重置期限完成切换。

### 7.2 开考、补考与冻结

1. 确认账号正常、考试发布、类别开放范围匹配。新培训考试默认关闭学习门槛；原有制度专项固定卷保留原行为。
2. 同一用户同一考试已有有效进行中记录时，直接返回本人原作答，不重抽、不重启期限。
3. 首次开考读取管理员设置的来源并选择难度；同一考试后续补考沿用首次的来源、难度和规则。来源变更影响另一个新考试，不跨难度比较本场最高分。
4. 校验次数与已通过状态，再原子创建考试记录和个人题单。只允许一次有效开考结果；重复请求不能产生不同卷面或多占次数。
5. 固化题型、题干、选项、标准答案、解析、实际分值、难度、考点、来源版本、显示顺序及考试评分规则。答案与解析只存服务端，不进入在考 payload。
6. 补考独立随机抽题，允许与之前作答部分重合，避免新增题库容量要求；同一次答卷内不重复题目/考点。

本场首次归属可从首条考试记录或等价关联记录读取，具体物理表由实施设计确定。数据库约束与事务必须兜住 Redis 锁失效和并发；抽题失败不能落下空卷或消耗次数。

归档或撤回后不允许新开考；已在考者按原题单与期限完成，历史结果保留。需要立即终止全部进行中考试属于另行管理动作，本期不隐含在撤回操作中。

## 8. 完整考试后端、人工批改与监控

### 8.1 答题与交卷

本期交付开考、恢复、草稿保存、心跳、切屏记录、主动交卷、超时交卷、结果与解析接口。现有固定卷员工页面保持可用；新随机卷、判断/图片题的学员侧能力用真实 API 场景验证，新 H5 展示不列本期验收。

草稿按学员、考试记录和个人题单版本隔离；服务端确认保存的答案须可跨进程重启恢复，Redis 不作为已确认草稿的唯一存储。答题接口只接受本人本次题单中的题号与合法答案结构。

期限取开考时的服务端截止时间。刷新、恢复、重进不延长期限；超时使用截止前服务端已确认的最新答案，不以客户端时间证明离线补答有效。主动交卷和超时处理共用幂等终结逻辑，响应不明可查状态；已交卷答案不可改。截止后不再接受改答或新增图片。

图片题单题最多 9 张，文件上传、归属检查与答案保存分别处理。上传成功不代表交卷；超时只采用已上传且已保存为答案的文件。文件类型、大小、数量和引用均由后端校验，文件访问只允许本人和有权阅卷者。

### 8.2 批改状态与成绩

```text
进行中 → 已交卷
           ├─ 只有客观题 / 没有待评答案 → 完成批改 → 通过或未通过
           └─ 存在图片答案 → 待人工批改 → 完成批改 → 通过或未通过
```

提交方式另记主动或超时，避免用“通过/未通过”覆盖掉超时事实。完成批改时间与交卷时间分别记录。

单选、判断按正确与否评分；多选沿用全对满分、错选零分、漏选按快照比例计分。未答题为未作答、零分，不创建无意义的人工批改任务。提交的图片答案进入待批改，其分数为空而非零。

PC 阅卷页面展示冻结的题目、评分参考、学员图片、满分、得分和评语。单题得分限定为 0 至该题满分，记录阅卷人和时间；未全批完不产生最终总分、及格结论或排名。最后一题完成后由服务端汇总，客观题分数不允许手工覆盖。

本期最终成绩不提供直接修改入口。人工分在最终结算前可更正并留痕；最终结算后只读，复核后改分作为后续明确需求。待批改期间不开放本场补考；完成批改后按现有未通过/次数规则处理。

结果、历史、解析、错题与报表使用同一批改版本。错题默认包括最终评分中未获满分的题目（含未答与多选部分分）；待批改不计为错题。正确率为满分题数/全卷题数，未答与部分分不算答对；未全批完时正确率不展示为最终值。

### 8.3 考试监控

PC 按场次展示学员、来源/难度、开始与截止时间、剩余时间、已答/总题数、最后心跳、连接提示、切屏数、设备摘要、提交和批改状态。进度来自服务端已确认草稿，剩余时间由服务端计算。

监控列表、轮询、手动刷新与记录详情本期实现。连接超时只提示待确认，不自动判作弊、不额外扣分。强制交卷、摄像头监考、人脸识别不在本期。

## 9. 统计报表、成绩分析与排名

保留现有制度、部门、个人统计、学习完成情况、未完成人员和 Excel 导出；新增培训类别与考试场次视角，以及来源、难度筛选。制度历史视图保留可查，不把旧数据强行贴上新难度。

| 指标 | 新培训业务口径 |
|---|---|
| 应学人数/完成率 | 当前应学范围内本机构正常学员；完成课程按规定课时版本计算。外来仅考试人员不进入分母。 |
| 应考人数 | 考试开放类别内正常学员，包含两类来源。报表注明统计时点，不宣称是不可变报名人数。 |
| 已开考人数/参考率 | 参考率 = 当前应考集合内已成功开考的去重人数/当前应考人数；分子分母同集合。历史全部已开考去重人数另列，不混入该分子；进行中和已交卷人数另列。应考人数为0时比例返回空值，页面显示暂无应考人数。 |
| 已交卷/待批改 | 按考试记录计次数，同时提供去重人数；待批改单独列示。 |
| 最高分 | 同场、同难度、同评分规则内，每人已完成批改的最高分；同分选择较早完成批改的记录作为展示记录。 |
| 平均分/分布/通过率 | 基于上述个人最高分；通过率分母为已有最终成绩的人数。待批改不当零分，也不当未通过。 |
| 排名 | 同场同难度分榜，按个人最高分降序，同分并列，展示姓名、来源、分数、用时；用时排序不暗改分数名次。 |
| 未完成清单 | 区分未完成学习、未参加考试、考试待批改、考试未通过；无学习义务者不出现未完成学习原因。 |

总览合计可统计人数，但成绩分布、平均分和排名需可按难度拆分，表头明确当前筛选。不同难度不合成一张默认名次榜。已通过人数按冻结的及格线与最终结论计算，不用当前试卷配置重判历史成绩。

本期对现有“跨试卷取最高分”查询增加业务口径区分：原制度报表保留历史含义，新考试场次报表严格按场次与难度统计。旧固定卷难度保持未知，不从用户当前来源倒推。批改完成后同步失效统计缓存，页面、详情和导出同口径。

## 10. 数据、接口与实施边界

以下是职责增量，具体表名、字段长度和迁移顺序由实施计划落实，不要求复刻旧后端表结构。

| 现有归属 | 需要扩展的事实 |
|---|---|
| `sys_user` / 管理权限 | 学员类别与来源、资料；管理员业务角色与菜单/操作权限关系。 |
| 新课程模块 | 培训类别、课程、章节、课时及内容版本、视频资源与引用。 |
| `regulation` / `regulation_version` | 保留依据和版本；新增与培训类别/课程的可选关联。 |
| `question` | 类别、三级难度、可选考点组、新题型与可选来源；保留审核轨迹。 |
| `exam_paper` / `paper_question` | 固定/随机模式、学习门槛开关、抽题规则、发布时冻结的候选题版本；原固定卷兼容。 |
| `exam_record` / 本次题单 | 来源/类别/难度/考试规则快照，个人题目与答案基准，提交方式和批改状态。 |
| `exam_answer` / 草稿与阅卷 | 已确认草稿、客观/图片答案、附件关联、得分、评语、阅卷人和时间。 |
| 学习记录与会话 | 视频播放覆盖/断点与课程完成汇总；原制度阅读记录单独保留。 |
| 统计与审计 | 场次/难度口径、来源快照、权限配置及关键操作留痕。 |

实施时优先增加字段、关系和必要表，不在现有客户端字段里混入两套不兼容语义。随机发题、暂存、评分、解析、导出都通过同一本次题单读取接口；禁止其中某一处回读动态题库代替冻结内容。

继续使用 `/api/v1`、统一 `{code,message,data}`、现有认证和错误码体系。管理接口与学员接口按权限隔离；下一期 H5 消费本期学员 API，不直接使用管理员题库接口。接口文档明确分页、所有权、幂等键、状态及错误恢复；完整请求响应在 04 册细化。

本期完整后端的接口面明确如下，不以新 H5 尚未建设为由省略：

- 管理认证：验证码生成/校验、登录、刷新、本人信息、改密、退出、在线会话与吊销；保留现有固定卷员工登录兼容性。
- 管理业务：第4节的类别、学员、课程/章节/课时、媒体、制度、AI、题库、导入、试卷、阅卷、监控、统计导出与权限配置接口。
- 学员基础：登录/刷新/退出/改密、本人资料与头像、首页推荐及网站展示配置、本人可见课程列表/目录与学习记录、本人可见考试列表。
- 学员学习与考试：视频会话/心跳/断点/完成汇总，开考/恢复/草稿/心跳/切屏/交卷，个人历史/结果/逐题解析/错题列表及图片答案上传。

学员接口通过 API 集成测试验证身份隔离、分页、正常和异常状态；头像选图、移动答题控件等终端交互留待下一期。公开品牌配置只返回可展示字段，不能暴露管理员配置或 AI 密钥。

文件、缓存、后台任务沿用当前部署基础。视频大小、存储容量与异步超时使用部署配置；新增配置同步 `.env.example`。不得为方便联调把真实凭据写入文档、代码、测试或日志。

## 11. 验收范围与必要证据

| 场景 | 验收要求 |
|---|---|
| PC 内容生产 | 学员标识/类别、课程章节视频、制度解析、人工与文件导题、AI 生成审核、固定/随机发布均有成功与失败路径。 |
| 难度与考点 | 同一场两类学员拿到指定难度；题型、数量、总分符合规则；同卷不重复题目/考点；三级缺某档时按实际规则阻止发布而非补错题。 |
| 开考并发与恢复 | 同一学员并发/重试只得到一份进行中题单；刷新/恢复题目不变；失败不占次数；补考保留本场难度规则。 |
| 题单与历史 | 新快照答卷在开考后编辑题库、试卷参数或学员标识，原题、标准答案、得分和历史解释不变；遗留记录保持明确的旧口径，不伪造历史快照。 |
| 服务端安全 | 在考响应无答案/解析；越权开考、读他人答卷、提交不属于本卷的题目或附件被拒绝。 |
| 客观与图片题 | 单选、多选、判断、图片答案覆盖正确、错误、部分分、未答；真实上传文件与PC阅卷，验证9图边界与失败恢复。 |
| 超时与重复提交 | 服务端截止时间独立生效，采用已确认答案；主动/超时竞态只结算一次；重启后已确认草稿可恢复。 |
| 人工批改 | 分值越界、重复批改、两名阅卷者同时处理同题、最后两题并发完成均不重复汇总或丢分；未完成批改不进入最终排名。 |
| 视频后端 | 开始/暂停/心跳/断点/关闭、乱序重复、跳跃、后台与缓冲标记、内容版本变化；课程汇总与课时一致。 |
| 监控 | 同一考试两名独立测试学员产生真实后端作答状态；PC显示进度、心跳、剩余时间及提交/批改变化。 |
| 统计与导出 | 准备本机构/外来、初级/高级、未开考、进行中、待批改、未通过、通过及补考样例，人工核对人数、分母、最高分和分榜。 |
| 兼容与权限 | 现有固定卷员工流程回归；管理员权限、停用/改密吊销、读取范围及历史查看回归。 |
| 学员基础API | 登录/刷新/退出/改密、本人资料与头像、课程/考试分页、推荐配置、历史/结果/解析/错题，覆盖本人隔离与失败恢复，不以API通过代替H5体验验收。 |

测试与风险匹配：后端构建与关键规则测试、前端类型检查和构建、独立测试库中的 API 闭环、PC 浏览器实际操作。验证优先覆盖新增边界，不靠重复运行全部检查代替缺失场景。禁止把 e2e 重建数据库脚本指向开发库。

本期“后端闭环通过”不等于“独立 H5 已验收”。下一期再验收四底部导航、移动端选图、内联播放/全屏、锁屏、微信浏览器及手机弱网体验。
