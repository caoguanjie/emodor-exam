# COS 媒体存储、上传续传与存量迁移设计

日期：2026-10-26。状态：用户已授权在独立 worktree 按 Astra 实施；后续明确采用 gooodwork 的 COS 短期链接方式，替换原 EdgeOne 建议。源码与自动化不等同真实云或上线验收。对应计划见 [COS 媒体集成实施计划](../plans/2026-10-26-cos-media-integration.md)。

## 1. 目标与已确认范围

主要目标是将反复播放视频、展示图片产生的文件流量从业务服务器移出，为集中培训、集中考试的数千在线用户准备独立分发链路。当前没有后端容量压测，不能把 COS 接入成功等同于数千并发已通过。

用户已确认：

- 沿用 gooodwork 当前 COS 桶；两个项目的数据各自在自己的数据库中保存。
- 按用户后续修订，两个项目共用 gooodwork 已有的同一套 COS `SecretId/SecretKey`；本地 COS 和媒体后端参数保存到 RuleExam 根目录 `.env`，由现有本地启动机制加载。
- 尽量借鉴 gooodwork 的媒体表结构和上传、确认、绑定、访问、回收交互。
- 本地已有图片和视频一并迁移；大文件上传断点续传同期集成。
- PDF/DOCX 资料原件暂不纳入本次 COS 迁移，保留当前存储和历史依赖。
- 执行方式由用户指定为 `astra-workflow`：根代理按依赖和文件归属编排并行工作，整个项目不经过 SDD。
- 读取沿用 gooodwork：当前权限校验后签发 COS GET 短链，默认300秒；用户已接受已发链接在有效期内仍可访问。有效期可配置至3600秒，PC/H5长视频必须自动续签并保持位置，不把链接有效期当作观看时长。

| 业务 | 本次范围 | 访问边界 |
|---|---|---|
| 课程课时视频 | 新上传、已有文件、历史版本文件、PC 管理预览、移动学员播放 | 管理预览与实名学员播放分别授权；保留当前版本及上下架检查 |
| 题目图片 | Tiptap 题干、选项、解析，以及历史试卷、记录和错题的同一资源 | 保留精确题目版本/题单 item 引用及考试阶段授权 |
| 课程封面 | 新上传与存量 | 保留课程访问规则 |
| 学员头像 | 本人上传与管理员代传、新上传与存量 | 保留目标学员、上传者和最终绑定检查 |
| Logo、轮播图 | 新上传与存量、PC/H5 展示 | 只公开当前站点配置白名单中的资源 |
| 实名图片 | 已处理身份证两面、人脸材料的新写入与存量 | 独立私有通道，保留实名处理和访问规则 |

本次不增加文件中心、视频转码、多清晰度、直播、离线观看或秒传。课程 MP4/H.264、有音轨时 AAC 的现有格式约束继续有效。Excel/TXT 题库导入、学员导入、AI 参考题仍临时处理；解析后的数据按现有规则入库，不新增长期原件归档。PDF/DOCX 原件、解析产物及旧阅读保持现状，不因此恢复已退场的文档直接出题接口。

## 2. 复用方式与适配边界

gooodwork 提供参考实现，不作为 RuleExam 的运行依赖。其 Python 服务不直接移入 NestJS；不调用其业务登录、上传 API 或数据库。

| 参考能力 | 本项目采用方式 |
|---|---|
| 对象位置、版本、ETag、CRC64 等元数据 | 在现有 `media_asset` 上增量补充；不存临时签名 URL |
| 上传申请、直传、完成确认 | 新增持久上传会话；前端使用统一上传服务 |
| 上传与业务保存分离 | 上传成功只取得资源 ID；业务保存事务建立 `media_reference` |
| 临时资源回收、失败删除重试 | 保留 RuleExam 引用保护，补充未完成上传与临时 COS 对象回收 |
| 私有访问、临时访问地址 | 复用既有 owner policy，每次申请/续签先核对授权，已签链接在有效期内由 COS 验签 |

保留 `media_asset.id` 的 BIGINT/十进制字符串协议，以及 `owner_id`、`uploaded_by`、`purpose`、`sha256`、`duration_ms` 和现有业务引用。上传会话可用 UUID，但不能替换业务资源 ID。课程、题库和冻结快照不写 COS 地址，不改写历史业务 ID。

不直接照搬 gooodwork 的租户字段、招聘业务引用、扫描结果枚举或可信上传旁路。其普通直传完成确认主要核对 HEAD 元数据；本项目继续实际检查图片内容、视频格式和时长。现有 SDK/供应商能力不等同于恶意文件扫描已部署。

## 3. 存储隔离和配置

同桶采用项目、环境前缀，例如 `ruleexam/prod/` 和 `ruleexam/dev/`。实际前缀在部署前核对，禁止与 gooodwork 已用键空间重叠。RuleExam 与 gooodwork 的业务后端使用同一套 `COS_SECRET_ID/COS_SECRET_KEY`，不再为 RuleExam 单独申请长期访问密钥。共享凭据可能具备两个项目范围的云权限，不能宣称长期凭据在云端相互隔离；RuleExam 适配器必须在调用 SDK 前拒绝本项目前缀外的键，客户端临时授权继续严格限制为本次 staging 文件。

前缀内部区分：

- `staging/`：前端直传的临时对象，按上传会话生成随机键。
- `media/`：校验后发布的正式对象，每次创建唯一键；前端没有写权限。
- `identity/`：由服务端处理、保存的实名材料，不进入普通分发通道。

暂存和正式对象均私有。公开品牌图由业务白名单控制公开访问，不把整个目录或桶设置为公开读。共享长期 SecretKey 仅用于两边业务后端及受控本地运维，不返回浏览器、不写入前端包。标准 COS 签名 URL 的 q-ak 是签名身份标识，不能把它与 SecretKey 或可直接使用的完整凭据混为一谈；完整签名 URL 仍不得入日志或业务持久数据。STS 下发和简单上传签名仍限于单次任务，不把共享长期权限整体交给客户端。

本地配置沿用现有 `scripts/backend-env.mjs` 和 `server/package.json` 的 `env:init/env:check/start:local`：真实共享 COS 密钥、桶、地域、RuleExam 前缀、存储/分发驱动及媒体后端参数写入根目录 `.env`（权限 0600、Git 忽略），后端通过 `node --env-file=.env` 注入 `process.env`，业务服务不再自建另一份配置文件。迁移和真桶检查命令也从同一根 `.env` 加载。显式进程环境覆盖文件的优先级延续 Node 既有规则，检查只报告键名、存在性及覆盖情况，不输出值。

在 `deploy/.env.example` 同步变量名、空占位和说明。实施时增加仅导入 COS 白名单的配置合并步骤：从明确指定的 gooodwork 环境文件读取 `COS_SECRET_ID/COS_SECRET_KEY/COS_BUCKET/COS_REGION`，写入本项目 `.env`；不复制 gooodwork 的数据库、JWT、加密密钥、`COS_KEY_PREFIX` 或整份文件，不生成或轮换 COS 密钥。即使 `.env` 已存在，也能原子合并这些指定键并保留其他配置，重复执行幂等。RuleExam 的前缀仍单独设置，真实值不进文档、示例或提交。共享 COS 密钥将来轮换时两边配置同步更新；本次不执行轮换。

本地代码中的 COS/媒体参数由上述 `.env` 读取；浏览器构建只使用公开的媒体域名字段，任何长期密钥都不能使用 `VITE_` 前缀。运行在 local 模式时仍支持现有开发/测试链路；明确配置为 COS 时缺失配置必须启动失败，禁止静默回落本地造成数据分散。生产环境继续由部署平台注入，不要求把本地 `.env` 提交或复制进镜像。

共用桶的 CORS、清理规则等变更必须先读现有配置，按最小范围追加并验证 gooodwork 访问。不得直接覆盖桶级配置，不要求为本项目开启或关闭全桶版本控制。若桶已有版本控制，写入后记录实际 `version_id`，读取和删除指定版本；未开启时使用唯一且不可被客户端覆盖的正式对象键。

## 4. 数据模型

### 4.1 媒体资源与业务引用

`media_asset` 增加以下概念字段，准确类型和命名由实施计划对齐 gooodwork 的通用字段及本仓库约定：

- `storage_provider`：`local | cos`，存量默认为 `local`；按行路由读取，不使用一个全局开关解释全部历史数据。
- `cos_bucket`、`cos_region`、`cos_version_id`：COS 对象定位；local 行允许为空。
- `etag`、`crc64`：供应商对象元数据；不能替代已有正文 SHA-256。

`storage_key` 保留为后端管理的定位键。`sha256` 继续表示服务端实际核验的文件正文摘要。`processing/ready/failed/deleting` 对外与内部语义保持兼容。保留 `media_reference(asset_id, owner_type, owner_id)` 的精确引用、事务绑定及删除保护，不增加能绕过引用检查的“持久化布尔开关”。

### 4.2 上传会话

新增 `media_upload_session`，用于可靠恢复一次直传，不要求在还未取得真实哈希时预造媒体资源行。至少记录：

- 会话 ID、操作者、业务拥有者、用途、客户端请求 ID。
- 原文件展示名、声明类型、声明大小、客户端文件指纹；客户端值不是可信媒体事实。
- 桶、地域、临时对象键、COS multipart UploadId（小文件可为空）。
- 状态、创建/过期时间、最近进度时间、后台处理 claim/lease、失败分类。
- 后端候选正式对象键、最终 `asset_id` 与完成回执，供故障恢复和幂等查询。

状态为 `uploading → finalizing → completed`，另有 `failed/aborted/expired`。状态变更由后端仲裁。`(uploaded_by, client_request_id)` 唯一；相同请求重放返回同一会话，不同文件或用途拒绝。恢复与查询必须校验操作者和当前上传权限，不能凭文件指纹查询他人的上传。

设计默认：上传会话有效期 24 小时，完成回执保留 30 天；这属于本设计的技术默认值，允许配置。超过回执期限的旧请求返回受控过期结果，不能自动再次创建资源。清理上传回执不删除正式媒体或业务引用。

新增迁移必须使用当前仓库的下一可用编号；不预占 029，不修改既有 checksum。实施时同步迁移、`database/init.sql`、entities 和设计分册。

## 5. 上传与断点续传

### 5.1 前端交互和端别

PC 大视频提供进度、暂停、继续、重试、取消。刷新/重新打开页面后，用户重新选择同一文件；按文件内容指纹、大小和原会话核对后恢复，不仅凭文件名匹配，不承诺浏览器关闭后继续后台上传。

默认小文件简单直传；大文件分块直传，建议初始阈值 16 MiB、分块 8 MiB、每文件并发 3，均为技术默认值。实际限制仍由 `/media/limits` 返回，视频默认 512 MiB、图片默认 10 MiB。续传保留已成功分块，失败只重传缺失或失败部分；临时凭证过期重新申请同一会话权限。

PC 为视频续传的本期验收端。H5 普通图片采用相同会话服务的简单直传；小程序图片先保留现有受控上传接口，由后端保存到 COS，保证现有能力连续。小程序大视频上传不属于现有业务，本次不新增。实名图片继续走现有服务端处理接口，不把未经处理的原图改为通用前端直传。

### 5.2 API 交接

路径为设计建议，全部沿用 `/api/v1` 及 `{code,message,data}` 信封、严格 DTO：

| 操作 | 建议端点 | 行为 |
|---|---|---|
| 创建 | `POST /media/upload-sessions` | 当前上传权限检查，创建/重放会话；返回会话、上传模式、分块参数和有效期 |
| 查询/恢复 | `GET /media/upload-sessions/:id` | 返回当前状态和可信已上传分块摘要；completed 返回同一资源回执 |
| 临时授权 | `POST /media/upload-sessions/:id/credentials` | 重新检查权限，仅授予本次临时键和所需上传操作的短期权限 |
| 完成 | `POST /media/upload-sessions/:id/complete` | 后端核对分块并完成临时对象，幂等进入 finalizing；异步返回处理状态 |
| 取消 | `DELETE /media/upload-sessions/:id` | 原子仲裁取消；停止新授权并安排临时对象/分块清理 |

后端初始化并记录 multipart UploadId；前端使用官方 SDK 分块原语上传和查询指定任务，不自行新建一个不受会话管理的上传。分块合并和业务完成确认由后端控制。前端临时权限不得包含正式目录写入、任意对象删除或全桶枚举；清理 multipart 由后端完成。

complete 响应丢失时先 GET 对账，不能换会话重传或创建第二个媒体资源。completed 返回既有 `asset_id/status/duration_ms` 语义。原 `/media/upload` 保留给实名之外的受控兼容调用、小程序图片和本地驱动；共用同一校验、保存、引用生命周期。

### 5.3 完成确认与不可变发布

```text
客户端直传临时对象
  → 后端合并/确认临时对象
  → 下载到受限私有临时文件，校验实际大小、正文 SHA-256、图片/视频内容
  → 将已校验的同一份字节写入客户端不可写的正式对象
  → 核验正式对象完整性
  → 数据库发布 ready 资源并保存会话完成回执
  → 业务表单保存时绑定 media_reference
```

不能把 HEAD 类型、ETag、客户端哈希或自定义元数据头当成正文校验。正式对象取自已经校验的本地临时文件，不能在校验完成后重新复制可能被客户端改写的临时对象。正式对象发布前回读并核对 SHA-256；保留大小、ETag、CRC64 和版本元数据。视频时长来自现有探测服务，不信前端传值。

后端检查会产生一次性上传处理流量；高频观看、展示的文件字节由分发层承担。后台处理有持久 claim/lease，实例只领取有限任务，初始每实例并发 2；实例重启能继续处理，不仅使用内存队列。超大对象在流式读取到上限时中止，临时文件有清理保障。

complete、取消和清理在会话行锁下仲裁；开始发布后取消返回当前状态，不能边发布边删。正式对象已写但事务未提交时按会话候选键恢复，禁止重复造资源。每次处理 claim 使用自己的唯一候选键，持久记录候选及核验结果；过期 claim 的迟到任务不能覆盖已发布对象或提交资源。最终事务重新核对会话所有权、处理 claim 和允许发布状态；完成回执与资源行同事务保存。处理失败不产生可绑定资源，临时和未引用候选对象进入可重试清理。

## 6. 授权读取与独立分发

### 6.1 必须保持的行为

- 学员视频：实名、启用账号、普通 mobile employee、published/current version、ready 和精确引用检查。
- 考试题图：按 item、本人记录和阶段授权；在考只读题干/选项，解析另按结果阶段开放，纯 timeout 拒绝。
- 管理预览：保留 PC Bearer 权限，不能使用 learner-only 视频签票入口冒充学员。
- 品牌图：每次请求品牌入口先检查当前白名单、ready branding 和site_config引用，再跳转短链；已发短链仍有有效窗口。
- 实名图：只允许原专用用途和主体；继续受控预览及服务端读取，不签普通COS直链。

这些规则适用于每次签发/续签及代理读取；已发COS链接在期限内仍可能可读，不承诺追回浏览器已接收/缓冲的字节。

### 6.2 与 gooodwork 一致的 COS 短期链接

```text
PC/H5 申请或续签媒体地址
  → RuleExam 校验当前账号、权限、状态与精确业务引用
  → 服务端按准确桶/地域/对象键/VersionId签发短期GET
  → 浏览器直接向私有COS取字节（支持Range）
  → 到期前重新申请；视频保留当前位置与原学习会话
```

不需要 EdgeOne、新媒体域名或额外长期密钥。`MEDIA_DELIVERY_MODE=proxy|cos-signed` 默认proxy；切换后，仅COS正式普通媒体返回签名直链。local和实名图继续原受控代理；COS身份目录和staging不对普通内容API签名。

`MEDIA_READ_URL_TTL_SECONDS` 与 `MEDIA_VIDEO_URL_TTL_SECONDS` 默认300，范围1—3600秒。5分钟限制链接有效期，不限制视频时长；长视频依赖客户端续签。延长配置也会延长旧链接的有效窗口，不能宣称撤权立即生效。签发与续签每次复核现行授权；停用、下架、换版、题图阶段变化后拒绝新链接，已发链接到期前仍可能可用。代理内容仍每次检查授权。

签名使用官方SDK的实际GET参数与准确版本；`VersionId` 必须进入被签名的query，不依赖错误或不完整的类型声明。SecretKey/JWT不出现在URL中。私有响应使用适当的Cache-Control；品牌由原 `/site-config/assets/:id/content` 检查当前白名单后307跳到短链，跳转本身no-store，禁止拼接公开桶路径。

PC `POST /media/:assetId/preview-ticket` 与学员票据区分；批量 `POST /media/tickets/batch` 限50项，逐项按 `asset_id + owner_type + owner_id` 授权并保留位置，同一asset不同题单不能复用许可。PC代理短票读取复核账号/权限/authVersion/jti/session；不改变旧mobile代理票据原有登出语义。

前端精确放行配置的 `VITE_COS_MEDIA_ORIGIN`（标准HTTPS桶域名）和 `VITE_COS_MEDIA_PREFIX`（正式media目录），拒绝其它项目、identity/staging、相似域名、编码路径绕过与未知query。COS签名URL不保存到作者JSON、localStorage或业务表。品牌仍调用原站点配置入口；CSP和小程序合法域名按真实桶域名配置。

PC/H5在URL临期或授权地址失效时单飞续签，最多一次有界网络重试；成功换src后恢复位置与暂停/播放状态。失去业务授权时停止并明确提示，不能继续补时、重建学习会话或换asset绕过。H5 30秒心跳、45秒封顶与95%覆盖规则完全保留。

COS 同一秒内可能返回相同 URL 和到期时间。正常播放遇重复票据不重新加载、不进入等待 metadata 的恢复态；等待至少一个签名时间粒度后最多再申请一次，仍重复则明确失败，不能按剩余时间的一半无限追赶。网络错误恢复也遵守该限制并保留原学习 session。1 秒这类极短 TTL 可能出现短暂缓冲窗口，不承诺无缝播放，也不偷偷延长签名期限。

真实只读检查发现，共用桶当前为 public-read。RuleExam 的正式写入、迁移、multipart 初始化和 simple 暂存 PUT 都必须显式设置对象 ACL private；simple 的该请求头还须纳入签名。实际小文件探针已验证匿名读取拒绝，不需要把整个 gooodwork 桶改成私有。历史对象权限不由本次推断或批量修改。

gooodwork网页当前附件播放器只消费既有src，没有自动续签；原生App缓存链会先完整下载。已核对源码和窄测试，但既有测试没有证明真实长视频跨过期与拖动可用。本项目补续签并独立验证，不把参考项目的未覆盖行为当作已验能力。详见独立交互核验记录。

## 7. 生命周期与清理

沿用现有媒体引用判断，不能仅按对象创建日期配置全桶删除。课程历史版本、冻结试卷、记录和实名事实仍被引用的资源必须保留。没有业务绑定的完成上传沿用现有孤儿宽限语义；本设计默认宽限 24 小时，业务保存仍按原事务规则检查 ready。

未完成上传过期后停止签发凭证，清理 multipart 和临时对象；需覆盖最后已签凭证仍有效期间的迟到写入，通过过期后再次核对、延后最终清理和后台补偿收口。取消不承诺已发出的云临时凭证立即失效，但这些凭证只能写不可用于业务读取的 staging 对象。

正式删除先在行锁下确认无引用并进入 deleting，再删除准确 COS 键/版本；失败留重试状态，不能提前删数据库事实。只清理 RuleExam 明确登记的对象和会话，不扫描删除 gooodwork 前缀。实名材料继续沿用现有临时/会话/实名事实保护，不新增任意留存期限。

## 8. 存量迁移

迁移是独立、可续跑的运维动作，不夹在建表迁移中执行。数据盘点以 `media_asset` 为权威，不盲扫上传目录并把残留文件都登记成资产。

1. 生成只读清单：资源 ID、用途、状态、引用数、原定位、文件存在性、大小和原 SHA-256；包含仍被历史版本引用的 ready 媒体，实名单列私有用途。processing 等待稳定；failed/deleting、缺失和哈希不符项列异常，不伪造修复。
2. 对每条正常 ready 资产上传独立正式 COS 对象，回读核对 SHA-256，记录键、版本和校验结果；不改业务 ID 或媒体用途。
3. 在事务中锁定该资源，确认仍是同一 local 定位、状态及版本，再切换该行存储元数据。删除竞争、源文件变化或状态变化时跳过并报告，不强制覆盖。
4. 业务验证覆盖课程播放/拖动、题图、历史记录、头像、封面、品牌和实名预览。迁移进度、成功/失败和回退定位存入受控运维记录，不入代码仓库、不含凭据或访问签名。
5. 本地原文件保留为回退副本；用户另行批准前不删除。已迁移资产可按清单验证本地副本后回退定位；新 COS-only 上传不存在本地副本，不能把全局切开关宣传为完整回退。

迁移与新上传通过按行驱动和独立对象键并存，不需要停写全部业务。重复运行复用已经核验的结果，不能覆盖任何 gooodwork 对象或重建历史媒体 ID。PDF/DOCX 的 `regulation_version.file_path` 不在本迁移范围。

## 10. 设计建议、部署依赖与后续交付

上传会话有效期、分块参数、回执期限和后台并发是本设计默认值。用户授权按Astra实施，并后续明确选择gooodwork的COS短链；原EdgeOne建议已被替换。默认300秒、可配置至3600秒与自动续签不代表真实供应商/长视频已验收。

执行采用 Astra 依赖队列和稳定工作线：上传、读取签名、迁移工具在基础接口就绪后并行；PC 上传与读取的共同文件由同一 owner 顺序维护，移动端可独立并行。根负责共享注册、接口裁决和最终集成；独立验证/审查按风险与阶段安排，不走 SDD 的固定逐任务流程。具体并行批次、容量和唯一写入者见对应实施计划。

实施前的部署核对包括：实际桶/地域/已有前缀、共享 COS 凭据的现有权限及 STS 能力、根 `.env` 的配置导入与加载、现有桶权限和版本状态、RuleExam页面测试/生产来源、COS跨域规则及小程序合法域名。可先做代码与自动化；本地真桶联调和迁移复用根 `.env`。新增权限若确有需要，应在保留 gooodwork 现有权限的基础上形成具体差异，不静默收窄或扩大共享身份权限。任何云配置修改或新增服务费用都必须形成具体配置变更后再取得授权，不能借本设计自动操作 gooodwork 资源。

实施时同步更新设计 02/03/04/05/06/07、README 对照、媒体冻结契约相关条款与独立验收记录。当前设计 02 的 AD-06 写明“不引入对象存储”；本提案批准后才据此改为 local/COS 双驱动及受控分发。改动不覆盖现有并行题库/UI工作；只提交本任务明确文件。
