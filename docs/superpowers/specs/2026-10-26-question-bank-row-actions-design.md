# 题库状态开关与逻辑删除增量设计

日期：2026-10-26。用户明确要求：启停采用学员管理同款开关，操作列仅“预览／修改／删除”，缩窄并居中；随后选择逻辑删除、保留历史，并授权先备份本地开发库再执行新增 029、重启本地 API。沿用当前 main，不新建工作树，不提交或推送，不涉及生产。

## 已确认范围

- 状态列使用带“启用／停用”文字的开关，宽度约 100 px，开关约 68 px；操作列表头、按钮组居中，宽度 180 px。
- 用户15:20追加独立题型／难度Tag列，15:32进一步要求六色、基础Tag外观和更紧凑列。本次采用单选蓝／多选紫／判断青，未知灰／简单绿／困难红；列宽84／80px且居中，Element Plus light Tag为4px小圆角、1px边框、浅底，不可点击。只在Questions局部恢复Tag外观，不改全局胶囊样式或导入预览。原标签、历史medium-warning和未知事实保持；“高”沿用现有“困难”名称，不改难度数据或启用目录。
- 开关直接保存，不弹确认框；保留服务器确认值，逐题 loading 与权限控制，同一题的启停、修改、删除互锁，其它行仍可操作。
- 操作“修改”复用现有人工 Tiptap、版本与启停并发校验，不重写编辑器。上一增量的简单／困难启用目录过滤继续有效。
- 删除需二次确认；逻辑删除从所有题库列表和新候选中消失，不能再用开关恢复或修订复活。不建设回收站或恢复已删接口，不物理删除题目、内容版本、媒体引用、试卷关联、发布快照或考试记录。
- 草稿已有引用继续可见并阻断新发布；已发布 release、已有个人题单、结果、历史旧卷首次开考继续读原事实，不套用当前题库的删除过滤。

## 存储与写入合同

`question.deleted_at` 为普通可空 `DATETIME(3)`，实体属性 `deletedAt:Date|null`，不用会隐式过滤历史读取的 `DeleteDateColumn`。既有行默认 NULL。追加 `029_question_soft_delete.sql`，线性接续 `026_question_lifecycle_slimming/add_question_enabled` 的完整有效探针，保留旧迁移和 checksum；初始化 SQL、实体和 03 册同步。不改原启停列和历史内容字段，不清理任何行。

`DELETE /api/v1/ai/questions/:id` 使用现有 `questions:write` 权限及严格 DTO：

```text
body = { expected_version_id:string|null, expected_enabled:boolean }
data = { question_id:string, deleted:true, deleted_at:ISO字符串 }
```

`expected_version_id` 必须显式出现，legacy 可为 null。事务锁定身份后先检查已删幂等回执，否则同时核验版本与启停基线，冲突为 40940、零写入。成功只写 `deleted_at` 与 `is_enabled=false`，不增 revision；只首次成功记录审计。重复 DELETE 返回原删除时间，不改内容或重复审计。

当前列表始终过滤 `deleted_at IS NULL`，当前详情已删返回 40401；版本 history 及授权历史读取保留。编辑、带身份 authoring commit、恢复启用、当前候选与新发布在现有锁／事务内显式拒绝已删，不能只依赖页面过滤。删除和发布遵循同一身份锁，允许先发布后删除，但发布快照不能变化。

## 前端请求与未知响应

启停沿用 `PUT /ai/questions/:id/enabled`，body 为 `enabled + expected_version_id`，成功返回完整 QuestionView。删除通过 Axios `delete(url,{data:body})`，收到合法回执后刷新列表；删最后一行时退到上一有效页。

所有写入只发送一次。丢失响应先 GET 当前详情：返回题目则应用其当前版本／启停；删除后 40401 表示该题已不在当前题库。读回失败保留未知提示和该题写入锁，待用户刷新核对，不自动重复 DELETE/PUT。延迟结果按题目 ID 更新，不覆盖其它行、其它页或已打开编辑草稿。

## 与旧设计的关系

本增量覆盖 03 册“题库通过停用、不引入 deleted_at”和原[题库瘦身设计](2026-10-26-question-bank-slimming-design.md)仅有启停的范围；未改变其不物理删除历史、不建回收站、题库无分值及冻结考试的约束。其它会话的录题底栏、导入模板、COS 计划和画板改动继续保留。

## 验收

- 行内开关、三项操作、180 px 居中、只读禁用、逐题互锁、未知响应 GET 对账均有真实组件测试。
- 后端测试固定逻辑删除、双令牌冲突、重复幂等、旧 revision／媒体／快照保留和不能复活。
- 029 在自有隔离数据库验证升级、重跑、DDL 后续跑、结构漂移拒绝及旧行／旧登记不变。
- 隔离 HTTP 验证删除前后列表、详情、候选、草稿发布和历史；本地开发库先私有备份，再用登记匹配的真实 022 制品走原正式 runner。
- 浏览器只对明确命名的自建验收题操作，绝不删除用户既有题；自动化、PC 与生产证据分别记录。
