## 4. 用户操作路径与界面保真

```text
题库 → 人工录题／编辑题目
         └─ main 现有表单 → 原有创建／修订／审核流程
              └─ 难度配置 + schema 3 无损数据适配

AI／导题队列 → main 现有处理与编辑入口

试卷列表 → 创建培训试卷 → 固定组卷 → 创建草稿
                                      └─ PaperDesigner 全屏弹窗
                                           ├─ 保存 → 留在设计器
                                           └─ 关闭 → 草稿详情 → 原有发布流程

已有固定草稿 → 编辑试卷 → 同一 PaperDesigner
随机卷      → 原有抽题规则配置
```

### 4.1 main 既有题目表单

- 新增与编辑题目继续使用 main 现有表单、字段、上传位置和操作流程；三种客观题的创建、修订和审核仍遵循 main。难度选项与标签接入集中配置，不借适配增加独立设计器按钮或路由。
- `PaperDesigner` 产生的 schema 3 题目也可能从原有题库入口编辑。表单界面保持原样，数据层须保留未改字段的富文本、稳定选项 ID、图片、布局及作者映射，不能把整份内容经纯文本字段重新序列化。
- 只改难度等属性时，保留未变正文及原稿，并同步相应属性；修改题干、选项、解析、答案或映射时，必须同步生成新版本的作者原稿与受控考试内容。禁止只更新考试内容、重开设计器却仍读到旧原稿。
- 某次修改无法由既有表单无损转换时，明确定位不支持的内容／字段，阻止保存并保留全部输入，允许取消或调整修改。不得静默打平、删除节点、重置布局，或自动切换为试题设计器。
- 具体无损规则见 §6.4，保存事务与版本规则见 §7.1；原有 AI／导题队列入口保持 main 的处理流程，不新增“保存并下一题”设计器工作流。

### 4.2 试卷设计器

- 保留来源三栏布局：左侧三种新增题型及试题库／试卷库，中间纸张与可编辑标题，右侧题目属性／试卷设置／模板设置。
- 保留完整工具栏、题块拖拽手柄、删除、添加选项、正确答案标记、库搜索分页、加载态、空态和失败重试。
- 保留正文格式、排版、撤销／重做、光标处插图和保存状态；右侧保留题目属性、答案摘要、富文本解析及其插图动作。支持单选、多选、判断，含图片不产生新题型。
- 正文使用一个 Tiptap 实例承载多道题；右侧解析可使用独立富文本实例。保留来源的 100 题限制和跨题结构保护。
- 创建成功的固定草稿进入 `/admin/papers/:id?scope=training&designer=1`。关闭设计器回到当前草稿详情，不重新创建试卷。
- 从试卷库载入：当前无题时直接载入；已有题时提供追加、整卷替换、取消。追加保持当前标题和配置；替换采用来源内容与配置，但保留当前草稿 ID。
- 全卷同培训类别、同版本不重复、同考点不重复，保存前总分符合 main 现有固定卷规则。追加失败整次不生效。
- 有题时不能直接改变试卷类别。切换题型后若原考点不再符合 main 的题型约束，明确提示重新选择／清空考点，不自动建立跨题型关系。

### 4.3 试卷设计器的保存、关闭与只读

- 保存成功必须指完整保存链路确认成功，不能仅因题目入库就显示试卷已保存。
- 未保存离开有保护；异步载入、上传、翻页、关闭以会话标识避免旧响应覆盖新状态。
- 图片上传占位只在内存，成功后替换为受控资产节点；未完成上传禁止保存，失败可在原位置重试。
- 保存结果不明时先查询原请求回执，不换新请求重复创建题目。
- 只读模式不可通过工具栏、选项点击、快捷键、拖拽、粘贴或图片上传修改内容。试卷只读状态与入口沿用 main 权限，不新增独立只读设计器页面或权限绕过。
- 顶部撤销／重做保留来源现有正文历史范围；题目增删、整卷替换和元数据修改不承诺新增全局撤销栈。

## 5. 两档难度与历史兼容

### 5.1 集中配置

服务端维护唯一权威目录，含 `code`、`label`、`enabled`、`sort`。初始为简单 `easy`、困难 `hard` 启用，历史 `medium` 可识别但停用。数据库继续使用字符串编码，不能用 `is_hard` 布尔值替代。

管理端通过权限受控的只读选项接口获得启用目录，既有题目表单、试卷设计器、AI 表单、导入和抽题设置复用它。前端可保留类型／历史标签映射，但不能各自决定启用状态；服务端保存、审核入池和发布再次校验。接口为 `GET /admin/questions/authoring-options`，接受 `questions:read OR questions:write`，且只返回非敏感目录元数据；这保留现有 write-only 录题员能力，但不授予题库内容读取权限。

随机卷继续 main 当前的 `institution → easy`、`external → hard`，固定卷继续允许两档混合并记为 `mixed`。增加新档位时，集中配置、来源抽题映射、题池完备性、导入、统计和测试一起调整；仅加一个下拉选项不算完成扩展。

### 5.2 行为矩阵

| 场景 | 设计行为 |
|---|---|
| 新建、修订、AI 生成、文件导入 | 只接受启用难度；模型输出不能覆盖请求指定值 |
| 新固定卷选题、新随机题池、新发布 | 只采用启用难度和合法当前审核版本；不可偷偷替换难度凑题 |
| 旧 medium／未知题目 | 列表与历史保留原值；载入时提示待分类，新增修订提交前由管理员明确选择简单或困难 |
| 已含 medium 的固定草稿 | 保留草稿可读，显示受影响题目；不得静默删除，完成管理员修订和重新选题后才能新发布 |
| 已发布 release／已有 assignment／历史成绩 | 沿用原快照和 main 现有规则，不重分类、不重抽、不重新评分；复制为新草稿时走当前启用规则 |
| 历史统计 | medium／mixed／unknown 保留原口径和可读标签，不归并到简单或困难 |

“新修订只能两档”不表示允许覆盖旧版本；旧版本及其历史引用保持原样。旧题重新分类后的审批流程沿用 main，不因本次改为两档就自动审批。

实施前只读盘点 `medium`／未知题目、草稿及发布引用、历史统计维度，并提供影响清单。没有实际盘点前，不宣称不存在旧题，也不执行批量改值。

## 6. 数据模型与内容保真

```text
PaperDesigner（共享 QuestionDocumentEditor / Tiptap）
            │
            v
完整作者原稿 + 题目业务属性 ← main 既有表单的无损数据适配
            │ 服务端校验、稳定选项映射、版本锁、同步生成
            ├─ 作者原稿随题目版本保存 → PC 试卷设计器重开继续编辑
            └─ 受控考试内容 schema 3
                   → 发布冻结 → 个人题单冻结
                   → 安全题面投影 → main mobile 独立渲染
```

### 6.1 作者原稿

- 保留来源 `QuestionAuthoringDocument` 的正文、题目映射和解析；三客观题以外的业务类型、rubric 和图片答案字段不进入新契约。
- 题目不可变版本增加可空的 `authoring_schema_version`、`authoring_json`，原稿包含该题完整可编辑内容与单题布局设置。旧版本不回填；首次实际修订时按其真实内容生成新原稿。
- 主表继续指向当前版本，作者原稿不在 `question` 和 `question_version` 双写两份。管理端装配从精确版本取原稿；旧题缺原稿时只转换已存在事实，不凭空补格式、答案或身份。
- 试卷增加管理端布局 JSON，持久化纸张规格、方向和边距等“模板设置”；题单仍以有序 `question_version_id` 关联为权威，不再存一份可漂移的整卷答案副本。
- 布局变化进入未保存状态，保存后重开一致；纸张布局仅控制 PC 设计器，不把 A4 固定宽度强加给学员手机。
- “模板设置”是当前文档布局，不等同于来源旧 `question_template` 库。来源公开设计器中未使用的模板 CRUD、AI 任务和通用表单能力不为方便复制而迁入。

### 6.2 考试内容与渲染

main schema 2 只接受 `doc/paragraph/text/hardBreak/image`，明确拒绝 marks、表格及任意样式。将完整编辑内容直接写入旧模型会失败或丢格式，因此本设计建议新增内容 schema 3：

- 保持 `stem`、`options[{id,content}]`、`analysis`、`answer_option_ids` 的结构和稳定 ID 评分含义。
- 扩展受控的段落／标题／引用／列表／代码块／分隔线／表格，以及加粗、斜体、下划线、删除线、上下标、字体字号、颜色和高亮等来源编辑器实际开放格式。
- 对齐、缩进、行距、字体、颜色、表格合并等属性使用明确枚举或数值边界，不接收任意 CSS、HTML、DOM 属性、脚本、事件、URL 或嵌入资源。
- 图片只保留 `asset_id`。作者原稿中的媒体节点转换为受控内容节点，不能携带外链 `src`、对象 URL、本地路径或 JWT。
- 管理端编辑涉及的题块、控件、选项身份和正确标记不作为学员交互节点下发。来源支持的普通展示控件若在当前工具栏可插入，必须明确转换为不含管理属性的静态内容；不能把 `checked`、`correct` 等属性透传。没有已定义、可保真转换规则的节点拒绝发布并定位原因，不能静默丢掉。
- 实施时形成“工具栏命令 → 作者节点 → 考试节点／属性 → PC/mobile 渲染 → 安全测试”的清单；`PaperDesigner` 及其共享编辑组件实际开放的内容操作必须全部覆盖。未完成这一清单及兼容验证，不能宣称原样集成完成。
- 学员端不引入 Tiptap 编辑器，继续使用独立只读内容组件；增加受控节点渲染，表格在窄屏允许水平滚动，字体以受支持回退字体展示，文字和图片语义不能丢失。
- 旧 schema 1／2 的存储、校验和冻结内容语义继续兼容，不把已有快照批量升级为 schema 3。试卷设计器新建或修订的完整富文本采用 schema 3；既有表单的普通新增沿用 main 当前内容路径，编辑 schema 3 题目须保持其版本语义及无损原稿，不能降回 schema 1／2。历史读取按原版本适配。

这部分会扩展现有内容白名单，是设计中的明确兼容工作，不允许直接放宽 schema 2 校验。内容大小、深度、表格复杂度和节点数量必须有界，具体阈值由实施者依据来源约束和 100 题回归确定。

现行 `review/2026-10-22-learner-mobile-contract-freezes.md` 的原句是“文本节点不允许 marks”及“禁止任意 `src`、HTML、链接、样式、事件属性、答案标记和管理元数据”。schema 3 是本设计提出的版本化扩展，不把旧白名单当作已解除；只有受控展示格式扩展，资源、脚本、答案与管理数据禁令继续生效。进入实施时须同步新增内容合同及版本选择规则，不改写旧 schema 2 的冻结含义。

### 6.3 稳定选项 ID

- PC 本地 `client_id` 只用于定位题块；考试答案使用 main 的稳定选项 ID，界面 A/B/C 是显示顺序，不是数据库身份。
- 已有题目的选项 ID 在载入、排序、改变正确答案、普通内容编辑和保存中保持不变；不能因为来源 codec 的长度限制而替换 main 合法的短 ID。
- 新选项创建一次 ID 并随保存请求保持稳定；新增整题副本可以有自己的选项 ID，必须与其原稿、业务内容和正确答案映射一致。
- 来源 `checked` 只用于推导 `answer_option_ids`。保存时校验单选／判断恰一个正确项、多选至少两个，所有答案 ID 均属于本题。
- 来源有“插入时为选项重新生成本地 ID”的代码，必须适配为独立本地身份／稳定身份映射；不能直接把重新生成值当成旧题的数据库选项 ID。
- 既有 legacy key 无效时沿用 main 数据契约错误处理，不随机补造旧身份。没有历史 ID 的真正新题才允许首次分配。

### 6.4 既有表单的无损数据适配

适配以精确版本的作者原稿、考试内容和表单实际修改字段为输入。表单显示值不作为整份富文本的替代来源，禁止使用 `textContent` 或等价纯文本提取打平整份文档；适配器保留未改字段的原始节点、格式、稳定 ID、图片引用、布局和映射，再把可无损表达的修改应用到该版本。

题干、选项、解析或答案发生修改时，同一套服务端 codec 必须从更新后的事实生成新的作者原稿与受控考试内容，并校验两者的内容、答案映射和媒体引用一致。若表单修改范围与复杂节点的边界无法可靠对应，或转换会丢格式／节点／身份，整个保存请求失败且不创建部分 revision。前端保留输入并展示具体原因，不能以丢弃原稿或仅保存纯文本作为回退。

只有属性修改时，未变内容与布局继续保留，作者原稿中镜像的相应业务属性同步更新；旧版本不变。该适配复用 `PaperDesigner` 的原稿 codec 和服务端校验能力，但不把既有表单宿主换成 `QuestionDocumentEditor` 或独立 `QuestionDesigner`。

## 7. 保存、版本与试卷复用

### 7.1 既有表单的单题保存与版本一致性

新增人工题沿用 main 人工创建并确认的规则；编辑既有题创建新 pending revision，保留旧版本。后续审核继续使用现行审核入口，不用客户端 `approved` 字段越权改变状态。

既有表单沿用 main 现有题目 create／revise API 和版本锁，不切换为独立设计器保存入口；目标版本有作者原稿或 schema 3 内容时，由服务端调用 §6.4 的共享适配能力，在同一题目版本事务内提交新作者原稿、考试内容与业务属性。不能分别成功或留下“新考试内容、旧作者原稿”。

试卷设计器的原稿批量提交契约携带稳定 `request_id`、原稿和精确 `expected_version_id`。既有表单只复用服务端内部的原稿适配与事务能力，仍调用原 create／revise API，不要求切换到批量提交端点。已有版本必须传字符串 ID，旧未版本化题显式传 `null`；仅有来源 `base_revision` 不足以代替 main 当前版本锁。锁内比较失败返回现有冲突错误，不创建新 revision。

保存结果返回本次实际保存的版本身份；使用原稿提交契约时同时返回规范化原稿，前端据此更新下次编辑凭据，不能用之后 GET 到的当前版本冒充本次保存结果。适配失败、内容校验失败和冲突时均保留表单输入。

### 7.2 固定试卷保存

沿用来源的三种身份语义：

| 来源与最终内容 | 保存结果 |
|---|---|
| 试卷内新建 | 创建题库新题并获得版本 ID |
| 库中带入、最终内容未变 | 复用原版本，不制造新题或新版本 |
| 库中带入、最终内容改变 | 另存新题，不修改来源题或其他试卷 |

标准化内容指纹覆盖题面、选项顺序、答案、解析、分值、难度和考点等业务属性；忽略题号、试卷内位置及本地客户端身份。拖拽题目不能触发另存新题，修改后完全恢复原内容应复用原版本。

```text
先校验类别、题数、有效题、重复版本／考点、总分
       → 新题／修改副本一次批量提交（事务 + request_id）
       → 获得精确题目版本回执并更新 bindings
       → 保存试卷配置和布局
       → 保存有序固定题单
       → 全部确认后显示“已保存”
```

保留来源可重试的分步保存，不声称上述多请求天然是一个数据库事务：

- 题目已入库、试卷保存失败时显示明确的未完成状态；保存上下文保留新版本 bindings 和原请求 ID，禁止重复建题。
- 结果未知时先按原 ID 查询回执；未知期间不允许更换请求、继续改稿或应用内离开。浏览器关闭只能给出原生离开提示，不能宣称可以强制阻止关闭。
- 得到完整题目回执后可按来源流程继续保存或明确放弃后续操作；放弃仍保留已入库版本绑定，下一次保存不会再创建同一批题。
- 试卷端在写题单与发布时再次检查当前版本、审核状态、类别、媒体和去重约束，不能只信前端预检。
- 当前不建设跨浏览器草稿恢复系统；整卷恢复、长离线编辑和多人实时协同不属于本期承诺。

### 7.3 提交回执

为试卷设计器保留管理端的原稿装配、批量事务提交和回执查询能力；取消独立试题设计器不取消这些后端依赖，可沿用来源路径：

- `POST /admin/question-documents/assemble`：按授权的精确题目版本装配原稿。
- `POST /admin/question-documents/commit`：校验、锁版本、保存题目／原稿／回执。
- `GET /admin/question-documents/commits/:requestId`：查询当前操作者可见的本次结果。

`question_authoring_commit` 保存操作者、请求 ID、内容摘要和结果引用，按操作者与请求 ID 唯一约束。同 ID 同内容返回原结果，不同内容拒绝；回执与题目版本在同一事务提交，响应丢失不丢幂等事实。回执不保存凭据；无权操作者不能枚举他人提交结果。

## 8. 来源、权限与媒体

- 人工题与试卷内修改副本不能任意指定 `source`、资料版本或审批人；来源字段由服务端按真实来源决定。已有 AI／导入题的管理端装配使用真实版本数据，不能因进入设计器就改成另一种来源。
- 分支右侧的资料来源位置可保留；人工新题显示无来源，已有可信来源按 main 规则只读。不重新启用制度管理下拉或允许伪造 AI 来源。
- 考点继续 main 的权限及同类别同题型约束；筛选器和切换提示由页面适配层处理。
- 设计器不自带登录状态，复用 web 权限与 HTTP 信封。试卷编辑分别检查试卷读写和实际所需的题库读写权限；仅复用题目的行为不能凭组件 UI 绕过服务端权限。
- 图片上传、管理端读图、版本媒体引用、发布冻结、个人题图授权都接 main 媒体链路。签票和读取继续校验精确 `media_reference`，禁止把个人 key 或 JWT 放进 URL。
- 保存／发布扫描作者原稿与规范化内容的受控资产引用；作者专属布局不得扩大在考图片权限。题目可见内容不能引用未授权资产。

1. 旧 schema 1／2 题目能打开；合法稳定选项 ID 在重排及修订中保持，短 ID 不被来源校验误拒绝。

4. 响应丢失、重复点击、同请求不同内容、部分保存失败、版本冲突、重试与关闭保护均有针对性测试。

### 10.3 考试与安全

1. 进行中 payload 任意深度均不含答案、解析、`checked/correct`、作者原稿、管理元数据或未经许可的资源 URL。
2. 学员选项按稳定 ID 提交；单选、多选、判断的评分与空答案规则保持，选项乱序不影响判分。
3. 主动截止前整卷提交、并发重复提交、到期纯 timeout、不自动评分、历史结果兼容均回归。
4. 受控图片继续通过当前移动端媒体票据和业务归属检查；新富文本样式、表格和静态控件不能绕过安全节点白名单。
5. 旧客户端对新内容的升级提示和新客户端对旧快照的显示通过验证；不消耗无效开考次数。

验证按风险选择：服务端构建及相关单测、web 类型检查和构建、mobile 内容类型／渲染回归、隔离 API 全链、PC 与 H5 浏览器实际操作。源码／自动化、桌面浏览器、真机和外部供应商证据分开记录；不沿用旧工作区测试数量冒充本次通过。
