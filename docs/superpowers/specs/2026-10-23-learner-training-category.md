# 学员培训工种统一与首次确认

## 已批准范围

PC「培训类别」与移动端「培训工种」是同一业务事实，权威来源为 `sys_user.category_id` 与 `training_category`。不再把自由文本 `occupation` 当培训工种，不根据旧文本猜测并回填类别。

个人资料与实名认证保留两个入口。导入或 PC 已分配类别的学员只读查看；类别为空的普通移动学员可选启用类别，二次确认后首次保存，之后只能联系有 `students:write` 权限的管理员或监考人员在 PC 修改。

选择器只改变草稿，取消确认不写后端。确认文案：`你选择的培训工种为「{name}」。确认后将用于匹配考试，学员端无法自行修改。如需调整，请联系管理员或监考人员。` 按钮为「返回修改」「确认培训工种」。课程继续沿用现行全 published 浏览和实名播放规则，不因本次工种绑定新增学习门槛。

## 接口契约

- `GET /me/profile` 和资料保存响应新增 `category_name: string | null`，名称从当前类别表解析（即使类别已停用）；`category_id` 保持字符串 ID。
- `GET /me/training-categories?page=1&page_size=100`：仅启用的普通 mobile employee 可用，返回 `Page<{id:string,name:string}>`；分页正整数，page_size ≤100，仅列启用类别，不开放后台类别权限。
- `PUT /me/training-category`：同一身份范围，严格 body `{category_id: 正十进制字符串}`，返回本人完整资料。服务器锁住用户事实并检查类别引用；null→有效类别首次赋值；相同值重复请求幂等返回；已有不同值返回 40001，`data.reason_code=TRAINING_CATEGORY_LOCKED`，不改写任何数据。非启用类别返回现有 40910。
- 普通 POST/PATCH `/me/profile` 继续拒绝 `category_id/source/role/status`；新专用接口不允许修改 source、姓名、实名、权限或他人信息。
- 首选类别与 PC 修改均记录操作者、目标、前后类别审计；不包含姓名、证件或令牌。并发不同首选只有一项成功；并发 PC 修改按用户行串行化。历史 assignment、考试记录和成绩不更新。
- 不新增 schema；旧 occupation 保留兼容，不再由移动页面将其当培训类别编辑。

## 移动交互

- 个人资料读取当前后端类别；未设置时加载真实启用类别（处理分页/空列表/失败），首次明确确认后即时持久化。其他普通资料单独保存，姓名仍由实名流程确认。
- 已设置者显示名称和「如需修改，请联系管理员或监考人员」，无可切换选择器。PC 修改后重新进入刷新可见。
- 保存中禁止重复点击；写请求结果不明时先 GET 本人资料收敛，绝不自动重发写操作。无法读回时保留输入并提示刷新确认，禁止根据旧 null 值继续盲写。
- 「我的」不再显示 occupation 作工种；实名认证与个人资料仍分开。
- 考试页按缺项显示行动指引：缺类别→去选择培训工种；只缺实名→去实名认证；两者缺失先选工种。实名待审核/失败与普通未认证状态区分。加载失败不能误报缺项。
- 已有历史与进行中考试不因当前资料缺项被前端隐藏；无缺项且暂无发布考试保持正常空状态。
- scenario 静态预览继续只用 fixture，不能请求真实接口。

## 验收与边界

服务端测试覆盖权限、严格输入、首选/重放/并发、停用类别、PC 调整与审计、普通资料拒绝越权。移动测试覆盖草稿取消、确认、读回、只读、缺项引导、静态预览。执行类型检查和构建；增加隔离 API/浏览器回归，不访问或重建开发数据库。实际供应商、手机真机和生产部署不是此次本地测试结论。
