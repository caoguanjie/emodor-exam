# 公共题库与单二维码随机考试设计

状态：待用户审阅。本文记录目标行为，不表示功能已实现或已验收。

## 1. 业务目标与已确认规则

固定安全教育机构使用一套公共题库，题目区分 easy（简单）和 hard（困难）。管理员创建一份随机试卷，发布后取得一个二维码。所有学员扫描同一个二维码，登录、完善必要资料并完成实名认证后进入该考试。

- 学员来源由服务端认定：institution 抽简单题，external 抽困难题，前端不能选择或伪造难度。
- 每份试卷配置题型数量、每题分值、总分、及格分、时限和最多考试次数；默认 100 道、100 分、3 次。
- 次数按学员与试卷累计。成功开始一次考试即占一次，超时未交卷也计次；开始事务失败不计次。
- 本次进行中刷新、断线、再次扫码，恢复同一考试记录、题目、顺序和截止时间，不重新抽题、不额外计次。
- 本次结束且次数剩余时，学员可自行再次开始，重新随机抽题。不同考试间允许重题；一次题单内不重复。
- 考完题单停止接受作答，但保留题目快照、答案及成绩，不删除历史记录。
- 培训类别／工种是可选资料，不再作为资料补全、实名认证、考试列表或开考的前置条件。

## 2. 范围与实现原则

沿用 Vue/Element Plus PC、uni-app H5、NestJS、MySQL 和 Redis，以及现有试卷、发布版本、个人考试归属、考试记录和题目快照结构。无需新建班级、租户、报名或复杂场次系统；一份试卷即本期的考试入口。

本期完整范围：PC 随机卷配置、公共题池、发布校验、单二维码入口、登录与实名后返回、来源分难度、重考/恢复、工种可选、统计和历史兼容。不得仅补一个配置表单就宣称链路完成。

保留固定卷与旧制度考试行为；不删除类别表、不批量改写历史题目版本或已发布快照，不绕过实名、账户状态、次数、服务端截止时间等校验。

## 4. 题库与试卷配置

题库统一维护，已有类别继续作为后台可选筛选与历史标签；公共随机卷不按类别限制候选题。题目本身不配置试卷分值，分值归属本份试卷的题型规则。

PC 新建支持固定/随机模式；已建试卷本期不提供模式互转。随机卷显示单选、多选、判断三行：题数、每题分数、分值小计；题数 0 表示不选此题型，提交时省略该行。总题数由各行相加，调整各题型数量即配置整卷题数；不保存第二份可能冲突的总题数字段。

总分可编辑，实时对照题型分值合计；二者不一致不可保存随机规则、不可发布。金额内部按整数分计算，最多两位小数。沿用现有接口上限：每题型 1—500 道，整卷 0.01—999.99 分，时限 1—1440 分钟，次数 1—100；及格分大于 0 且不超过总分。

设计默认（由实现方建议，待本文批准）：初始单选 100 道×1 分，其余 0 道，总分 100、及格 60、时限 30 分钟、次数 3。用户可调整；不自动推定 1000 道题的题型分布足够。

展示固定说明“本机构：简单题；外来人员：困难题”，两类人员共享数量、分值、时限及次数。保留现有多选部分得分规则和可选考前学习配置，不另行改变评分方式。

## 5. 发布版本与公共题池

发布事务从当前已启用、未删除、内容合法的当前题目版本中收集候选题，按题型和难度检查；每一条抽题规则都必须在 easy 和 hard 两个题池各自满足数量。缺题错误具体到难度、题型、所需数和可用数。

发布冻结规则、候选题版本、媒体引用和分值口径。后续题库编辑不改变这份发布快照；需要使用更新题库时撤回、编辑并重新发布。整份快照不得下发学员端；开始考试仅下发该次题单的受控题面，不含答案解析。

拟增加显式题池范围 `pool_scope=category|public`（具体数据库列/契约命名留给实施计划）：既有数据默认 category，新公共随机卷为 public；只对 public random 取消试卷类别要求和候选池类别过滤。避免历史随机卷无意扩大题池。若需要 DDL，新增迁移并同步 init.sql、entity、03 册，不改旧迁移。

学员参与培训考试整体不再按工种限制；旧发布题池仍保留原冻结范围。旧制度考试继续其原资格规则。

## 6. 二维码与 H5 进入链路

```
PC 配置草稿 → 发布校验成功 → 展示/下载一个考试二维码
                                      ↓
H5 考试入口（paper_id）→ 登录 → 必要资料 → 实名 → 考试说明
                                      ↓
                            用户明确点击开始/再次考试
                                      ↓
                        恢复进行中记录，或新建本次题单
```

设计选择：二维码使用稳定的 `paper_id` 入口，不固定某名学员或某次 attempt，不携带 JWT、手机号、答案或供应商信息。公开 H5 域名由部署配置提供，不使用管理员浏览器的 localhost 自动拼成正式二维码；域名未配置时给出明确配置提示。

发布前不提供正式二维码；发布后可重复下载同一入口。撤回后入口仍可访问状态页但禁止新开考，进行中记录按既有恢复规则处理。重新发布不重置次数；旧纸质二维码仍指向这份试卷。独立新考试及新额度通过新建另一份试卷实现。

仅接受站内受控考试标识作为登录/实名回跳目标，禁止任意外部 return URL。跨登录、补资料、实名与页面刷新保存该目标；换账号后重新查询该账号权限/次数/记录，不能复用前一账号题单。扫码本身不占次数、不发送开考请求。

## 7. 个人归属、难度与每次抽题

服务端在首次成功开考时，根据数据库中的合法来源确定难度，冻结到当前个人考试归属；短信新注册沿用 external 默认，管理员预先录入的 institution 生效。缺失/非法来源阻止开考并提示联系管理员，不降级到简单题。

设计选择：沿用现有 assignment 语义，同一学员同一试卷首次开考冻结来源、难度、发布版本和规则；后续重考从该冻结候选池重新抽题。管理员后来改学员来源或重新发布试卷，不改这个人的既有考试归属、次数上限和历史；尚未开始的学员使用最新发布版本。PC 撤回/重新发布时明确说明这一点。

新一次考试先锁用户/归属并检查已有记录；有进行中记录就恢复。超时记录先收口，显示本次超时结果，后续用户明确点击再次考试才新建。无进行中记录且次数未满，按规则随机取题，将记录、截止时间、题目和选项排列一次性保存；重复/并发请求只产生一次记录。成功提交自动评分；重复提交幂等，超时不评分、不伪造答案。

已及格仍可在次数内重考，不额外增加“及格后禁止”限制。用完次数显示已用/上限及历史成绩入口。每份试卷独立计次，不同二维码访问同一 paper_id 不产生额外额度。

## 8. 工种可选与统计兼容

PC 学员新建/编辑/导入以及 H5 资料允许未填工种；空值统一为 null，已填合法 ID 继续校验。保留现有首次确认后修改由管理员负责的规则，不为了可选而删除既有资料。

H5 首次资料补全和实名只保留姓名等真正必需条件；移除“选工种匹配考试”的文案与拦截。类别为空时仍能列出已发布培训考试并通过二维码开始考试。

统计须区分学员工种与试卷标签：公共卷显示“公共题库”，无工种显示“未填写”；不能继续用同类别学员数作为公共考试应考人数分母。设计选择：无报名名单的公共考试展示实际参与人数、交卷人数和按来源/难度分组成绩，不推导全机构应考率；保留既有按最高分的成绩统计口径，跨难度不混成公平排名。历史记录按冻结来源、类别、难度显示，不用当前用户资料重算。

## 9. 验收与实施边界

必须覆盖：

1. PC 随机卷创建、保存、重开编辑，默认值和规则回显正确；100 道100分及80道100分均可配置；不一致、非法数量/分值/次数被前后端拒绝。
2. simple/hard 各题型不足时发布失败，失败不产生有效新发布版本或二维码；补足后成功。
3. 同一二维码，本机构取 easy、外来取 hard；前端伪造来源/难度无效。
4. 无工种的新建、导入、登录、补资料、实名、列表和开考可用；实名和账户权限仍有效。
5. 本次恢复不换题、不延时、不计新次数；并发开考、提交重试安全。
6. 第一次结束后第二次建立独立记录并执行抽样；不能用“题单必须不同”作为随机测试条件；第4次被默认3次限制拒绝，超时占用次数。
7. 撤回、重新发布、修改来源遵守个人归属冻结；旧固定卷、旧随机发布和旧制度考试可读且不被静默改写。
8. 公共卷统计不使用类别应考人数；题面/媒体不泄漏答案、解析或候选题全集。
9. PC/H5 浏览器验证扫码落地、登录/实名回跳、刷新及账号切换。真实手机扫码与真实供应商实名需单独验收，不以自动化替代。

必要自动化使用隔离数据库；不得对开发库执行重建或回填验证。先批准本设计，再生成实施计划，最后实施。仅本文属于本轮交付；没有业务代码、数据库变更或服务重启。
